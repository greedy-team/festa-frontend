## 본문

## 🔍 현재 문제점

- main·develop에 필수 CI 규칙을 추가한 뒤 릴리스 자동화가 생성한 새 커밋을 develop에 반영하지 못해 배포가 중단된다.
- 릴리스 PR #197에서 기존 커밋의 빌드·유닛·E2E 검사는 통과했지만, 버전·changelog 변경 커밋은 필수 검사 결과가 없어 GH013으로 거절됐다.
- 실패 당시 PR 제목은 v0.1.11로 변경됐으나 원격 버전은 0.1.10에 남았고, 후속 병합·태그 생성이 진행되지 않았다.
- 참고: https://github.com/greedy-team/festa-frontend/actions/runs/34047613614

## 💡 해결 방안 / 제안 기능

- 코드가 모이는 develop에서 릴리스 준비 PR로 버전·changelog를 함께 검증하고 반영한다.
- develop → main에서는 준비된 변경의 필수 CI 통과 후 PR을 병합하고 태그·배포를 진행한다.
- 버전은 작업 PR마다 올리지 않고 릴리스당 한 번만 확정한다.
- 브랜치 보호 규칙과 필수 검사를 유지하며 자동화가 이를 우회하지 않도록 한다.
- 영향 범위: 릴리스 준비·병합·태그·배포 및 관련 안내 문서. 공용 자동화 변경 시 frontend·backend·crawler의 공통 규칙 정합성을 함께 확인한다.
