## 본문

## 🔍 현재 문제점

- `src/lib/api.ts`의 `API_BASE`와 5개 mock 핸들러 파일이 각자 정의한 `API` 상수가 전부 `https://api.festa.kr`(또는 `NEXT_PUBLIC_API_BASE_URL`)에 `/festivals`, `/artists`, `/admin/auth/login` 같은 경로를 그대로 붙인다 — `/api` 접두사가 코드 어디에도 없다(전수 확인, 0건)
- 백엔드는 2026-08-23 `/api` 접두사를 붙이는 쪽으로 결정을 뒤집었고(관리자 경로는 `/api/admin/...`), 2026-08-28에 착지한 첫 공개(비관리자) API 3종도 전부 `/api` 접두사가 붙어 있다 — `GET /api/hosts/{id}`, `GET /api/festivals/upcoming`, `GET /api/festivals/recent`, `GET /api/artists`, `GET /api/artists/{id}`
- 지금은 `NEXT_PUBLIC_API_MOCKING=true`라 mock이 응답을 대신 만들어줘서 안 드러나지만, 실제 백엔드로 전환하는 순간(`MOCKING=false`) 모든 요청이 `/api` 없이 나가 404가 날 가능성이 높다

## 💡 해결 방안 / 제안 기능

- 공개 화면(`src/lib/api.ts`)과 관리자 화면(`src/features/admin/*/api.ts`) 양쪽의 요청 경로에 `/api` 접두사를 반영한다
- mock 핸들러(`src/mocks/handlers/*.ts`)도 실제 요청 경로와 계속 같은 값을 가로채도록 함께 맞춘다 — 핸들러 등록 URL과 프론트 호출 경로가 어긋나면 mock 자체가 조용히 응답을 못 만든다
