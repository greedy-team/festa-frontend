## 🔍 현재 문제점

홈 히어로는 다가오는 축제를 데스크톱 기준 슬롯 4칸에 나눠 담는다. 축제가 4건이면
시안(360 × 4)과 같지만, 그보다 적으면 남은 칸을 나눠 가지면서 패널 하나의 폭이
넓어진다 — 1건이면 화면 전폭 한 장, 2건이면 절반씩, 3건이면 1/3씩이다.

- 패널 내부 조판은 폭 360을 전제로 만들어졌다. 좌측 인셋 40에 D-day와 정보 블록이
  붙어 있고 텍스트 폭도 좁게 잡혀 있어서, 패널이 넓어져도 내용은 왼쪽 아래에 그대로
  머문다. 축제가 1건인 지금 상태에서는 화면 대부분이 포스터 면만 남는다
- 지금 실데이터가 1건이라 이 화면이 예외가 아니라 홈의 기본 화면이다
- 축제가 0건인 시즌(방학 등)에 나오는 아티스트 이름 벽 화면은 개수와 무관하게
  고정된 조판을 쓴다. 해상도와 이름 개수에 따라 밀도가 크게 달라지는지, 가운데
  안내 문구가 항상 읽히는지 확인된 적이 없다

즉 "축제 4건 + 데스크톱"이라는 한 조건에서만 검증된 화면이고, 실제로 더 자주
나오는 조건(1~3건, 0건)은 설계된 적이 없다.

## 💡 해결 방안 / 제안 기능

- 축제 개수(0 / 1 / 2 / 3 / 4 이상)를 화면 상태로 보고, 각각에서 히어로가 어떻게
  보여야 하는지를 먼저 정한다. 개수가 적을 때 패널을 늘려 채우는 지금 방식이
  맞는지부터 다시 본다
- 패널이 넓어질 때 정보 블록(D-day·학교명·축제명·날짜·장소)이 어디에 놓일지를
  정하고, 폭에 따라 조판이 따라오게 한다
- 0건 화면은 이름 개수와 해상도가 달라져도 안내 문구가 항상 먼저 읽히도록 다듬는다
- 결정된 규칙은 DESIGN.md에 반영해서 다음에 같은 판단을 반복하지 않게 한다
