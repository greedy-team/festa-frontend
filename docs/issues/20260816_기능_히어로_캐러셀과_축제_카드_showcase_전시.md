## 본문

## 📝 현재 문제점

이슈 #34로 토큰·공용 컴포넌트·레이아웃 셸이 섰고 PR #33으로 MSW 목 데이터가 들어왔지만, `.claude/rules/DESIGN.md`의 `05 Components` 시트에는 아직 만들지 않은 컴포넌트가 19개 남아 있다.

이것들을 카탈로그로 한꺼번에 만들면 쓰이는 자리가 없는 컴포넌트가 생긴다. 화면 단위로 필요한 것만 만들면 그런 일이 없다. 홈이 요구하는 것부터 만든다.

또 목 데이터에 축제가 3건뿐이고 그중 다가오는 것이 1건이라, 4분할 히어로를 채울 수가 없다.

## 🛠️ 해결 방안 / 제안 기능

DESIGN.md 홈(06-D)이 요구하는 컴포넌트를 만들고 `/showcase`에 전시한다. 데이터는 MSW 목의 `/festivals/upcoming`과 `/festivals/recent`에서 받는다. 두 엔드포인트는 이미 홈을 위해 만들어져 있고 응답 필드가 화면과 정확히 맞는다.

## ⚙️ 작업 내용

1. 목 데이터 확장 — 축제 3건을 12건으로, 학교 4곳을 11곳으로. D-day가 D-3부터 D-40까지 골고루 퍼지게 배치한다. 기존 학교(연세대·고려대·성균관대·세종대)는 재사용한다

2. API 레이어 — 실패를 흡수하는 fetch와 축제 조회 함수 두 개. 서버 컴포넌트에서 부른다

3. 유틸 — 축제 id로 포스터 틴트를 고르는 함수, D-day와 기간 문자열을 만드는 함수

4. 공용 컴포넌트 — 포스터 이미지(로드 실패 시 사라짐), 섹션 헤더 행

5. 히어로 컴포넌트 — 패널, 좌우 화살표, 도트 인디케이터, 캐러셀 컨테이너

6. 최근 등록 카드

7. showcase 전시 화면 두 개 — `/showcase/hero`와 `/showcase/card`. 인덱스에 항목을 추가한다

## 📌 확정한 설계 결정

- **컴포넌트를 홈에 조립하지 않고 showcase에 전시한다.** 처음에는 홈까지 만들었다가 되돌렸다. 루트 경로는 플레이스홀더로 두고 검증은 showcase에서 한다. 홈 조립은 별도 이슈다
- 데이터는 서버 컴포넌트의 fetch로 받는다. TanStack Query를 설치하지 않는다. instrumentation.ts가 Node 런타임에 MSW를 띄우므로 서버 fetch가 그대로 가로채진다
- 히어로 패널 수를 화면 폭이 정한다. 좁은 화면 1개, 중간 2개, 넓은 화면 4개. 360px은 1440을 4등분한 결과값이지 못박을 값이 아니다
- 도트 개수를 하드코딩하지 않고 계산한다. 축제 수를 현재 패널 수로 나눈 올림값이다. DESIGN.md는 도트 8개를 그려 두었지만 그것은 축제 32개를 전제한 그림이고, 문서 스스로 축제 수가 다를 때의 규칙이 없다고 적어 두었다
- 포스터가 없는 것이 정상 경로다. 목 데이터의 posterUrl은 대부분 null이고, 값이 있어도 존재하지 않는 CDN을 가리켜 로드에 실패한다. 틴트를 먼저 깔고 이미지를 그 위에 얹어, 실패하면 이미지가 스스로 사라지고 틴트만 남는다
- D-day 계산의 기준 시각을 한국 시각에 고정한다. 히어로가 클라이언트 번들에 들어가 서버와 브라우저 양쪽에서 실행되는데, 실행 환경의 로컬 날짜를 쓰면 한국 시각 0시부터 9시까지 서버와 브라우저의 D-day가 하루 달라지고 하이드레이션이 깨진다

## 🚫 범위에서 빼는 것

- **홈 화면 조립.** 위 결정대로 별도 이슈로 뺐다
- 분실물 패널과 광고 배너. 목 핸들러가 분실물은 P1로 보류라고 명시했다. 데이터 없이 만들면 하드코딩된 가짜 목록이 화면에 박힌다. 둘은 한 행을 이루는 짝이라 함께 미룬다
- 히어로 클릭 인터랙션. DESIGN.md Known Gaps에 세 사람의 안이 경합 중이다. 팀이 정할 문제다. 캐러셀은 클릭과 무관하므로 동작하게 만들었다
- 히어로 자동재생. DESIGN.md에 일시정지 아이콘이 그려져 있으나 전환 방식과 주기가 미정의다
- 축제 목록·상세, 아티스트, 검색 화면. 각각 별도 이슈다

## ⚠️ 알아 둘 것 두 가지

**배포 빌드가 깨질 수 있는 자리.** 목킹 플래그는 로컬 전용이고 Vercel에는 등록하지 않는다. 서버 컴포넌트가 fetch를 그냥 호출하면 정적 프리렌더 시점에 실제 API 연결이 실패해 빌드가 죽는다. 그래서 fetch 실패를 빈 배열로 흡수해 빈 상태 화면을 그리고, 데이터를 쓰는 전시 화면만 렌더를 요청 시점으로 돌렸다.

**HMR이 서버측 모킹을 푼다.** instrumentation.ts의 register는 서버 부팅 시 한 번만 실행된다. 파일을 고쳐 HMR이 돌면 그 패치가 풀려 요청이 실제 인터넷으로 나가고, 앱이 그 실패를 흡수하므로 화면이 500이 아니라 조용히 빈 상태로 뜬다. 로컬에서 데이터가 안 보이면 코드를 의심하기 전에 개발 서버를 재시작한다. 이 내용은 `src/mocks/README.md`에도 남겼다.

로컬에서 목 데이터를 보려면 `.env.local`에 `NEXT_PUBLIC_API_MOCKING=enabled`와 `NEXT_PUBLIC_API_BASE_URL`이 필요하다. env 파일은 추적되지 않으므로 각자 만든다.
