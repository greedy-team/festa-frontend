# 🔧 [설정] E2E가 안 덮는 흐름 추가

## 🔍 현재 문제점

- E2E는 현재 10파일 17건이고 그중 1건은 스킵된다. 실행하면 16 통과 1 스킵이다. 스킵은 통과가 아니라 그 흐름이 검증되지 않고 있다는 뜻인데, 초록 옆의 회색 한 줄이라 눈에 잘 띄지 않는다.
- 목 데이터를 단일 소스에 두고 아티스트를 id로 참조하게 만든 명시적 이유가 축제에서 아티스트로, 다시 축제로 도는 순환탐색 E2E였다. 그런데 축제에서 주최로 가는 경로만 덮여 있고 축제에서 아티스트로 가는 경로는 비어 있다. 구조를 그렇게 만든 목적이 정작 검증되지 않는다.
- 라인업 행에서 아티스트 상세로 가는 링크는 최근에 생겼는데 E2E가 없다. 시크릿 게스트 행이 링크가 아니라는 것도 확인되지 않는다.
- 목록 화면의 페이지네이션은 눌러서 다음 페이지가 실제로 오는지 확인하는 테스트가 없다. 결과 0건일 때 에러 화면이 뜨던 과거 사고와 같은 계열이 재발해도 잡히지 않는다.
- 없는 축제로 접근했을 때의 404 화면과 조회에 실패했을 때의 안내 화면이 둘 다 검증되지 않는다. 하나가 다른 하나로 둔갑해도 알 수 없다.
- 아티스트 목록의 장르 필터, 축제 이력의 연도 필터는 화면에 있는데 E2E가 지나가지 않는다. 관리자도 가드는 덮였지만 루트 접근 시 리다이렉트와 로그아웃은 비어 있다.
- 접근성 항목 중 본문 바로가기와 모션 감소는 지금 사람이 수동으로 확인하고 있다. 접근성 작업 당시 자동화 도구가 실제 창 포커스를 만들지 못해 수동 확인으로 돌렸는데, 브라우저를 실제로 띄우는 E2E는 진짜 키 이벤트를 보내므로 그 한계에 걸리지 않는다. 수동 확인을 자동으로 옮길 수 있는 자리다.

## 💡 해결 방안 / 제안 기능

- 위에서 짚은 흐름을 세 묶음으로 나눠 스펙을 추가한다.
  - 1순위 — 실사용 경로인데 검증이 없고 목 데이터도 이미 있는 것: 라인업에서 아티스트 상세로 이동, 목록 페이지 이동, 없는 축제 접근 시 404
  - 2순위 — 필터와 상태 전이: 아티스트 장르 필터, 축제 이력 연도 필터, 관리자 루트 리다이렉트와 로그아웃
  - 3순위 — 접근성: 본문 바로가기 링크가 키보드로만 나타나고 본문으로 이동하는지, 동작 줄이기 설정에서 애니메이션이 멈추는지
- 스킵되던 예정 공연 흐름은 목 데이터에 예정 공연을 만들어 해소한다. 날짜를 고정값으로 넣으면 시간이 지나면서 예정이 아니게 되므로, 오늘 기준 상대 날짜를 만드는 기존 헬퍼를 쓴다.
- 스펙은 기존 관례를 따른다. 이름이나 건수 같은 값을 하드코딩하지 않고 화면에서 조건에 맞는 대상을 찾아 확인한다. 조건을 만족하는 대상이 없으면 조용히 넘어가지 않고 실패로 떨어뜨린다.
- 영향 범위: 스펙 파일 추가와 목 데이터 보강이다. 제품 코드는 바뀌지 않는다.
- 제외: 관리자 아티스트·주최·임포트 화면은 목 핸들러가 없어 요청이 실서버로 나가는 상태라 별도 이슈의 몫이다. 아티스트 목록 페이지네이션은 목 데이터가 한 페이지 분량이라 대상이 아니다. 브라우저를 늘리는 것과 화면 캡처 비교도 이번 범위가 아니다.

## 🔧 작업 내용

- [ ] 라인업 행에서 아티스트 상세로 이동, 공개 예정 행은 링크가 아님
- [ ] 축제 목록에서 다음 페이지로 이동하면 목록과 주소가 함께 바뀐다
- [ ] 없는 축제로 접근하면 404 화면이 뜨고 조회 실패 안내와 구분된다
- [ ] 아티스트 장르 필터로 좁히면 주소와 결과가 함께 바뀐다
- [ ] 축제 이력에서 연도로 좁히면 주소와 결과가 함께 바뀐다
- [ ] 관리자 루트로 접근하면 검수 화면으로 이동하고, 로그아웃하면 로그인 화면으로 돌아간다
- [ ] 본문 바로가기가 키보드로만 나타나고 본문으로 이동한다
- [ ] 동작 줄이기 설정에서 진입 애니메이션이 멈추고 내용은 그대로 보인다
- [ ] 목 데이터에 예정 공연을 추가해 스킵되던 스펙을 해소한다
- [ ] 전체 실행으로 통과 확인, E2E 문서의 수치와 목록 갱신
