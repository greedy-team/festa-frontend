# 제목

❗ [버그][축제목록] "다가오는 순" 정렬이 실제로는 오래된순으로 동작한다

# 본문

## 🔍 현재 문제점

- /festivals 화면의 정렬 드롭다운 "다가오는 순"을 누르면 sort=UPCOMING 하나만 전송된다.
- 백엔드의 sort=UPCOMING은 개최일 오름차순 정렬만 하고, 지난 축제를 걸러내지 않는다. 거르는 일은 status 파라미터의 몫이다 — 이름만 겹칠 뿐 축이 다르다.
- getFestivals의 파라미터에 status가 아예 없어, 프론트가 그 파라미터를 전혀 쓰지 않는다. 백엔드는 이미 제공하고 MSW 목도 검증·필터한다.
- 실제 동작: "다가오는 순"이 가장 오래된 축제부터 보여준다.
- 예상 동작: "다가오는 순"은 오늘 이후 시작하는 축제만, 임박한 순서로 보여준다.
- 지금은 DB의 축제가 대부분 현재~미래라 증상이 드러나지 않는다. 크롤러 백필(2023~2025)이 발행되면 "다가오는 순"의 첫 화면이 과거 축제로 채워진다.
- 같은 sort=UPCOMING 값을 /hosts/[id]/history 화면은 "오래된순"으로 부른다. 과거 축제만 있는 화면이라 그쪽 라벨은 맞다. 틀린 쪽은 /festivals다.

## 🔄 재현 방법

1. 크롤러 백필 규모(2023~2025)를 흉내 낸 픽스처를 넣는다.
2. /festivals 접속 후 정렬 드롭다운에서 "다가오는 순" 선택.
3. 첫 페이지가 과거 연도 축제부터 나열되는 것을 확인한다.

## 💡 해결 방안

- "다가오는 순"을 정렬 옵션이 아니라 status 필터와 sort의 조합으로 낸다. 백엔드 변경은 필요 없다.
  - "다가오는 순" 선택 시 status=UPCOMING&sort=UPCOMING 전송.
  - status=UPCOMING은 KST 오늘 기준 시작일이 오늘보다 뒤인 축제.
  - 오늘 진행 중(ONGOING) 축제는 이번 범위에서 제외한다 — status 다중값은 백엔드가 지원하지 않아 별건으로 둔다.
- /hosts/[id]/history의 "오래된순"은 변경하지 않는다. 과거만 있는 화면이라 status를 붙이면 목록이 통째로 빈다.
- sort 값 개명(UPCOMING을 sort에서 떼는 것)은 백엔드 계약이라 범위 밖이다. 이 작업이 그 개명의 근거가 된다.
