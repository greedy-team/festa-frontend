## 제목

🔧 [설정][관리자] 일괄 발행 응답 계약을 publishedIds/failed로 맞춤

## 본문

## 🔍 현재 문제점

- 축제 일괄 발행 응답 타입(`BulkPublishResult`, `features/admin/festival/types.ts:55`)이 `requested`·`published`(파생 건수)·`publishedIds`·`failed` 네 필드인데, 브레인 볼트에 기록된 백엔드 결정(DEC-0100: 일괄 발행 응답은 `publishedIds`와 `failed[]`로만 낸다)은 `publishedIds`·`failed` 둘뿐이다 — 파생 건수 필드가 실제 계약에 없다
- `FestivalReviewScreen.tsx:177`이 그 파생 건수를 화면에 그대로 쓴다: `요청 {requested}건 중 {published}건 발행됨`. 실제 API로 전환하면 이 값들이 응답에 없어 화면이 깨진다
- 존재하지 않는 festivalId를 발행 요청에 섞어 보내는 경우도 계약과 다르게 처리하고 있다 — DEC-0100은 "존재하지 않는 id는 `reason: NOT_FOUND`로 `failed[]`에 담는다"고 정하는데, 지금 mock(`features/admin/festival/api.ts`의 `publishFestivals`)은 존재하지 않는 id를 `.filter(Boolean)`으로 그냥 걸러내 버려 `publishedIds`에도 `failed`에도 안 잡힌다

## 💡 해결 방안 / 제안 기능

- `BulkPublishResult`에서 `requested`·`published`를 빼고 `publishedIds`·`failed`만 남긴다
- 화면의 "요청 N건 중 M건 발행됨" 문구는 `publishedIds.length + failed.length`(요청)·`publishedIds.length`(발행)처럼 프론트에서 파생시켜 그린다
- `publishFestivals`가 존재하지 않는 id를 `reason: NOT_FOUND`로 `failed[]`에 담도록 고친다 — `PublishBlockerReason`에 `NOT_FOUND`를 추가할지, 별도 reason 체계로 둘지는 DEC-0100 원문("reason은 에러 코드와 다른 체계") 확인 필요
