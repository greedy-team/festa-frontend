# 🔧 [설정] 테스트가 없는 순수 함수에 유닛테스트 추가

## 🔍 현재 문제점

- #100에서 유닛테스트 환경을 만들고 핵심 순수 함수를 덮었고, 이후 #105~#109·#122에서 로직이 생길 때마다 한 파일씩 붙여 지금 13파일 74건이다. 그런데 그 사이 추가된 순수 함수 중 아직 테스트가 없는 것이 남아 있다.
- 남은 것 중 일부는 코드 주석이 실패 모드를 명시해 두고 있는데, 정작 그 실패 모드를 확인하는 테스트가 없다. 주석이 약속하는 동작과 실제 동작이 갈려도 알 방법이 없는 상태다.
  - 요청 실패 처리는 "응답 자체가 없었으면 상태 코드가 null, 응답은 왔는데 본문이 깨졌으면 상태 코드가 남는다"는 구분을 문서화해 두었으나 검증이 없다.
  - 관리자 토큰 읽기는 "저장소 접근이 예외를 던지면 로그인으로 돌아갈 길 없이 콘솔이 막다른 길에 빠진다"는 이유로 예외를 잡고 있는데, 그 경로가 실제로 막히는지 확인된 적이 없다.
  - 검수 표의 주소 표시는 "행 하나가 표 전체를 무너뜨린다"는 이유로 폴백을 두었는데 폴백이 도는지 확인이 없다.
- 페이지네이션 번호 창 계산은 목록 화면 7곳이 공유하는데 산술식이 비자명해서, 리팩토링에 조용히 깨져도 CI가 잡지 못한다.
- 히어로 패널 슬롯 수는 타겟 환경 문서가 "1장 / 2장 / 4장"으로 공식 명시하는 값인데, 문서의 주장과 코드가 어긋나도 잡히지 않는다.
- URL 파라미터 파서가 화면마다 흩어져 있는데, 같은 일을 하는 파서 중 일부만 테스트가 있고 나머지는 없어 기준이 일관되지 않다.

## 💡 해결 방안 / 제안 기능

- 테스트가 없는 순수 함수 8곳에 유닛테스트를 추가한다. 두 묶음으로 나눠 우선순위를 둔다.
  - 1순위 — 코드가 이미 약속한 동작인데 검증이 없는 것: 요청 실패 처리, 페이지네이션 번호 창, 히어로 슬롯 수, 관리자 토큰 저장소 접근
  - 2순위 — 같은 계열이 이미 테스트돼 있어 일관성이 필요한 것: URL 파라미터 파서 6종, 검수 표 주소 폴백, 임포트 미리보기 대표 이름 폴백, 임포트 이력 일시 포맷
- 날짜·시각 포맷은 실행 환경의 지역화 데이터에 따라 결과가 갈릴 수 있으므로, 값 자체가 아니라 값이 없거나 깨졌을 때의 폴백만 확인한다.
- 영향 범위: 테스트 파일 추가가 대부분이고, 제품 코드는 대상 함수를 테스트에서 가져다 쓸 수 있도록 내보내는 변경만 있다. 대상 함수 다수가 화면 파일 안의 모듈 private 함수라 내보내는 곳이 6개 파일 10줄이 된다. 별도 모듈로 빼내는 방식도 있으나 변경 폭이 커져 택하지 않는다. 이 저장소는 이미 히어로 슬롯 계산과 미리보기 행 키를 화면 파일에서 내보내 쓰고 있어 새 방식이 아니다. 런타임 동작 변경은 없다.
- 제외: 데이터 조회 배선과 요청 경로 조립은 대상이 아니다. 목을 만들어 목을 검증하는 모양이 되어 얻는 것이 없다. 폼 초기값 변환도 필드 나열이라 테스트가 코드를 그대로 복사하게 되므로 제외한다.

## 🔧 작업 내용

- [ ] 요청 실패 처리 테스트 — 정상, 서버 오류 응답, 연결 실패, 응답은 왔으나 본문 파싱 실패 네 갈래
- [ ] 페이지네이션 번호 창 테스트 — 전체가 창보다 작을 때, 첫 페이지, 마지막 페이지, 중간, 범위를 벗어난 현재 페이지
- [ ] 히어로 슬롯 수 테스트 — 축제 수 1~4와 그 이상에서의 상한
- [ ] 관리자 토큰 저장소 테스트 — 서버 렌더 중 호출, 저장소 접근이 예외를 던지는 경우
- [ ] URL 파라미터 파서 6종 테스트 — 유효값 통과, 잘못된 값 폴백
- [ ] 검수 표 주소 폴백 테스트 — 정상 주소, 파싱 불가한 값
- [ ] 임포트 미리보기 대표 이름 폴백 테스트 — 폴백 순서
- [ ] 임포트 이력 일시 포맷 테스트 — 값 없음, 깨진 값
- [ ] 전체 실행으로 통과 확인, 유닛테스트 문서의 수치와 매핑표 갱신
