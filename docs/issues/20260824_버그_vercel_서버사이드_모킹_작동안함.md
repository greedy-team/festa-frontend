## 제목

❗ [버그] Vercel 배포 환경에서 서버 사이드 API 모킹이 동작하지 않음

## 본문

🗒️ 설명
---
`NEXT_PUBLIC_API_MOCKING=true`로 설정해도, Vercel에 배포된 서버 컴포넌트(홈·축제 목록·아티스트 목록 등)는 실제 백엔드로 요청을 보내고 실패한다. 백엔드가 아직 없거나 불안정한 지금, 데모·프리뷰 화면이 전부 "불러오지 못했습니다"로 뜬다.

`src/instrumentation.ts`가 Node 런타임에서 MSW(`msw/node`) 서버를 띄워 `fetch`를 가로채는 구조인데, 로컬 `pnpm dev`에서는 작동하지만 Vercel 서버리스 함수 환경에서는 인터셉션이 걸리지 않는다.

🔄 재현 방법
---
1. Vercel 프로젝트 환경변수에 `NEXT_PUBLIC_API_MOCKING=true` 설정
2. `develop → main` 릴리스로 배포
3. 배포된 홈(`/`)·`/festivals`·`/artists` 접속

📸 참고 자료
---
Vercel Function 로그:
```
GET /  200  GET /festivals/upcoming 실패 null fetch failed
```
실제 API 도메인으로 요청이 나가서 실패한 게 로그로 확인됨.

로컬 검증: 같은 조건(`NEXT_PUBLIC_API_MOCKING=true`)으로 `pnpm build && pnpm start`(프로덕션 Node 서버)를 띄우면 모킹이 정상 작동해 목데이터가 렌더된다. 즉 코드 로직 자체는 맞고, Vercel 서버리스 함수 환경에서만 MSW의 네트워크 레벨 인터셉션이 안 걸리는 것으로 확인됨.

✅ 예상 동작
---
- `NEXT_PUBLIC_API_MOCKING=true`일 때, 배포 환경(Vercel)과 로컬 어디서든 서버 컴포넌트 fetch가 동일하게 목데이터를 받아야 한다.
- `false`일 때는 지금처럼 실제 API를 그대로 호출한다.

⚙️ 환경 정보
---
- Vercel 프로덕션 배포 (Node.js 서버리스 함수)
- Next.js 16.2.12 (Turbopack), MSW 2.15.0
