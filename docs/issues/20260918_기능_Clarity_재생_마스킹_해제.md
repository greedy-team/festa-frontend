## 제목

🚀 [기능요청][분석] Clarity 재생에서 화면 내용이 보이도록 마스킹을 해제

## 본문

## 🔍 현재 문제점

- 운영 Clarity가 실사용자 세션을 정상 수집하기 시작했습니다. 30일 기준 12건이 잡히고, 20~25분 동안 14페이지를 도는 실제 탐색도 들어 있습니다.
- 그런데 재생 화면에서 모든 글자가 점으로, 모든 이미지가 회색 상자로 치환돼 실질적으로 읽을 수 없습니다.
- 지금 얻을 수 있는 것은 클릭 좌표와 스크롤, 마우스 궤적뿐입니다. 어느 위치를 눌렀는지는 보이지만 무엇을 보다가 눌렀는지는 알 수 없습니다.
- 이용 장면을 확인해 사용성을 개선하려고 도입한 도구인데 그 목적을 달성하지 못하고 있습니다.
- 원인은 두 겹입니다. 루트 레이아웃의 body에 전체 마스킹 속성이 걸려 있고, Clarity 프로젝트의 마스킹 모드도 Strict입니다. 둘 중 하나만 바꾸면 여전히 전부 가려집니다.

## 💡 해결 방안 / 제안 기능

- 루트 레이아웃 body의 전체 마스킹 속성을 제거합니다. 이 속성은 값이 아니라 존재 여부로 판정되므로 값을 false로 바꾸는 것은 해제가 아닙니다.
- Clarity 프로젝트의 마스킹 모드를 Relaxed로 전환합니다. 이것은 코드 밖 운영 작업입니다.
- 마스킹 범위가 바뀌므로 개인정보 처리방침의 Clarity 처리 항목 문구를 실제 동작에 맞게 고칩니다. 코드만 바꾸면 이용자에게 알린 내용과 실제 처리가 달라집니다.
- 검색어 보호는 마스킹이 아니라 녹화 대상 판정이 담당합니다. 검색 화면과 쿼리·해시가 있는 URL에서는 Clarity를 아예 로드하지 않으므로 이 경계는 함께 풀지 않습니다.
- 입력창과 드롭다운은 마스킹 모드와 무관하게 Clarity가 강제로 가리며 해제할 수 없습니다.
- 녹화 대상 화면은 전부 공개 축제 정보입니다. 개인정보를 표시하거나 입력받는 화면은 대상 목록에 없습니다.
