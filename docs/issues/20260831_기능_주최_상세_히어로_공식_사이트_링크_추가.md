## 본문

## 🔍 현재 문제점

- DEC-0107이 `GET /hosts/{id}` 응답과 프론트 `HostDetail` 타입에 `homepageUrl` 추가를 확정했으나(2026-08-26), 프론트에는 반영되지 않았다.
- 백엔드는 이미 응답에 `homepageUrl`을 내려주고 있다(`festa-backend`의 `HostDetailResponse`에 필드 존재 확인). 프론트만 뒤처져 있다.
- 주최 시드에 대학 홈페이지 값이 대부분 채워져 있는데, 주최 상세가 주최를 소개하는 유일한 화면인데도 공식 채널로 나가는 출구가 없다.
- 축제 상세 히어로(`FestivalHero`)는 이미 주최 공식 사이트·인스타그램 아이콘 링크를 우상단에 그리고 있어 학교 상세만 빠져 있다.

## 💡 해결 방안 / 제안 기능

- 프론트 `HostDetail` 타입에 `homepageUrl: string | null`을 `bannerUrl` 다음에 추가한다(DEC-0107이 지정한 위치).
- MSW 목 핸들러(`GET /hosts/{id}`) 응답에 `homepageUrl`을 포함한다. 목 fixture에는 이미 값이 있다.
- `HostHero` 우상단에 공식 사이트 아이콘 링크를 얹는다. 축제 상세 히어로와 같은 패턴(우상단 원형 아이콘 버튼)을 재사용하고, `homepageUrl`이 없으면 자리를 그리지 않는다.
- 인스타그램은 이번 범위가 아니다 — DEC-0107이 `homepageUrl` 하나만 계약에 넣기로 했고 host 응답에 `instagramUrl`이 없다.
- 링크 href는 `safeHttpUrl`을 통과시켜 http(s)가 아닌 값은 링크로 그리지 않는다(DEC-0107이 부정적 결과로 지적한 지점).
- DESIGN.md의 Host Detail 히어로 서술에 공식 사이트 링크를 추가해 근거를 남긴다.
