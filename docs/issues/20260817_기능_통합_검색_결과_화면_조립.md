## 본문

## 📝 현재 문제점

- 지금까지 만든 모든 SearchPill은 표시 전용이다. 실제로 동작하는 검색 자체가 앱에 없다.
- `/search` 결과 화면(DESIGN.md 12-2 Search Results, node `113:230`)이 없다 — 아티스트/학교/축제를 한 화면에서 검색하는 통합 검색 결과.

## 🛠️ 해결 방안 / 제안 기능

- Nav의 SearchPill을 실제 입력 폼으로 바꾼다 (`/search?q=`로 이동). 다른 화면들(축제·아티스트 목록 상단)의 SearchPill은 계속 표시 전용으로 둔다 — 이 화면 하나만 진짜 검색 진입점이 된다.
- `/search` 페이지에서 `GET /search?q=&type=`을 호출해 아티스트/학교/축제 세 섹션으로 결과를 보여준다. 타입 필터 칩(전체/아티스트/학교/축제)은 실제 동작.
- **아티스트 결과 카드의 Verified 배지·참여 학교 통계·별칭(alias) 배지는 뺀다.** `/search` 응답에 대응 데이터가 없고(`appearanceCount`/`latestAppearanceDate`만 있음), DESIGN.md에도 이 카드 자체가 컴포넌트 시트에 없어 미확정 상태다. 백엔드 스펙이 정해지면 후속 작업으로 추가한다.
- 학교 결과 행은 #51에서 만든 `/hosts/{id}/history`로 실제 연결한다 (School Detail이 없어 임시 링크가 필요 없는 유일한 진입점).
- 축제 결과 행의 "매칭 하이라이트"는 시안처럼 부분 문자열 강조까지 만들지 않고, 이름이 아니라 학교명에서 매칭됐을 때만 "학교명 일치: OO대학교" 텍스트로 단순화한다.
- 검색 결과 0건이면 `relatedKeywords`를 추천 검색어 칩으로 보여준다 (API가 이미 제공).
- 아티스트 "프로필 보기", 축제 카드 클릭은 상세 화면이 아직 없어 임시로 홈(`/`)에 연결한다.

## ⚙️ 작업 내용

- `src/components/layout/NavSearchForm.tsx` — Nav 전용 실제 검색 폼(GET, JS 불필요), `Header.tsx`에서 기존 `SearchPill`을 교체
- `src/features/search`: 검색 결과 타입(`ArtistResult`/`HostResult`/`FestivalResult`), `search({ q, type })` API(`GET /search`)
- `ArtistResultCard`, `SchoolResultRow`, `FestivalResultRow` 컴포넌트
- `src/app/search/page.tsx` 조립: 검색 바(재검색용) → 결과 건수 → 타입 필터 칩 → 아티스트/학교/축제 섹션 → 광고 배너. 쿼리 없거나 0건일 때 안내 문구/추천 검색어 처리
