## 본문

## 🔍 현재 문제점

- 검색 응답에서 주최를 가리키는 식별자 필드명이 다른 도메인과 어긋난다. 축제는 festivalId, 아티스트는 artistId를 쓰는데 주최만 id를 쓴다.
- 백엔드가 검색 결과의 주최 식별자를 hostId로 통일했다고 전달했다. 프론트 검색 결과에서 주최의 id를 참조하는 부분이 실제 응답과 갈린다.
- 앞서 완료한 아티스트 id 필드명 통일(artistId vs id)과 같은 종류의 정합 문제다.

## 💡 해결 방안

- 검색 관련 타입·컴포넌트·목 핸들러에서 주최 식별자를 hostId로 바꾼다.
- 대상은 GET /search 응답 경로로 한정한다. 검색 밖의 축제 상세·축제 목록 응답의 주최 필드는 백엔드 통지 범위에 없어 이번 작업에서 건드리지 않는다.
- 축제 검색 결과에 중첩된 주최 객체의 식별자도 같은 응답이라 함께 바꾼다. 실제 응답이 그대로인지 백엔드에 확인이 필요하며 PR 본문에 남긴다.
- 외부 동작 변경 내용: 없음. 화면 동작과 라우팅 경로는 그대로다.
