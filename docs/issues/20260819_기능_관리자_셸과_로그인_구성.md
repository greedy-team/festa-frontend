## 본문

## 📝 현재 문제점

- 관리자 페이지가 아직 하나도 없다. `app/(admin)`도 `features/admin/`도 존재하지 않는다.
- `app/layout.tsx`가 Header·Footer·`bg-canvas`를 하드코딩하고 있어서, 관리자 화면을 붙이면 서비스 헤더가 그대로 딸려온다. 관리자 셸은 검은 사이드바이고 서비스 셸과 겹치지 않는다.
- 관리자 API는 인증을 요구하는데 프론트에 토큰을 받을 곳도, 보관할 곳도, 로그인 없이 들어온 사람을 막을 곳도 없다.
- 상태 색이 success 한 계열뿐이라 관리자 화면이 쓰는 상태 가짓수를 표현할 수 없다.

## 🛠️ 해결 방안 / 제안 기능

- 공개 화면을 `(main)` 라우트 그룹으로 모으고, 서비스 셸(Header·Footer·배경)을 그 그룹의 레이아웃으로 내린다. URL과 화면은 그대로 유지한다.
- `/admin` 아래에 관리자 전용 레이아웃을 세운다. 사이드바 5개 항목(크롤링 임포트·축제 검수·아티스트·주최·분실물)과 다크 셸을 둔다.
- 로그인 화면을 만들고, 토큰을 받아 보관하고, 토큰이 없으면 로그인으로 보내는 가드를 건다.
- 관리자 화면들이 공유할 기반을 함께 넣는다 — 데이터 계층, 페이지네이션 응답 타입, 열거값 표시 사전, 클릭 가능한 필터 칩, 상태 배지.

## ⚙️ 작업 내용

- 공개 화면(`/`, `/artists`, `/festivals`, `/showcase`)을 `(main)` 그룹으로 이동. 외부 동작 변경 없음
- 관리자 셸 색과 상태 색(경고·위험·중립) 토큰 추가
- 관리자 사이드바와 `/admin` 레이아웃, 진입 시 축제 검수로 이동, 관리자 전용 에러 화면
- 로그인 화면, 토큰 보관, 라우트 가드
- 에러 코드를 사용자 문구로 바꾸는 사전. 모르는 코드는 코드를 괄호에 남긴다
- 관리자 데이터 계층 도입과 목록 응답 타입 공통화
- 클릭 가능한 필터 칩, 상태 배지
