## 📝 현재 문제점

- src/app/artists가 아직 없다. Header nav의 "아티스트" 메뉴가 가리키는 목적지 자체가 비어 있다.
- DESIGN.md 18 Artist List 시안(node `272:210`)의 목록·장르 필터·검색·정렬·페이지네이션도 미구현.

## 🛠️ 해결 방안 / 제안 기능

- 18 시안대로 `/artists` 목록 화면을 조립한다: 아티스트 카드 그리드(10개, 5-up × 2행), 페이지네이션, 장르 필터 칩(전체/힙합/발라드·R&B/밴드/댄스) 실제 동작, 정렬(출연 많은 순/이름순) 실제 동작, 검색창은 축제 목록(#42)과 같은 관례로 표시 전용
- 카드 클릭은 아티스트 상세 화면(DESIGN.md `09 Artist Detail`, node `66:708`)이 아직 없어 임시로 홈(`/`)에 연결한다. 목적지 화면이 정해지면 후속 작업으로 교체한다
- #42에서 만든 `Pagination`·`AdSlot`(banner variant)·`SearchPill` 공용 컴포넌트를 그대로 재사용한다

## ⚙️ 작업 내용

- `src/features/artists`: Artist(목록 항목) 타입, `getArtists` API(`GET /artists`, page/size/genre/sort)
- `ArtistCard`(정사각 포토 236×236 — festival-card와 달리 포스터가 아니라 정사각 프로필), `GenreFilter`(칩 5개, 실제 동작), `SortDropdown`(출연 많은 순 `APPEARANCES` / 이름순 `NAME`) 컴포넌트
- `src/app/artists/page.tsx` 조립: 브레드크럼·타이틀 → 장르 칩 + 검색/정렬 → 카드 그리드 → 페이지네이션 → 광고 배너

## ⚠️ 확인 필요 — 프로필 플레이스홀더 스타일

- `imageUrl`은 항상 `null`이다 (DEC-0063: 초상권 문제로 아티스트 실사진을 쓰지 않기로 결정, 기본 이미지/플레이스홀더로 대체하기로 함). 지금 구현은 다른 카드(festival-card 등)와 동일하게 **색 틴트 사각형**만 보여준다.
- DEC-0063 회의에서는 "이니셜 + 이름 해시 색상" 같은 구체적 플레이스홀더 스타일도 언급됐지만 **다루지 않았고, 실제 에셋도 아직 없어 미확정 상태**다.
- 디자인 쪽 확인 후 실제 플레이스홀더 스타일(아이콘·이니셜 등)이 정해지면 `ArtistCard`의 포토 영역만 교체하면 된다. 그 전까지는 색 틴트로 둔다.
