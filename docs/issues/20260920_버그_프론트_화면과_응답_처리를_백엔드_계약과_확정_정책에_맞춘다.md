## 제목

❗ [버그][프론트] 프론트 화면과 응답 처리를 백엔드 계약과 확정 정책에 맞춘다

## 본문

## 🔍 현재 문제점

- 없애기로 결정한 아티스트 검수 필요 필터·표시·체크박스가 관리자 화면에 남아 있다.
- 축제 등록·수정 화면에서 처음 50개 주최만 조회해, 그 이후의 주최를 새로 선택할 수 없다.
- 서버는 장소·학교 약칭이 없는 응답을 허용하지만 프론트는 값이 항상 있다고 가정해 null 문구나 불필요한 구분자가 표시될 수 있다.
- 발행 취소 시 발행 시각이 비어 오는 계약이 프론트 응답 정의에 반영되지 않았다. 이 항목의 현재 화면 장애는 확인되지 않았다.
- 예상 동작: 확정된 운영 정책과 실제 서버 응답에 맞게 관리자 기능과 공개 화면이 동작한다.

## 🔄 재현 방법

1. 관리자 아티스트 목록·수정 화면에서 검수 필요 필터와 표시를 확인한다.
2. 주최가 51개 이상인 테스트 환경에서 축제 등록 화면을 열고 뒤쪽 주최를 선택하려고 한다.
3. 장소 또는 학교 약칭이 없는 테스트 데이터로 홈·아티스트·주최 화면의 표시를 확인한다.
4. 테스트 환경에서 축제 발행을 취소하고 발행 시각이 비어 있는 응답을 확인한다.

## 💡 해결 방안

- [ ] 아티스트 검수 필요 필터·검수 열·이름 옆 표시·체크박스를 제거하고 관련 요청·응답 정의를 정리한다.
- [ ] 축제 폼에서 전체 주최를 선택할 수 있게 하고 기존 선택을 유지한다.
- [ ] 장소·학교 약칭이 없을 때 null 문구와 빈 구분자가 나타나지 않도록 한다.
- [ ] 발행 취소 응답의 빈 발행 시각을 허용한다.
- [ ] 아티스트 목록·등록·수정·병합, 주최 선택, 빈 값 표시, 발행 취소 후 상태 갱신을 검증한다.
