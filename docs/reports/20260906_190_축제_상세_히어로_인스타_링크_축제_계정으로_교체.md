# 축제 상세 히어로 인스타 링크를 축제 계정으로 교체 (#190)

### 📌 작업 개요

축제 상세 화면 히어로 우상단의 인스타그램 아이콘 링크가 주최(학교) 공식 계정을 가리키고
있었다. 백엔드가 `GET /api/festivals/{id}` 응답 최상위에 축제 공식 계정 `instagramUrl`
(nullable)을 추가했고, 축제 상세는 그 축제 하나를 보는 화면이므로 학교 계정 대신 축제
계정을 쓰도록 전환했다. DESIGN.md 축제 상세 절의 서술도 함께 갱신했다.

### 🎯 구현 목표

- 히어로 인스타 링크 소스를 응답 최상위 `instagramUrl`(축제 계정)로 교체
- 축제 계정이 없으면 인스타 아이콘 미표시 — 학교 계정으로 fallback 하지 않는다
- 주최 공식 사이트(`host.homepageUrl`) 링크와 주최 pill은 그대로 유지
- 접근성 라벨을 "축제 인스타그램"으로 변경
- DESIGN.md 축제 상세 절 갱신

### ✅ 구현 내용

#### 타입에 축제 계정 필드 추가

- **파일**: `src/features/festivals/types.ts`
- **변경 내용**: `FestivalDetail`에 `instagramUrl: string | null` 추가. `FestivalHostSummary`
  주석을 갱신해 `host.instagramUrl`(학교 계정)은 이 화면에서 쓰지 않고 축제 계정을 쓴다고 명시
- **이유**: 백엔드가 응답 최상위에 축제 계정을 내려주는 계약을 프론트 타입에 반영

#### 히어로가 축제 계정을 참조

- **파일**: `src/features/festivals/components/FestivalHero.tsx`
- **변경 내용**: `safeInstagramUrl` 계산의 소스를 `host.instagramUrl` → `festival.instagramUrl`로
  교체. `aria-label`을 "주최 인스타그램" → "축제 인스타그램"으로 변경. 우상단 아이콘 묶음
  주석도 "축제 인스타그램 + 주최 공식 사이트"로 갱신
- **이유**: 축제 상세에서 학교 계정은 이 축제를 안내하지 않는다. `safeHttpUrl` 가드는 축제
  계정에도 그대로 적용

#### 목 데이터 반영

- **파일**: `src/mocks/fixtures/db.ts`, `src/mocks/handlers/festivals.ts`
- **변경 내용**: `FestivalRecord`에 `instagramUrl: string | null` 추가, 축제 픽스처 12건에
  값 채움(4건은 실제 계정, 8건은 `null`로 두 경로 모두 커버). `GET /festivals/:id` 핸들러가
  응답 최상위에 `instagramUrl: f.instagramUrl`을 낸다. `host.instagramUrl`은 응답에 그대로 유지
- **이유**: 실서버 계약과 목 응답을 일치시키고, 축제 계정이 있는 경우와 없는 경우를 모두
  화면에서 확인할 수 있게 함

#### DESIGN.md 갱신

- **파일**: `.claude/rules/DESIGN.md`
- **변경 내용**: 축제 상세 히어로 절의 "주최의 인스타그램·공식 사이트" 서술을 "축제 공식
  인스타그램(응답 최상위 `instagramUrl`)·주최 공식 사이트(`host.homepageUrl`)"로 고치고,
  인스타는 학교 계정이 아니라 축제 계정을 쓴다는 근거와 학교 계정이 화면에 노출되지 않는다는
  점을 명시
- **이유**: 코드와 문서를 같은 변경에서 함께 바꿔 갈라지지 않게 함(#146·#166·#184는 문서가
  코드에 뒤늦게 따라간 경우라 별도 이슈였으나, 이번은 함께 처리 가능)

### 🧭 결정 기록 (ADR)

#### 축제 계정만 쓰고 학교 계정 fallback을 두지 않는다

- **문제**: 축제 계정 `instagramUrl`이 `null`일 때 인스타 아이콘을 어떻게 처리할지
- **선택**: 아이콘 자체를 그리지 않는다. `host.instagramUrl`(학교 계정)로 대체하지 않는다
- **대안**:
  - 축제 계정 우선 + 없으면 학교 계정 fallback — 인스타 출구는 남지만 `aria-label`이
    소스에 따라 갈리고("축제 인스타그램" / "주최 인스타그램") 한 아이콘이 두 가지를 뜻하게 된다.
    축제 상세에서 학교 계정은 애초에 맞는 정보가 아니다
- **트레이드오프**: 학교 공식 인스타 계정은 이 변경 이후 서비스 어느 화면에도 노출되지
  않는다(주최 상세에도 DEC-0107대로 인스타 자리가 없다). `host.instagramUrl`은 응답·타입에
  남지만 화면 소비처가 0이 된다
- ⭐ **볼트 승격 권장** — 외부 API 계약 변경 + DEC-0107이 "인스타는 결정 하나 더"로
  남겨 둔 자리의 화면 쪽 답. 등록됨: `knowledge/decisions/DEC-0173` (백엔드 계약 쪽
  결정은 별도로 `DEC-0172`)

#### `host.instagramUrl`을 프론트 타입에서 제거하지 않는다

- **문제**: 이 화면에서 안 쓰는 `FestivalHostSummary.instagramUrl`을 타입에 남길지
- **선택**: 남긴다. 주석으로 "이 화면에서 쓰지 않는다"를 명시해 재사용을 막는다
- **대안**: 타입에서 제거 — 백엔드가 응답에 계속 내려주므로 타입이 계약과 갈린다
- **트레이드오프**: 미사용 필드가 타입에 남는다. 주석이 그 이유를 설명

### 📌 참고사항

- 노션 API 명세의 축제 상세 필드표에 `instagramUrl`을 추가하는 것은 팀 몫이다. DEC-0107과
  같이 계약이 명세를 앞서는 방향이라, 명세를 안 고치면 명세만 읽는 사람에게는 없는 필드가 된다
- 관리자 등록·수정 API는 URL 형식을 검사하지 않는다(`blankToNull()`만, DEC-0107). 축제 계정
  URL도 같은 리스크를 지며, 프론트는 `safeHttpUrl`로 `<a href>` 노출을 막는다
