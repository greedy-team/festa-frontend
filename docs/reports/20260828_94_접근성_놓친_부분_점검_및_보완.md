### 📌 작업 개요

프론트엔드 코드베이스 전체를 대상으로 아이콘 버튼 라벨, 모션 감소 대응, 이미지 alt, 헤딩 구조, 키보드 바로가기, 포커스 표시 등 접근성 요소를 전수 조사했다. 대부분 이미 잘 구현돼 있었고, 실제로 빠져 있던 부분과 조사 과정에서 사용자 판단으로 범위가 넓어진 포커스 링 전역 통일까지 함께 처리했다.

### 🔍 문제 분석

이슈를 처음 열 때는 "아이콘 버튼 라벨·모션 감소 대응이 빠져 있을 것"이라는 가정으로 작업 범위를 잡았다. 그러나 실제로 코드를 읽어보니:

- 아이콘 전용 버튼(nav 검색, 히어로 화살표·도트, 페이지네이션, 라인업 바텀시트 닫기, SNS 아이콘 등)은 이미 전부 `aria-label` + `aria-hidden` 패턴이 적용돼 있었다
- `prefers-reduced-motion`도 `PageFadeIn`·`FadeInSection`에 이미 `motion-reduce:` 유틸리티로 대응돼 있었다
- 이슈 본문에 예로 들었던 nav 벨·북마크·footer 소셜 아이콘은 애초에 MVP 범위 밖이라 코드에 존재하지 않았다

전수 조사 범위를 넓혀 랜드마크 구조, 폼 접근성, 클릭 카드의 키보드 접근성, 상태 표시의 색상 의존도, 헤딩 구조, 키보드 바로가기, 포커스 표시까지 확인한 끝에 실제로 놓친 부분 네 가지를 찾았다.

### ✅ 구현 내용

#### Header.tsx 모바일 메뉴 아이콘 aria-hidden 누락
- **파일**: `src/components/layout/Header.tsx`
- **변경 내용**: 모바일 메뉴 버튼의 `X`/`Menu` 아이콘에 `aria-hidden` 추가
- **이유**: 버튼 자체엔 `aria-label`이 있었지만 안의 SVG 아이콘에는 없어, 다른 아이콘 버튼들과 패턴이 어긋나 있었다. 스크린리더가 아이콘을 중복으로 읽지 않도록 통일

#### /search 페이지 h1 누락
- **파일**: `src/app/search/page.tsx`
- **변경 내용**: 검색창 다음 바로 `h2`(아티스트/학교/축제)로 넘어가던 것에, 시각 디자인은 그대로 두고 `sr-only h1`("검색")을 추가
- **이유**: 다른 모든 페이지(홈·아티스트·축제·주최 상세)는 히어로에 `h1`이 있는데 이 페이지만 대표 헤딩이 없어, 스크린리더 사용자가 헤딩만으로 페이지 구조를 파악할 시작점이 없었다

#### 본문 바로가기(skip to content) 링크 부재
- **파일**: `src/components/layout/SiteChrome.tsx`
- **변경 내용**: 평소엔 `sr-only`로 숨겨져 있다가 키보드 포커스 시에만 나타나는 본문 바로가기 링크를 셸 최상단에 추가. `<main>`에 `id="main-content"` 부여
- **이유**: 모든 페이지가 nav(홈·축제·아티스트 3개 링크)를 지나야 본문에 닿는 구조라, 키보드 사용자는 페이지를 열 때마다 이 nav를 매번 Tab으로 통과해야 했다

#### 검색창 4곳 포커스 표시 부재, 사이트 전역 포커스 링 통일
- **파일**: `src/app/search/page.tsx`, `src/features/artists/components/ArtistSearchForm.tsx`, `src/components/layout/NavSearchForm.tsx`, `src/components/ui/SearchInput.tsx`, `src/app/globals.css`, `src/features/home/components/HeroPanel.tsx`
- **변경 내용**:
  - 검색 pill 4곳에 `focus:outline-none`으로 지워진 채 대체 표시가 없던 것을 `focus-within:ring-2`로 복구 (다크 nav는 흰색, 나머지는 인디고)
  - `globals.css`에 사이트 전역 `:focus-visible` 규칙 추가(인디고, `@layer base`) — 링크·버튼 등 나머지 모든 상호작용 요소에 일괄 적용
  - 히어로 패널 링크만 포스터 이미지 위에 바로 겹치므로 흰색 인셋 링으로 예외 처리
- **이유**: 검색창 포커스 표시를 확인하는 과정에서, 사이트 나머지 요소들은 전부 브라우저 기본값(파란색)에 의존하고 있어 검색창만 인디고로 고치면 오히려 비일관적으로 보인다는 지적이 있었다. 새로운 색을 디자인하는 대신 기존 액션 색 토큰(`{colors.primary}`)을 전역 기본값으로 재사용했다

### 🧭 결정 기록 (ADR)

#### 포커스 링을 사이트 전역 인디고로 통일하기로 범위를 넓혔다
- **문제**: 검색창 4곳만 고치면 그 부분만 인디고, 나머지는 브라우저 기본 파란색이라 눈에 띄게 달랐다
- **선택**: 이슈 초안에서는 제외했던 "포커스 상태(focus-visible) 디자인"을, 검색창 수정 중 발견한 비일관성을 계기로 사용자 판단에 따라 범위에 포함했다. `globals.css`에 전역 규칙을 두고 컴포넌트별 `focus-visible:` 유틸리티가 필요할 때 덮어쓸 수 있게 했다
- **트레이드오프**: `@import "tailwindcss"`가 만드는 레이어(`theme, base, components, utilities`) 밖에 전역 규칙을 두면 특이도와 무관하게 항상 이겨 컴포넌트별 오버라이드가 무시된다 — `@layer base`에 넣어야 `utilities` 레이어의 컴포넌트별 클래스가 정상적으로 덮어쓴다는 걸 실제로 겪고 나서 확정했다
- ⭐ **볼트 승격 권장** — "Tailwind 커스텀 base 스타일은 반드시 @layer base 안에 둔다"는 이 스택 특유의 함정으로, 다른 전역 스타일 추가 시에도 재발할 수 있다

#### 히어로 패널만 흰색 포커스 링 예외
- **문제**: 전역 인디고 기본값이 홈 히어로 패널(포스터 이미지에 바로 겹치는 유일한 링크)에도 그대로 적용되면 DESIGN.md의 "히어로 안에 인디고를 넣지 않는다" 규칙과 부딪힌다
- **선택**: `HeroPanel.tsx`에만 `focus-visible:outline-on-media`로 흰색 예외를 두었다. 패널끼리 여백 없이 맞닿아 있어(DESIGN.md) 기본 `outline-offset`을 그대로 쓰면 옆 패널을 침범하므로 `-outline-offset-4`(인셋)로 안쪽에 그리게 했다
- **대안(기각)**: 축제·주최 상세 히어로(FestivalHero·HostHero)도 같은 예외를 줄지 검토했으나, 그 화면들은 이미 D-day 뱃지 등에 인디고를 쓰고 있어 "히어로 안에 인디고 금지" 규칙이 홈 히어로 전용임을 확인하고 예외를 두지 않았다
