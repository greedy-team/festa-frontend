### 📌 작업 개요

메인 홈 화면의 히어로를 수동 페이지네이션에서 오토플레이 캐러셀로 교체하고, 화면 크기·개수에 따라 안정적으로 반응하도록 개선했다. 다가오는 축제가 없는 시즌의 폴백 화면과 스크롤 페이드인·hover 확대 같은 마이크로 인터랙션도 함께 추가했다.

### 🎯 구현 목표

- 홈 히어로를 오토플레이 캐러셀로 바꾸고, 화면 높이를 뷰포트 기준으로 채운다
- 축제 개수·화면 폭에 따라 패널 폭·비율이 안정적으로 반응하게 한다
- 다가오는 축제가 0건일 때도 화면이 비어 보이지 않게 한다
- 정적으로 뚝 뜨던 화면에 스크롤 페이드인·hover 효과로 생동감을 준다

### ✅ 구현 내용

#### 히어로 오토플레이 캐러셀 전환
- **파일**: `src/features/home/components/Hero.tsx`
- **변경 내용**: 수동 `useState(page)` 페이지네이션을 `embla-carousel-react` + `embla-carousel-autoplay` 기반 캐러셀(5초 간격, `stopOnInteraction: false`)로 교체. 화살표 버튼 제거, 도트 인디케이터를 다음 섹션으로 스크롤하는 힌트 버튼으로 교체
- **이유**: 오토플레이가 도입되면서 수동 화살표·도트는 더 이상 필요한 컨트롤이 아니게 됐다

#### 패널 폭 계산 버그 수정
- **파일**: `src/features/home/components/Hero.tsx`
- **변경 내용**: `LG_BASIS` 룩업 테이블에 슬롯 1개 항목이 없어 `lg:basis-1/4`(25%)로 폴백되던 버그를 `BASIS_CLASS`로 1~4개 전 구간을 명시해 수정
- **이유**: 다가오는 축제가 정확히 1건일 때 히어로 패널이 화면의 25%만 차지하는 실제 프로덕션 버그였다

#### 히어로 높이를 뷰포트 기준으로 전환
- **파일**: `src/features/home/components/Hero.tsx`, `src/app/page.tsx`
- **변경 내용**: 고정 높이(`h-[560px] lg:h-[952px]`)를 `h-[calc(100vh-72px)] min-h-[420px] max-h-[952px]`로 교체해 화면 크기와 무관하게 첫 화면 끝까지 히어로가 닿게 함
- **이유**: 화면을 아래로 내릴 때 히어로가 화면을 꽉 채운 뒤 다음 섹션이 이어지는 느낌을 만들기 위함

#### 와이드 화면 비율 완화
- **파일**: `src/features/home/components/Hero.tsx`, `src/app/page.tsx`
- **변경 내용**: 높이 상한 952px가 화면 폭과 무관한 고정값이라 와이드 모니터(2560px 등)에서 패널 폭:높이 비율이 0.67까지 벌어지던 것을, `xl`(1280)·`2xl`(1536) 구간에서 상한을 1100px·1300px로 단계적으로 완화해 0.49로 개선
- **이유**: 패널이 풀블리드로 넓어지는데 높이만 고정 상한에 눌려 납작해 보이는 문제였다

#### 다가오는 축제 0건 폴백 화면
- **파일**: `src/features/home/components/Hero.tsx`, `src/app/globals.css`
- **변경 내용**: 방학 등으로 다가오는 축제가 없을 때 단순 텍스트 대신, 실제 패널과 같은 다크 틴트 위에 서비스 소개 카드 3개(축제 라인업/아티스트/통합 검색, 실제 목적지 화면이 있는 라우트만) + 은은한 배경 모션 + 순차 페이드업 등장을 배치
- **이유**: 빈 히어로가 첫 화면 전체를 차지하는데 아무 정보도 없으면 서비스가 죽어 보인다

#### 스크롤 페이드인
- **파일**: `src/components/ui/FadeInSection.tsx`(신규), `src/app/page.tsx`
- **변경 내용**: `IntersectionObserver` 기반으로 스크롤 진입 시 페이드인하는 컴포넌트를 만들어 "최근 등록된 축제" 섹션에 적용. JS 실행 전·비활성 시 기본값은 항상 보이는 쪽으로 두고 `prefers-reduced-motion`을 지원
- **이유**: 히어로가 화면을 꽉 채운 뒤 다음 섹션이 뚝 끊기지 않고 자연스럽게 이어지게 하기 위함

#### 카드 hover 확대 효과
- **파일**: `src/features/home/components/RecentCard.tsx`
- **변경 내용**: hover 시 포스터가 살짝 확대되며(`scale-105`) 그림자(`shadow-hover`)가 뜨도록 추가
- **이유**: `{elevation.hover}` 토큰이 정의만 되어 있고 실사용처가 없었다

#### 간격·표본 정리
- **파일**: `src/app/page.tsx`, `src/app/showcase/hero/page.tsx`, `src/app/showcase/_components/samples.ts`
- **변경 내용**: "최근 등록된 축제"·"분실물·광고" 두 섹션의 위쪽 여백을 `mt-16` → `mt-20`으로 통일. showcase에 축제 개수별(1·2·3개) 패널 폭 표본을 추가하고 표본 높이를 실제 히어로 최대 높이(952px)로 맞춤

### 🧭 결정 기록 (ADR)

#### 히어로 옵션·플러그인 배열을 useState 초기화 함수로 고정
- **문제**: `useEmblaCarousel(options, plugins)`에 매 렌더 새로 생성되는 배열 리터럴을 넘기면, 리액트 래퍼가 "옵션이 바뀌었다"고 판단해 매번 재초기화한다. 그러면 오토플레이 타이머가 한 번도 끝나지 못하고 계속 리셋돼 캐러셀이 넘어가지 않는다
- **선택**: `useState(() => ({...}))` 지연 초기화로 옵션·플러그인 객체를 최초 1회만 생성해 참조를 고정
- **트레이드오프**: 없음 — embla-carousel-react의 공식 권장 패턴이다

#### 다가오는 축제 0건 폴백은 WebGL 없이 CSS 모션만 사용
- **문제**: "더 역동적으로" 요청에 kodit50history.com(WebGL 3D 드래그 인터랙션)류의 참고 사례가 나왔으나, 폴백 패널 하나에 전용 3D 씬을 새로 붙이는 것은 배보다 배꼽이 크다
- **선택**: 새 라이브러리 없이 기존 Tailwind 애니메이션 토큰(`--animate-hero-drift`, `--animate-fade-up`)만으로 배경 글로우 + 순차 등장을 구현
- **대안**: WebGL 3D 인터랙션 — 기각(규모 불균형). 카드 로우 없이 텍스트만 — 기각(사용자가 "역동적" 느낌을 명시적으로 요청)
- **트레이드오프**: 없음

#### 히어로 높이 상한을 화면 폭 구간별로 단계 완화
- **문제**: 패널 폭 상한(1)·패널 슬롯 추가(2)·높이 상한 완화(3) 세 방향이 있었는데, 1은 풀블리드 원칙과 충돌(양옆에 빈 공간 발생)하고 2는 이번 요청에서 "패널 4개는 유지하자"는 방향으로 배제됨
- **선택**: `xl`·`2xl` 구간에서 `max-h`만 단계적으로 완화
- **트레이드오프**: 완벽한 시안 비율(0.38)에는 못 미치고 0.49까지만 개선된다 — 뷰포트 높이를 넘지 않는 제약과 풀블리드·4패널 유지 조건 아래서 낼 수 있는 최선
