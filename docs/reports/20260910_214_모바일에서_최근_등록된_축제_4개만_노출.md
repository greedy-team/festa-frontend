# 모바일에서 최근 등록된 축제 4개만 노출

## 📌 작업 개요

홈 "최근 등록된 축제" 섹션이 모바일(2열 그리드)에서 5개를 노출해 마지막 행에 카드
한 장만 남는 고아 행이 생겼다. 모바일 뷰포트에서는 4개까지만 노출해 2 x 2로 맞추고,
태블릿·데스크톱은 기존 5개를 유지한다.

관련 이슈: #214

## 🎯 구현 목표

- 640px 미만에서 "최근 등록된 축제"를 4개까지만 표시 (2 x 2)
- sm 이상(3열 / 5열)은 5개 그대로
- 서버 렌더 결과가 어느 뷰포트에서도 어긋나지 않을 것
- 실데이터가 5개 미만일 때는 아무것도 숨기지 않을 것

## ✅ 구현 내용

### 최근 축제 그리드에 뷰포트 조건부 클래스 추가

- 파일: `src/app/page.tsx`
- 변경 내용: 그리드 컨테이너에 `recent.length > 4`일 때만
  `max-sm:[&>*:nth-child(n+5)]:hidden`를 덧붙인다. 카드는 5개 모두 렌더하고,
  640px 미만에서만 다섯 번째부터 `display: none` 처리한다.
- 이유: 노출 개수가 뷰포트에 따라 갈리지만, 개수의 상한은 데이터가(몇 개를 렌더할지),
  뷰포트 판정은 CSS가(그 중 몇 개를 보일지) 담당하도록 나눴다. 서버는 화면 폭을
  모르므로 개수 자르기를 서버나 JS에 두면 일부 뷰포트에서 틀린 화면이 나간다.

## 🧭 결정 기록 (ADR)

### 뷰포트별 노출 개수를 CSS로만 판정

- 문제: "모바일에서 4개"는 화면 폭에 따라 렌더 개수가 달라지는 요구다. 서버 컴포넌트
  (`await getRecentFestivals()`)는 요청 시점에 뷰포트를 알 수 없다.
- 선택: API 응답(기본 5개)을 그대로 다 렌더하고, `max-sm:` 유틸리티로 5번째 카드를
  640px 미만에서만 숨긴다. "5개 이상일 때만" 조건은 `recent.length > 4`로 서버에서
  건다.
- 대안:
  - `getRecentFestivals(4)`로 개수를 줄이는 안 — 데스크톱에서도 4개가 되어 요구와
    어긋난다.
  - 서버/JS에서 뷰포트 추정해 `slice` — 서버는 폭을 모르고, `useState` + `useEffect`로
    폭을 재면 첫 페인트가 일부 뷰포트에서 틀리며 JS(px)와 CSS(rem) 브레이크포인트
    단위가 갈린다. 히어로 패널 캐러셀에서 같은 방식으로 겪었던 문제다.
  - `hidden sm:flex`를 5번째 카드에 직접 부여 — 카드 루트(`Link`)의 `flex`와
    `display` 유틸리티가 충돌하고, 클래스 병합 유틸리티가 이 저장소에 없어 순서
    의존이 생긴다.
- 트레이드오프: 그리드 컨테이너 클래스에 arbitrary variant(`[&>*:nth-child(n+5)]`)가
  하나 들어와 이 파일에서는 처음 쓰는 표기다. 대신 카드 컴포넌트에 prop을 추가하거나
  래퍼를 두지 않아 변경 범위가 한 줄로 닫힌다.

## 🔧 주요 변경사항 상세

### page.tsx

```
recent.length > 4 ? "max-sm:[&>*:nth-child(n+5)]:hidden" : ""
```

컴파일 결과는 `@media not (min-width: 40rem)` 안에서
`.max-sm:[...] > :nth-child(n+5) { display: none }` 한 규칙이다. 640px 이상에서는 이
규칙이 적용되지 않아 카드가 각자의 `flex`로 그대로 표시된다.

특이사항:
- 현재 운영 API는 "최근 등록된 축제"가 1건이라(`recent.length > 4`가 거짓) 이 화면에서는
  아무것도 숨기지 않는다. mock 환경(13건)에서만 4 / 5 분기가 실제로 보인다.
- DESIGN.md의 "최근 등록된 축제" 절은 데스크톱 5-up만 기술한다. 모바일 노출 개수 규칙의
  문서 반영은 이 작업에 포함하지 않았다 — 구현이 시안을 앞서고 문서 갱신을 별도 작업으로
  두는 기존 방침(#182 → #184 선례)에 맞췄다.

  브라우저 창이 그 폭까지 축소되지 않아 대신 컴파일 CSS로 검증했다.

## 📌 참고사항

- e2e에는 최근 축제 카드 개수를 단언하는 테스트가 없어 회귀 위험이 낮다. 개수 분기를
  고정하려면 mock 환경에서 375 / 640 폭 카드 수를 확인하는 e2e를 추가할 수 있다.
- `max-sm:` 변형은 이 저장소에서 처음 쓰였다. 앞으로 모바일 전용 처리에 재사용 가능.
