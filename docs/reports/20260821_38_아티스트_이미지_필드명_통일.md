### 📌 작업 개요
mock 응답마다 제각각이던 아티스트 이미지 필드명(`portraitUrl`/`photoUrl`/`avatarUrl`)을 `imageUrl` 하나로 통일했다.

### 🔍 문제 분석
아티스트 이미지를 가리키는 필드명이 응답마다 달랐다 — `src/mocks/handlers/artists.ts`는 `portraitUrl`, `hosts.ts`의 `frequentArtists`는 `photoUrl`, `search.ts`는 `avatarUrl`을 썼다. 전부 같은 값(항상 `null`, DEC-0063에 따라 아티스트 실사진은 쓰지 않음)인데 응답마다 이름이 갈려서 프론트 타입 정의가 그만큼 불필요하게 늘어났다.

### ✅ 구현 내용

#### 필드명 통일
- **파일**: `src/mocks/fixtures/db.ts`, `src/mocks/handlers/artists.ts`, `src/mocks/handlers/festivals.ts`, `src/mocks/handlers/hosts.ts`, `src/mocks/handlers/search.ts`, `src/mocks/CODE_GUIDE.md`
- **변경 내용**: `ArtistRecord.portraitUrl` → `imageUrl`로 스키마 자체를 바꾸고, 이 필드를 참조하는 5개 핸들러 파일의 응답 매핑도 함께 수정
- **이유**: DEC-0081과 API 명세 수정 목록이 이미 `imageUrl`로 필드명을 확정해뒀다 — mock을 그 명세에 맞춤

### 🧭 결정 기록 (ADR)
해당 없음 — 이미 확정된 명세(DEC-0081)를 mock에 반영한 기계적 리팩터링이다.

### 🔧 주요 변경사항 상세
`ArtistRecord` 타입 정의의 필드명을 바꾸면 TypeScript가 이를 참조하는 모든 핸들러의 타입 에러를 잡아주므로, 빠짐없이 5개 파일을 고칠 수 있었다.
