# 히어로 캐러셀과 축제 카드 — showcase 전시

### 📌 작업 개요

DESIGN.md 홈(06-D)이 요구하는 컴포넌트를 만들고 `/showcase/hero`·`/showcase/card`에 전시했다. 4분할 히어로 캐러셀, 최근 등록 카드, 섹션 헤더 행, 포스터 이미지와 날짜 유틸까지다.

홈 조립은 범위에서 뺐다. 루트 경로는 플레이스홀더로 두고 검증은 showcase가 맡는다.

### 🧭 결정 기록 (ADR)

#### D-day 계산의 기준 시각을 KST에 고정

- **문제**: 히어로가 클라이언트 번들에 들어가 서버와 브라우저 양쪽에서 실행된다. 실행 환경의 로컬 날짜를 쓰면 한국 시각 0~9시에 두 곳의 "오늘"이 하루 달라 D-day가 틀리고 하이드레이션이 깨진다
- **선택**: `toLocaleDateString("sv-SE", { timeZone: "Asia/Seoul" })`로 KST를 못박는다. `sv-SE` 로케일이 `YYYY-MM-DD`를 그대로 준다
- **대안**:
  - 서버에서만 계산해 prop으로 내리기 — 캐시된 페이지가 자정을 넘기면 같은 문제가 다시 난다
  - UTC 기준 — 축제는 전부 한국에서 열린다. 한국 사용자에게 하루 어긋난 D-day를 보인다
- **트레이드오프**: 해외 축제가 생기면 축제별 타임존이 필요하다
- **검증**: `TZ=UTC` → D-5, `TZ=Asia/Seoul` → D-4로 재현했고 고정 후 일치
- ⭐ **볼트 승격 권장** — 같은 함정을 목 계층(`src/mocks/fixtures/date.ts`)이 먼저 밟았다. 두 번 난 문제다

#### 컴포넌트를 홈에 조립하지 않고 showcase에 전시

- **문제**: 홈까지 한 이슈에 넣으면 히어로 클릭 인터랙션(DESIGN.md Known Gaps에서 세 안이 경합 중)이 막는다
- **선택**: 루트 경로는 플레이스홀더로 두고 부품만 전시한다. 홈 조립은 별도 이슈
- **대안**: 홈까지 만들기 — 처음에 만들었다가 되돌렸다. 미결 인터랙션 위에 조립하면 정해질 때 다시 뜯는다
- **트레이드오프**: API 레이어(`getUpcomingFestivals`·`getRecentFestivals`)에 호출부가 없는 상태로 머지됐다. 아래 「참고사항」에 적었다

#### 포스터 없음이 정상 경로

- **문제**: 목의 `posterUrl`은 대부분 `null`이고, 값이 있어도 존재하지 않는 CDN을 가리켜 로드에 실패한다
- **선택**: 틴트를 먼저 깔고 이미지를 그 위에 얹는다. 실패하면 이미지가 스스로 사라지고 틴트가 남는다
- **대안**: 스켈레톤·대체 이미지 — 실패가 예외가 아니라 다수인 상황에서 매번 깜빡인다
- **트레이드오프**: 이미지가 성공해도 밑에 틴트가 깔려 있어 투명 PNG면 배경색이 비친다

#### 도트 개수를 계산한다

- **문제**: DESIGN.md는 도트 8개를 그려 두었지만 그것은 축제 32개를 전제한 그림이고, 문서 스스로 축제 수가 다를 때의 규칙이 없다고 적었다
- **선택**: `ceil(축제 수 / 현재 패널 수)`
- **대안**: 8 고정 — 축제가 12건이면 빈 페이지 5개가 생긴다
- **트레이드오프**: 축제가 아주 많으면 도트가 pill을 넘친다. 상한 규칙은 아직 없다

### 🔧 주요 변경사항 상세

#### fetchJson — 실패를 삼키지 않고 결과로 돌려준다

최초 구현은 성공·HTTP 에러(404/500)·연결 실패 셋을 전부 `fallback` 하나로 뭉갰다. 호출부에서 "축제가 0건"과 "서버가 500을 냈다"가 똑같은 값이라 구분할 수 없었다.

리뷰 반영으로 판별 유니온을 돌려주게 바꿨다.

```
fetchJson<T>(path, fallback): Promise<T>
  → fetchJson<T>(path): Promise<ApiResult<T>>

type ApiResult<T> =
  | { ok: true;  data: T }
  | { ok: false; status: number | null; message: string }
```

- `status`는 서버가 응답한 HTTP 코드다. `null`이면 응답 자체가 없었다는 뜻이다(연결 실패·DNS·타임아웃)
- 200인데 본문이 에러 페이지 HTML인 경우도 "연결 실패"가 아니라 `status: 200`으로 잡힌다
- `fallback` 인자는 없앴다. 실패했을 때 무엇을 보일지는 라이브러리가 아니라 화면이 정한다

**던지지 않는 성질은 그대로다.** 삼키기를 그만둔 것이 아니라 호출부로 넘기게 바꾼 것이다.

#### Hero.tsx

`festivals.length`와 현재 패널 수로 페이지 수를 구하고, 패널 수가 바뀌어 마지막 페이지를 넘어서면 `Math.min`으로 당긴다. 축제가 0건이면 캐러셀 대신 빈 상태를 그린다.

**특이사항**:

- 패널 수 결정이 `useState(1)` + `useEffect`라, 서버가 내보내는 HTML은 화면 폭과 무관하게 항상 패널 1장이다. 근본 수정이 필요한 항목으로 이슈 #35에 증상과 방향을 함께 적었다
- 조건부 렌더에 `&&`를 쓰지 않는다. 좌변이 `0`이면 화면에 `0`이 찍힌다

#### HeroPanel.tsx

D-day는 스크림 밖 상단(y140), 나머지 정보는 스크림 안 하단(y700~897)에 붙어 패널 가운데를 비운다. 실제 포스터가 들어갔을 때 주제가 드러나는 자리다. 위계는 흰색 불투명도 100 / 85 / 75%로만 낸다 — 히어로에는 인디고를 쓰지 않는다.

### 📌 참고사항

**전시 화면이 MSW 목이 아니라 고정 표본을 쓴다.** `/showcase/hero`와 `/showcase/card`는 `_components/samples.ts`의 상수를 그린다. 홈 조립을 되돌리면서 fetch 호출부가 함께 빠졌고, 완료 조건은 되돌리기 전에 작성된 것이라 문구가 남았다. 그 결과:

- `getUpcomingFestivals`·`getRecentFestivals`에 호출부가 없다. 홈 조립 이슈에서 처음 쓰인다
- 빌드 출력이 8개 페이지 전부 `○ Static`이다. 요청 시점 렌더가 필요한 화면이 없다
- 목을 켜고 끄는 것이 전시 화면에 영향을 주지 않는다

부품 검증에는 문제가 없다 — 표본이 12건 목 데이터에서 뽑은 것이라 화면에 뜨는 값은 같다. 다만 **API 레이어는 아직 한 번도 실제로 실행된 적이 없다.** 홈 조립 때 첫 연결에서 문제가 드러날 수 있다.

**`getUpcomingFestivals(limit = 12)`의 기본값에 제품 근거가 없다.** 목 축제를 12건으로 늘린 작업에서 나온 숫자가 그대로 기본값이 됐다. 백엔드가 붙어 축제가 200건이 돼도 히어로는 12건만 받는다. DESIGN.md는 도트 8 × 패널 4 = 32건을 전제하지만 같은 문서 Known Gaps가 "축제 수가 그보다 적거나 많을 때의 규칙이 없다"고 적어 두었다. 기본값을 지우고 호출부가 정하게 하거나 32로 확정하는 판단이 필요하다.

**HMR이 서버측 모킹을 푼다.** `instrumentation.ts`의 register는 서버 부팅 시 한 번만 실행된다. 파일을 고쳐 HMR이 돌면 패치가 풀려 요청이 실제 인터넷으로 나간다. 로컬에서 데이터가 안 보이면 코드를 의심하기 전에 개발 서버를 재시작한다. `src/mocks/README.md`에도 남겼다.

**범위에서 뺀 것**: 홈 조립, 분실물 패널·광고 배너(목 핸들러가 분실물을 P1 보류로 명시), 히어로 클릭 인터랙션(Known Gaps에서 세 안 경합), 히어로 자동재생(전환 방식·주기 미정의).

**이 이슈는 PR 머지로 자동 종료되지 않는다.** 브랜치명이 #34에서 딴 것이라 #34만 닫혔다.
