# 검색 연관 검색어(relatedKeywords)를 빈 배열로 고정하고 추천 검색어 UI 제거 (#140)

### 📌 작업 개요

통합 검색(`GET /search`) 화면은 "결과 0건이면 `relatedKeywords`를 추천 검색어 칩으로
보여준다"는 전제로 조립돼 있었다(ISS-0063(#53) 통합 검색 결과 화면 조립, 2026-08-21).
이후 백엔드가 이번 검색 API 범위에서 연관 검색어 생성을 빼기로 통지했고 — 연관 검색어는
2026-08-09 회의에서 P3로 내려간 항목이다 — 실제 API는 `relatedKeywords`를 항상 빈 배열로
내린다.

그 결과 (1) MSW 목이 0건일 때 예시 추천어 3개를 채워 실제 계약과 갈렸고, (2) 검색 화면의
"추천 검색어" 렌더 블록은 실 환경에서 절대 실행되지 않는 죽은 코드가 됐다. 이 PR은 목을
실제 계약에 맞추고 죽은 UI를 제거한다.

### 🎯 구현 목표

- MSW `/search`·`/search/autocomplete` 핸들러의 `relatedKeywords`를 조건 없이 빈 배열로
- 검색 결과 0건 화면에서 추천 검색어 칩 블록 제거, "검색 결과가 없습니다." 안내만 유지
- 응답 계약에 필드가 남으므로 `SearchResponse.relatedKeywords` 타입 선언은 유지
- 라우팅·그 밖의 화면 동작 변경 없음

### ✅ 구현 내용

#### 검색 0건 화면에서 추천 검색어 블록 제거

- **파일**: `src/app/search/page.tsx`
- **변경 내용**: `!data.counts.all`일 때 렌더하던 `<div>`(안내 문구 + `data.relatedKeywords`
  map으로 `Chip` 링크 나열, 13줄)를 안내 문구 한 줄(`<p>검색 결과가 없습니다.</p>`)로 축소
- **이유**: `relatedKeywords`가 항상 `[]`라 `data.relatedKeywords.length` 분기가 실 환경에서
  절대 참이 되지 않음. `Link`·`Chip` import는 타입 필터 칩에서 계속 쓰여 유지

#### MSW 검색 핸들러 응답 정합

- **파일**: `src/mocks/handlers/search.ts`
- **변경 내용**:
  - `/search`: `relatedKeywords: counts.all === 0 ? ['연세대 아카라카', '대학 축제', '싸이'] : []`
    → `relatedKeywords: [] as string[]` (범위 밖임을 밝히는 주석 추가)
  - `/search/autocomplete`: `relatedKeywords: primary ? [] : ['연세대 아카라카', ...]`
    → `relatedKeywords: [] as string[]`
- **이유**: 실제 API가 항상 `[]`를 내리므로 목을 계약에 일치시킴. 하드코딩 예시 추천어 제거

#### 이슈 초안 문서 추가

- **파일**: `docs/issues/20260831_리팩토링_검색_연관검색어_빈배열_정합.md` (신규)
- **내용**: 이 리팩토링의 배경·해결 방안·작업 항목

### 🧭 결정 기록 (ADR)

#### `relatedKeywords` 타입 선언은 유지하고 필드만 빈 값으로 고정

- **문제**: 연관 검색어 기능이 이번 범위에서 빠졌다. 프론트 타입에서 `relatedKeywords`
  자체를 지울지, 필드는 남기고 값만 빈 배열로 둘지
- **선택**: `SearchResponse.relatedKeywords: string[]` 타입 선언 유지. 값만 항상 `[]`
- **이유**: 백엔드 `SearchResponse`의 유일한 팩토리가 `relatedKeywords`에 무조건
  `List.of()`를 넣는다(리뷰에서 백엔드 코드로 확인). 필드는 응답 계약에 그대로 존재하며
  `null`이나 필드 누락은 나오지 않는다. P3로 밀린 기능이 되살아나면 타입을 다시 만들 필요
  없이 값 소스만 연결하면 된다
- **트레이드오프**: 아무도 읽지 않는 필드가 타입에 남는다. 목 2곳 + 타입 1곳이 전부이고
  주석으로 사유를 남겨 혼동을 줄였다

#### 외부 동작 변경 — 0건 화면의 "추천 검색어" 칩 제거

- **변경**: 검색 결과 0건일 때 나오던 "추천 검색어" 칩이 사라진다
- **영향**: 데이터 소스가 없어 실 환경에서는 늘 빈 상태였을 영역. 사용자 체감 변화는
  로컬 목 환경에서만 발생
- 리뷰어 승인 완료

### 📌 참고사항

- **백엔드 확인 완료**: `SearchResponse` 팩토리가 `relatedKeywords`에 항상 `List.of()`.
  실 API도 항상 `[]`, `null`·필드 누락 없음. 이 필드를 읽는 프론트 코드는 이 PR 이후 없음
  (타입 선언 1곳 + 목 2곳이 전부)
- **범위 밖 (별건 이슈 #145로 분리)**: 리뷰에서 `page.tsx`의 `counts.all` 사용이 지적됐다.
  타입 칩으로 결과를 좁혔을 때(`?q=…&type=HOST` 등) 헤더 count와 빈 상태 판정이 모두
  `counts.all`(타입 무관 매치 수 합)을 써서, 선택 타입에 매치가 없으면 "N건"으로 표시되고
  "검색 결과가 없습니다"도 안 뜬다. 이 PR의 0건 블록 바로 그 줄이지만 relatedKeywords와
  별개 관심사(카운트 로직)이고 동작 변경(`type: fix`)이라 [#145](https://github.com/greedy-team/festa-frontend/issues/145)로 분리
