### 📌 작업 개요
통합 검색 결과(`/search`) 화면을 새로 만들고, nav의 표시 전용 검색창을 실제로 동작하는 검색 폼으로 교체했다.

### 🎯 구현 목표
- 아티스트·학교·축제 세 카테고리를 한 화면에서 보여주는 통합 검색
- JS 없이도 동작하는 GET 폼 기반 검색

### ✅ 구현 내용

#### 검색 결과 화면 신규
- **파일**: `src/app/search/page.tsx`, `src/features/search/api.ts`, `src/features/search/types.ts`
- **변경 내용**: `GET /search`(q/type) 연동, 타입 필터 칩(전체/아티스트/학교/축제), 결과 0건일 때 추천 검색어 표시
- **이유**: 12-2 시안에 정의된 통합 검색 화면

#### 결과 행 3종
- **파일**: `src/features/search/components/ArtistResultCard.tsx`, `FestivalResultRow.tsx`, `SchoolResultRow.tsx`
- **변경 내용**: 기존 카드(세로 그리드 + 포스터)와 다른 가로 행 구조로 신규 작성. `FestivalResultRow`는 축제명이 아니라 학교명에서만 검색어가 매칭됐을 때 "학교명 일치" 표시를 추가
- **이유**: 시안(검색 결과 리스트)이 카드가 아니라 행 레이아웃이라 기존 컴포넌트를 재사용하지 않음

#### nav 검색을 실제 폼으로 교체
- **파일**: `src/components/layout/NavSearchForm.tsx`, `src/components/layout/Header.tsx`
- **변경 내용**: `<form action="/search"> GET` 제출로 `/search?q=`로 이동. `router.push` 없이 서버 컴포넌트로만 구현
- **이유**: 기존 `SearchPill`은 표시 전용(`aria-hidden`)이라 실제 검색에 쓸 수 없었다

### 🧭 결정 기록 (ADR)

#### 검색은 `res.ok` 실패와 "0건"을 구분한다
- **문제**: 초기 구현은 검색 실패도 결과 0건과 같은 빈 상태로 보여줬다. 다른 화면(목록)은 0건이 드문 경우지만, 검색은 0건이 정상 상태라 사용자가 실패와 구분할 단서가 아예 없었다
- **선택**: `res.ok`로 먼저 갈라 실패 시 "검색 결과를 불러오지 못했습니다" 별도 문구, 진짜 0건일 때만 추천 검색어와 함께 "검색 결과가 없습니다"
- **트레이드오프**: 다른 목록 화면보다 이 구분이 더 중요한 이유(0건이 정상 상태)를 코드 주석에 남김

#### `NavSearchForm`과 `SearchPill(nav variant)`의 클래스 중복은 그대로 둔다
- **문제**: 두 컴포넌트가 같은 시안 값(280×40)을 각자 갖고 있어 DESIGN.md가 바뀌면 한쪽만 고쳐질 위험이 있다
- **선택**: 통합하지 않음 — `SearchPill`은 `aria-hidden` 표시 전용 계약을 갖고 있고, `nav` variant는 이제 컴포넌트 시트(`showcase/chip`)의 참조용 표본으로만 쓰인다. 폼으로 바꾸면 그 계약이 깨지고, 지우면 시트의 참조가 사라진다
- **대안**: 둘 중 하나로 통합 — 검토했으나 어느 쪽도 깔끔하지 않아 보류

### 🔧 주요 변경사항 상세
