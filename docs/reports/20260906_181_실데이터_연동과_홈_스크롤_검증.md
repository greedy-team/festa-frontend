# #181 실데이터 연동과 홈 스크롤 검증

검증일: 2026-09-06. FE 기준 커밋 `60bb5c2`, 크롤러 `65f1312`.
이슈: https://github.com/greedy-team/festa-frontend/issues/181

## 변경

- 홈의 최근 축제·광고 영역이 최소 한 화면에서 헤더 높이를 뺀 만큼의 높이를 갖는다. 최근 축제가 적어도 맨 아래에서는 히어로를 벗어나며 광고는 하단에 배치한다. 히어로 자체 높이와 이름 벽 모션은 유지한다.
- 공개 축제 입장 안내의 세 enum 필드가 null일 수 있음을 타입에 반영하고 기존 ‘안내 없음’ 표시를 명시적으로 처리한다. 실제 축제 8번 응답의 verification·ticketType이 null이었다.
- 높은 화면의 최대 스크롤 위치에서 히어로 하단과 헤더 배경을 확인하는 회귀 테스트를 추가한다.

## API·화면 검증

- 로컬 `api-docs.json`과 서버 `/docs/v3/api-docs`의 paths·components를 재귀 비교했다. 39개 작업, 차이 0건.
- 공개 8종(예정·최근·축제 목록·축제 상세·아티스트 목록·아티스트 상세·주최 상세·검색)의 실제 GET 응답이 모두 200이었다.
- 홈, 축제 8번, 아티스트 3번, 주최 9번 및 이력, 목록·검색 화면에서 실제 데이터를 확인했다. 표본 이동 중 pageerror와 관측된 400 이상 응답은 없었다. 모든 데이터 조합의 보장은 아니다.
- 관리자 31개 작업 중 27개에 호출 구현이 있다. 단일 CSV 임포트·일괄 발행·커버리지·라인업 단건 조회는 호출하지 않는다. 각각 번들 전용 화면·개별 발행·화면 없음·라인업 목록 응답 활용에 해당하며, 미호출 자체를 오류로 판정하지 않았다.
- 관리자 축제 폼은 주최 목록 첫 50개만 선택지로 사용한다. 현재 선택된 주최는 추가하지만 새 주최 선택에는 이 한계가 남는다.
- 관리자 로그인·인증 후 CRUD·병합·임포트·발행을 실서버에서 완료했다는 증거는 없다. 자동 승인 검토가 자격증명 전송의 목적지 확인을 요구해 로그인 실행을 거부했다. 사용자 확인 질문이 대기 중이다. 운영 데이터를 변경하지 않았다.

## 검증 결과

- 추가 회귀 테스트는 수정 전 실패: 히어로 하단 383px, 기대 ≤72px.
- 수정 후 홈 스크롤·모션 감소 E2E 8개 통과. 1440·1880·375px 화면과 스크롤 힌트 키보드 이동 포함.
- 유닛 133개 통과. TypeScript `tsc --noEmit --incremental false` 통과.
- lint: 오류 0, 기존 생성 파일 `public/mockServiceWorker.js` 경고 1개.
- 수정 전 실데이터 전체 조회 E2E는 28개 통과·1개 스킵·3개 실패. 실패는 시크릿 게스트 부재 1개와 축제 2페이지 부재 2개다. 목 전제 테스트가 현재 실데이터에 맞지 않은 결과이며 전체 E2E 통과로 표기하지 않는다.
- 후속 검증: 수정 커밋 `ec43df1`을 임시 폴더에 복사하고 환경변수 파일 없이 `CI=true pnpm test:e2e`를 실행했다. 기존 설정의 `pnpm build && pnpm start`가 성공했으며 E2E 37개 통과·3개 스킵이었다. 스킵은 예정 축제가 존재하는 목 데이터에서 실행 대상이 아닌 빈 히어로 테스트 3개다. 이 검증은 관리자 로그인·검수의 목 테스트를 포함하지만 실제 관리자 인증·저장을 검증한 것은 아니다. 실행 중인 원본 개발 서버의 빌드 폴더에는 손대지 않았다.

## 크롤러 검증

크롤러는 검증만 수행했고 소스·산출물을 수정하지 않았다. 외부 수집·LLM 추출을 새로 실행한 결과가 아닌 기존 산출물 검사다.

- 현재 브랜치: `fix_24_채울_수_있는_값이_빈다_charset_폴백과_하루_축제_추론`.
- pytest 172개 통과.
- `FESTIVAL_FIELDS`, `LINEUP_FIELDS`, `ARTIST_FIELDS`와 백엔드 `ImportSection`의 열 이름·순서가 모두 일치한다.
- 2026 산출물: 축제 29행(OK 26, NO_CANDIDATE 3), 라인업 219행, 아티스트 133행.
- 축제 키 중복 0, 축제 CSV에 없는 키를 참조하는 라인업 0, OK 축제의 좌표 누락 0.
- 한국외대 `QUINQUATRIA: Luminous`는 OK지만 시작일이 없다. 서울대 12행·서울시립대 6행은 공연 day가 없다. 백엔드가 필수 날짜·양의 day를 검사하므로 해당 행은 교정 없이 전체 반영할 수 없다. 결측값을 추측해 채우지 않았다.
- 현재 브랜치와 로컬 develop의 `import_key()`는 `{주최}-{캠퍼스}-{연도}`다. 볼트 DEC-0167의 월 세그먼트(미상 00)가 반영돼 있지 않다. 원격 최신 코드나 별도 작업 폴더의 상태까지 확인한 결론은 아니다. 기존 DB 키 이관 없이 키 형식만 바꾸면 중복 축제를 만들 수 있어 이번 FE 이슈에서 변경하지 않았다.

## 남은 작업

관리자 로그인 목적지 승인이 오면 인증된 조회·편집 폼을 검증한다. 운영 데이터 쓰기·삭제·발행은 별도 격리된 검증 대상이 확보되기 전까지 실행하지 않는다. 크롤러 누락값은 원문 확인을 통해 교정해야 하며 월 키 전환은 기존 DB 키와 함께 검토해야 한다.

사용자 지시에 따라 issue-branch의 빈 브랜치 선행 푸시는 생략했다. FE 변경은 로컬 커밋만 남긴다.
