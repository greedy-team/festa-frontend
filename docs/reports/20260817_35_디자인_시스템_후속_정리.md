### 🧭 결정 기록 (ADR)

#### Chip의 sheet-active를 만들지 않고 타입으로 막는다

- **문제**: `variant="sheet"`일 때 `active`가 아무 효과가 없다. 리뷰에서 두 가지 방향이 제시됐다 — `STYLE`에 `sheet-active`를 추가하거나, 타입으로 조합을 막거나
- **선택**: `Props`를 판별 유니온으로 만들어 `{ variant: "sheet"; active?: never }`로 막는다
- **대안**: `sheet-active` 스타일 추가 — DESIGN.md의 `sheet-chip`은 한 가지 모양뿐이고 활성 상태가 정의돼 있지 않다. 없는 디자인을 코드가 만들면 시안과 코드 중 어느 쪽이 정본인지 흐려진다
- **트레이드오프**: sheet에 선택 상태가 실제로 필요해지면 DESIGN.md에 먼저 넣고 유니온을 풀어야 한다. 한 단계가 늘지만 그 단계가 곧 시안 갱신이다

#### Header의 표시 전용 아이콘을 Footer식 데이터 배열로 묶지 않는다

- **문제**: 로그인 전 표시 전용 요소를 Footer는 `{ label, href }` 배열 + 삼항으로, Header는 하드코딩된 `<span>` 셋으로 다르게 풀고 있다는 지적
- **선택**: 현행 유지
- **대안**: 배열로 통일 — Footer의 10개는 전부 라벨 + href로 동질이라 배열이 값을 한다. Header의 셋은 벨·북마크(lucide 아이콘 + `hidden sm:inline`)와 프로필(`bg-primary` 원형, 반응형 숨김 없음)이 서로 달라 항목마다 className을 실어야 하고, 1회용 셋에 추상화를 만드는 것이 된다
- **트레이드오프**: 두 파일이 같은 문제를 다르게 푼 상태로 남는다. 로그인이 붙으면 셋이 각각 드롭다운·목록·아바타로 갈라지므로, 공통 형태가 드러난 뒤 묶는 편이 낫다고 판단했다

#### `dDay`의 기본 인자 중복 계산을 그대로 둔다

- **문제**: `dDay(startDate, today = todayInSeoul())`의 기본값이 호출마다 계산돼, 히어로가 패널 4장을 그릴 때 `todayInSeoul()`이 렌더당 최대 4번 실행된다
- **선택**: 유지
- **대안**: `Hero`에서 한 번 계산해 prop으로 내리기 — 아끼는 것은 `toLocaleDateString` 4회이고, 기본 인자를 둔 이유가 호출부를 `dDay(startDate)`로 유지하는 것이라 이점이 상쇄된다
- **트레이드오프**: 패널 수가 크게 늘거나 측정에서 잡히면 다시 본다

### 📋 잔여 항목

머지된 코드 기준 대조 결과다. 이슈 본문의 우선순위 묶음을 그대로 쓴다.

#### 1. 동작에 걸리는 것

- [ ] `Button`에 `type="button"` 기본값이 없다 — `search-filter-panel`(초기화 + 검색하기)이 곧 나오는데 폼 안에서 기본값 `submit`이 의도치 않은 제출을 일으킨다
- [ ] `Button`에 `disabled` 스타일이 없다 — `ButtonHTMLAttributes`로 `disabled`를 받으면서 비활성 버튼이 활성과 똑같이 보이고 `cursor-pointer`까지 뜬다. `HeroArrow`는 `disabled:opacity-40`이 있으니 두 곳을 같이 본다
- [x] `Chip`의 `active` 무시 — 반영됨

#### 2. 접근성

- [x] `aria-current="page"` — Header에 적용됨. `HeroDots`도 활성 도트에 `aria-current`가 있다
- [ ] `showcase/layout.tsx`의 활성 항목에는 아직 없다
- [ ] `<body>`에 기본 글자색이 없다 — 현재 `flex min-h-full flex-col bg-canvas font-sans`뿐이라, 토큰 클래스를 달지 않은 텍스트는 ink가 아니라 브라우저 기본 검정을 상속한다
- [x] `InlineFilter` — `aria-hidden` 적용됨
- [ ] `Chip`은 아직 없다. 조작할 수 없는데 시각적으로는 컨트롤로 보인다

#### 3. 컴포넌트 규약 통일

- [x] prop 이름을 `variant`로 통일
- [ ] lookup 객체 타입이 아직 갈린다 — Button·Badge·SearchPill은 `Record<K, string>`, Chip은 `as const`
- [ ] 네이티브 속성을 전개하는 것은 여전히 Button 하나뿐이다

#### 4. 토큰 리셋 범위

- [ ] `--color-*`와 `--radius-*`만 리셋돼 있다. `--text-*`, `--font-weight-*`, `--leading-*`, `--tracking-*`, `--shadow-*`는 Tailwind 기본값이 남아 `text-lg`·`font-light`·`leading-relaxed`·`tracking-wide`·`shadow-xl`이 전부 살아 있다. 각각 DESIGN.md의 Don'ts를 정면으로 뚫는다

#### 5~7. 중복과 규칙 위치

- [ ] className 규칙이 `.claude/rules/coding-principles.md`에 없다 — 추적되지 않는 스펙 문서와 Button의 인라인 주석에만 있다
- [ ] `showcase/layout.tsx`가 Chip의 클래스 문자열을 그대로 복제한다 (`h-[36px] … rounded-pill …` 두 벌). Chip이 `<span>`이라 `<Link>` 자리에 쓸 수 없어서다
- [x] `Header.tsx`의 `ml-[75px]` — 반영됨

#### 홈 화면(#36) 리뷰에서 추가된 것

- [ ] 「전체 보기 →」 정책 — `SectionHeaderRow`가 `href` 옵션을 갖도록 만들어졌으나, 홈이 플레이스홀더라 Header·Footer(`/festivals`로 링크)와의 정책 정합은 홈 조립 때 판단해야 한다
- [x] `/`에 `h1`이 없다 — 현재 플레이스홀더에 `h1`이 있다. 홈을 조립할 때 다시 확인할 항목이다
- [ ] `Hero`의 브레이크포인트가 JS는 px(640·1024), CSS는 rem(`sm:`·`lg:`)이다. 브라우저 기본 글꼴을 키운 사용자에게서 갈라지고, 갈라지면 JS가 계산한 패널 수가 CSS 열 수를 넘어 그리드가 두 줄이 된다
- [ ] 히어로 도트의 클릭 타깃이 6~8px이다 (`size-[6px]` / `size-[8px]`). 장식이 아니라 버튼이므로 데스크톱에서도 조준이 어렵다

- [ ] README가 아직 Geist를 쓴다고 적혀 있다(31행). 같은 파일의 npm·yarn 안내도 AGENTS.md의 "pnpm만" 하드 제약과 어긋난다
- [x] `showcase/button/page.tsx`의 `w-full max-w-[…]` — 반영됨

#### 히어로 초기 렌더 (근본 수정 필요)

- [ ] `Hero`의 `panels`가 1로 시작하고 `useEffect`가 실제 폭을 읽어 고친다. 서버가 내보내는 HTML은 화면 폭과 무관하게 항상 패널 1장이고, 하이드레이션까지 그 상태가 유지된다

어떤 상수로 초기화해도 일부 뷰포트에서 하이드레이션 불일치나 더 큰 플래시가 되므로 싸게 고칠 방법이 없다. 패널 수 결정을 JS에서 CSS로 옮겨야 한다 — 스크롤 스냅 캐러셀이 후보다. **위의 JS px ↔ CSS rem 항목과 뿌리가 같아, CSS로 옮기면 함께 사라진다.**
