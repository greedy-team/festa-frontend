### 📌 작업 개요

홈 히어로 패널이 축제 개수(1~4건)에 따라 어떻게 조판돼야 하는지 정해지지 않아, 4건 미만일 때
패널이 넓어지면서 내용이 좌하단에 그대로 머무는 문제를 정리했다. 개수별 조판 규칙을 확정하고
`HeroPanel` 컴포넌트에 반영했다.

### 🎯 구현 목표

- 축제 1~3건일 때 패널이 넓어지면서 생기는 빈 공간을 정보 배치로 채운다
- 4건 미만 어느 개수에서도 포스터가 잘리지 않게 한다
- 결정한 규칙을 DESIGN.md와 쇼케이스 표본에 반영해 재검토를 반복하지 않게 한다

### ✅ 구현 내용

#### 패널 조판을 개수별로 분기

- **파일**: `src/features/home/components/HeroPanel.tsx`, `src/features/home/components/Hero.tsx`
- **변경 내용**: `heroSplitFrom(count)` 헬퍼를 추가해 축제 1건은 `lg`(1024)부터, 2건은
  `xl`(1280)부터 텍스트 열 | 포스터 좌우 분할로 서고, 3건 이상은 항상 세로 스택(D-day → 포스터
  → 정보)이 되도록 했다. `HeroPanel`은 `splitFrom` prop을 받아 Tailwind 반응형 클래스를
  분기별 표(`SPLIT`)로 적용한다.
- **이유**: 패널 폭이 개수마다 달라 고정 좌표로는 대응할 수 없었다. 화면 폭이 아니라 개수로만
  분기하는 이유는 서버(SSR)가 화면 폭을 모르는 상태에서 조판을 정해야 하기 때문이다 — JS로
  뷰포트를 재서 분기하면 SSR과 하이드레이션 결과가 어긋난다.

#### 스크림 띠 제거, 포스터 원본 비율 유지

- **파일**: `src/features/home/components/HeroPanel.tsx`
- **변경 내용**: 패널 하단에 깔던 스크림 띠(360×364, 순검정 55%)를 없애고 패널 전면에
  검정 35%를 얹은 뒤, 텍스트에 그림자(`text-shadow: 0 2px 16px rgba(0,0,0,0.45)`)를 걸어
  대비를 냈다. 포스터는 어느 조판에서도 자르지 않고(`object-contain`) 남는 자리는 같은
  포스터를 흐리게 깐 배경으로 채운다.
- **이유**: 스크림 띠는 텍스트가 포스터 옆(분할)이나 위(스택)로 이동하면서 받칠 자리를
  잃었고, 포스터 하단(날짜·장소가 인쇄된 영역)을 가리는 문제도 있었다.

#### 쇼케이스 표본 갱신

- **파일**: `src/app/showcase/hero/page.tsx`, `src/app/showcase/_components/samples.ts`
- **변경 내용**: 히어로 쇼케이스의 "패널 폭 — 축제 개수별" 절을 1~3건에서 1~4건으로
  확장하고, 각 표본 라벨에 분기 브레이크포인트(`lg부터 좌우 분할` 등)를 표시했다. 표본
  데이터에 4번째 축제(한양대 라치오스)를 추가했다.
- **이유**: 실제 화면에서 확인하기 어려운 조합(2·3·4건, 데스크톱 기준)을 한 화면에서
  대조할 수 있어야 회귀를 바로 알아챌 수 있다.

### 🧭 결정 기록 (ADR)

### 히어로 패널을 좌우 분할 vs 세로 스택으로 나누는 기준

- **문제**: 패널 폭이 1440(1건)부터 360(4건)까지 개수마다 달라, 하나의 조판으로는 넓은
  패널의 빈 공간과 좁은 패널의 좌우 여유 부족을 동시에 해결할 수 없었다
- **선택**: 패널이 텍스트 열 + 포스터를 나란히 둘 만큼 넓어지는 개수(1·2건)에서만 좌우
  분할을 쓰고, 그 아래(3건 이상)는 항상 세로 스택
- **대안**:
  - 4건 조판을 그대로 축소 적용 — 패널이 넓어져도 텍스트가 좌하단에 그대로 남아 원래
    문제를 해결하지 못한다
  - 개수와 무관하게 항상 좌우 분할 — 3·4건은 패널이 341px 이하라 텍스트 열이 들어갈
    폭이 없다
- **트레이드오프**: 조판 분기가 3갈래(스택/lg분할/xl분할)로 늘어 `HeroPanel`의 스타일
  테이블이 커졌다. 향후 5건 이상(캐러셀 오버플로) 케이스는 이번 범위에 포함하지 않았다

### 🔧 주요 변경사항 상세

#### `heroSplitFrom` 헬퍼

`Hero.tsx`에 `count <= 1 ? "lg" : count === 2 ? "xl" : null`로 정의했다. `slideBasisClass`와
같은 패턴(개수 → 리터럴 클래스 테이블)을 따라, 분기점을 함수 하나로 모아 `HeroPanel`과
쇼케이스가 같은 기준을 참조하게 했다.

**특이사항**:
- 1건은 `lg`(1024)부터, 2건은 `xl`(1280)부터 분할이 시작되는 것이 비대칭적으로 보일 수
  있는데, 1건은 패널이 전체 폭이라 1024에서 이미 여유가 있고 2건은 패널이 반폭이라
  1280(패널 640)은 돼야 같은 구성이 들어가기 때문이다.

#### `HeroPanel`의 `SPLIT` 스타일 테이블

`lg`/`xl` 각각에 대해 그리드 컨테이너, 텍스트 열, 정보 블록, 포스터 높이 클래스를
리터럴로 미리 적어뒀다 — 템플릿 문자열로 브레이크포인트를 조합하면 Tailwind가 빌드
시점에 클래스를 인식하지 못한다(`slideBasisClass`의 `BASIS_CLASS`와 같은 이유).
