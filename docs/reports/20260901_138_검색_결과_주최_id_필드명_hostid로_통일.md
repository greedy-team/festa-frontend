# 검색 결과 주최 id 필드명 hostId로 통일 (#138)

### 📌 작업 개요

검색(`GET /search`) 응답에서 주최 식별자 필드명이 다른 도메인과 어긋나 있었다. 축제는
`festivalId`, 아티스트는 `artistId`를 쓰는데 주최만 `id`였다. 백엔드가 검색 결과의 주최
식별자를 `hostId`로 통일했다고 통지해, 프론트 타입·컴포넌트·목 핸들러를 맞췄다.

리뷰에서 "중첩 host는 범위 밖"이라는 지적을 받아, 축제 검색 결과에 중첩된 `host` 객체는
`id`로 되돌렸다. 최종 반영 범위는 **최상위 `hosts[]`(= 백엔드 `SearchHostResponse`) 하나**다.

### 🎯 구현 목표

- 검색 결과 최상위 주최 결과의 식별자를 `id` → `hostId`로 변경
- 이 필드를 참조하는 컴포넌트·리스트 key·목 핸들러 동기화
- 화면 동작·라우팅 경로 변경 없음

### ✅ 구현 내용

#### 검색 타입 정의 수정

- **파일**: `src/features/search/types.ts`
- **변경 내용**: `HostResult.id` → `HostResult.hostId`. 중첩 `FestivalResult.host`는 `id` 유지
- **이유**: 백엔드 통지 범위(`SearchHostResponse`)가 최상위 주최 결과 하나뿐. 중첩
  `host`는 검색 전용이 아닌 공용 레코드(`HostSummaryResponse`)라 백엔드가 안 건드림

#### 학교 결과 행 컴포넌트 수정

- **파일**: `src/features/search/components/SchoolResultRow.tsx`
- **변경 내용**: 구조 분해와 사용처를 `id` → `hostId`로 교체 (`href={/hosts/${hostId}}`,
  `gridTint(hostId)`)
- **이유**: 타입 변경에 따른 참조 정합. 실제로는 버그도 함께 고쳐졌다 (아래 상세)

#### 검색 페이지 리스트 key 수정

- **파일**: `src/app/search/page.tsx`
- **변경 내용**: 학교 결과 map의 `key={host.id}` → `key={host.hostId}`
- **이유**: 실 API 연결 시 `host.id`가 `undefined`라 모든 학교 행의 key가 동일해지는 문제

#### 검색 목 핸들러 응답 키 수정

- **파일**: `src/mocks/handlers/search.ts`
- **변경 내용**: `toHostResult` 반환 키를 `id` → `hostId`. `toFestivalResult`의 중첩 host는
  `id` 유지
- **이유**: 목 응답을 실제 계약과 일치시킴. `toHostResult`는 검색 결과·자동완성 공용

### 🧭 결정 기록 (ADR)

#### 검색 host 필드 통일 범위를 최상위 `SearchHostResponse` 하나로 한정

- **문제**: 검색 응답에는 최상위 `hosts[]`와 축제 결과에 중첩된 `host` 두 자리에 주최
  식별자가 있다. 둘 다 `id`였고, 어디까지 `hostId`로 바꿀지 판단이 필요했다
- **선택**: 백엔드가 실제로 바꾼 최상위 `SearchHostResponse`만 `hostId`로 반영. 중첩
  `host`는 `id`로 되돌림
- **대안**:
  - 중첩 host까지 `hostId`로 통일 — 초안에서 시도했으나, 그 객체가 물고 있는
    `HostSummaryResponse`는 `FestivalListItemResponse`·`FestivalRecentResponse`·
    `FestivalUpcomingResponse`와 공용이라 응답 4개가 걸린다. 백엔드도 이 이유로 안 건드림
  - 백엔드 확인까지 PR 보류 — 리뷰어가 백엔드 코드를 확인해 `id`가 맞다고 회신, 보류
    불필요
- **트레이드오프**: 검색 응답 안에서 최상위는 `hostId`, 중첩은 `id`로 필드명이 갈린다.
  다만 현재 중첩 host의 식별자를 읽는 코드가 없어 런타임 영향은 없다. 나중에 축제 검색
  결과 행에서 주최 상세로 링크를 걸 때 이 불일치를 인지해야 한다
- **후속**: 중첩 host까지 통일하려면 백엔드 응답 4개가 걸린 변경이므로 별도 백엔드
  이슈로 올린다
- ⭐ **볼트 승격 권장** — 외부 API 계약 범위에 관한 결정. `/capture`로
  `knowledge/decisions/`에 등록 (백엔드측 DEC-0154와 짝)

### 🔧 주요 변경사항 상세

#### SchoolResultRow — 리네임과 함께 고쳐진 버그

`SearchHostResponse`는 실제로 `Long hostId`를 내린다. 기존 프론트는 `host.id`를 읽고
있었으므로, 실 API 연결 시 다음이 발생했다.

- `href={/hosts/${id}}` → `/hosts/undefined`
- `gridTint(id)` → `Math.abs(undefined)` = `NaN` → `GRID_TINTS[NaN]`이 `undefined`라
  className에 `undefined`가 그대로 박힘
- `page.tsx`의 `key={host.id}` → 학교 행 전부 `undefined`

목 데이터가 우연히 `id`를 내리고 있어 에러 없이 가려져 있던 문제다.

#### 중첩 host 되돌림

축제 검색 결과 행(`FestivalResultRow`)은 중첩 `host`에서 `host.name`만 텍스트로 쓴다.
행 클릭은 `/festivals/{festivalId}`로 가고, 주최 상세로 가는 경로가 없다. 따라서 중첩
host의 식별자 필드명은 현재 아무 컴포넌트도 읽지 않으며, `id`로 되돌려도 화면·동작
변화가 없다.

**특이사항**:

- 자동완성(`GET /search/autocomplete`)은 목만 있고 프론트 소비처가 아직 없다.
  `toFestivalResult`·`toHostResult`가 자동완성 목에도 쓰이지만 되돌린 값이 그대로
  전파돼 목끼리 정합이 유지된다
