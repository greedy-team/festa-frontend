### 📌 작업 개요

사용자 화면 E2E(#115)에 이어, 로그인 없이는 접근할 수 없는 관리자 화면(로그인·가드·축제 심사)을 같은 Playwright 인프라로 커버했다. 새 인프라 추가 없이 기존 `e2e/`에 스펙만 추가했다.

### 🎯 구현 목표

- 관리자 로그인 성공/실패
- 비로그인 상태의 콘솔 접근 차단(`AdminGuard`)
- 축제 발행 성공/실패(발행 조건 미충족 케이스 포함)

### ✅ 구현 내용

#### 관리자 로그인 (`admin-login.spec.ts`)
- 잘못된 자격증명 → 에러 문구(`아이디 또는 비밀번호가 올바르지 않습니다.`) 확인. `role="alert"`가 Next.js의 route announcer(`#__next-route-announcer__`)와 겹쳐서 `p[role="alert"]`로 좁혀야 했다
- 올바른 자격증명(mock 계정 `admin`/`admin`, `src/mocks/handlers/adminAuth.ts`) → `/admin/festivals`로 이동, `축제 검수` 헤딩 확인
- 로그인 폼이 컨트롤드 인풋 + `onSubmit` 전부 클라이언트 훅에 의존하고, root layout이 `/admin/*`에도 공개 Header를 얹어 하이드레이션할 게 많다 — `festivals-sort.spec.ts`(#115)에서 겪은 것과 같은 종류의 레이스가 가능해 보여, 로그인 성공 케이스의 URL 검증에 미리 15초 타임아웃 여유를 줬다

#### 콘솔 접근 가드 (`admin-guard.spec.ts`)
- 토큰 없는 새 브라우저 컨텍스트로 `/admin/festivals` 직접 접근 → `/admin/login`으로 리다이렉트 확인 (`AdminGuard.tsx`)

#### 축제 발행 (`admin-festival-review.spec.ts`)
- 로그인 폼을 매번 거치지 않고 `page.evaluate`로 토큰(`festa.admin.accessToken`)을 직접 심어 발행 흐름에만 집중
- 발행 조건을 만족하는 축제(fixture의 festivalId 1 "아카라카 2025") 선택 → 발행 → 결과 배너(`요청 1건 중 1건 발행됨`) + 행 배지가 "발행됨"으로 바뀌는지 확인
- 발행 조건 미충족 축제(festivalId 4 "라치오스 2025", 라인업 0팀) → 발행 → 실패 배너(`1건 실패`, 축제명 포함) 확인

### 🧭 결정 기록 (ADR)

#### 발행 흐름에 별도 MSW 핸들러가 필요 없었다
- **문제**: 처음엔 관리자 축제 심사 화면도 사용자 화면처럼 MSW 핸들러를 새로 만들어야 할 거라 예상했다
- **발견**: `features/admin/festival/api.ts`는 실제로는 네트워크를 전혀 타지 않고, 모듈 스코프의 로컬 픽스처(`adminFestivalsFixture`)를 직접 읽고 쓴다. 파일에 이미 "백엔드 연결일에 이 본문이 `adminFetch` 호출로 바뀐다"는 주석이 있다 — 지금은 로그인(MSW)과 그 이후 화면(로컬 픽스처)이 서로 다른 방식으로 목이 돼 있다
- **선택**: 추가 인프라 없이 그대로 진행 — 페이지가 새로 로드될 때마다 픽스처가 초기화되므로 `page.goto`만으로 테스트 간 격리가 된다
- **트레이드오프**: ⚠️ 백엔드가 실제로 연결되는 시점에 이 픽스처가 사라진다. 그때 `admin-festival-review.spec.ts`가 실제 API를 상대로도 통과하는지 반드시 다시 확인해야 한다 — 지금은 이 사실을 주석과 이 보고서에 남겨두는 것으로 대비한다

### 🧪 테스트 및 검증

- `pnpm exec playwright test` — 사용자 화면(7) + 관리자 화면(5) 합쳐 12개 전부 통과
- `pnpm test`(유닛테스트) 40개, `pnpm exec tsc --noEmit`, `pnpm lint` 모두 통과
- CI(`FESTA-E2E.yaml`)는 이미 `develop`에 있어 이 PR만으로 별도 워크플로우 추가가 필요 없다. `main-develop-protection` 룰셋에 `E2E 테스트`가 이미 required로 걸려 있어, 이 PR도 그 게이트를 통과해야 머지된다

### 📌 참고사항

- `adminFestivalsFixture`의 festivalId 1·4는 각각 "항상 발행 가능"·"항상 발행 불가"로 고정된 값이다. 픽스처 배열이 바뀌면(순서·값 모두) 이 테스트도 같이 손봐야 한다
- 로그인 mock 계정(`admin`/`admin`)은 `src/mocks/handlers/adminAuth.ts`의 `DEV_ACCOUNT` 고정값이다
