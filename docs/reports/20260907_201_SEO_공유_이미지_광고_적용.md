### 📌 작업 개요

공개 페이지가 실제 콘텐츠에 맞는 검색 제목·설명·대표 주소를 제공하도록 SEO 기반을 정리했다. 검색엔진에 전달할 공개 URL을 사이트맵으로 구성하고 FESTA favicon과 공유 이미지를 적용했으며, 기존 광고 플레이스홀더를 실제 배너와 패널 소재로 교체했다.

### 🎯 구현 목표

- 홈·축제·학교·아티스트 페이지를 검색 결과와 링크 미리보기에서 구분
- 검색 필터와 비공개 화면을 색인 대상에서 제외
- 공개 축제·학교·아티스트 URL을 빠짐없이 사이트맵에 제공
- FESTA 브랜드 이미지와 실제 광고 소재 적용

### ✅ 구현 내용

#### 페이지별 검색·공유 메타데이터

- **파일**: `src/lib/seo.ts`, `src/lib/site.ts`, `src/app/**/page.tsx`
- **변경 내용**: 공통 `pageMetadata`와 목록용 `listingMetadata`를 추가하고 홈·축제·학교·아티스트 페이지에 제목, 설명, canonical, Open Graph, Twitter Card 정보를 연결했다.
- **이유**: 모든 화면이 같은 메타데이터를 공유하던 상태를 해소하고 검색 결과와 공유 링크가 현재 페이지의 내용을 설명하도록 했다.

축제 상세 설명에는 학교명, 축제명, 기간과 공개된 출연진 최대 6팀을 포함한다. 잘못된 상세 ID나 데이터를 불러오지 못한 화면, 내부 검색과 필터 조합은 `noindex`로 처리한다. 기본 목록의 2페이지 이상은 자체 canonical을 유지한다.

#### robots와 sitemap 구성

- **파일**: `src/app/robots.ts`, `src/app/sitemap.ts`, `next.config.ts`
- **변경 내용**: `/robots.txt`에서 사이트맵 위치를 안내하고, 축제·아티스트 API의 마지막 페이지까지 조회해 축제 상세, 학교 상세·이력, 아티스트 상세 URL을 생성한다.
- **이유**: 검색엔진이 공개 경로만 발견하도록 하고, 축제에서 반복되는 학교 URL은 `Set`으로 중복 제거하기 위해서다.

사이트맵 생성 중 API가 실패하면 일부 URL만 담긴 결과를 성공으로 반환하지 않고 오류를 발생시킨다. Vercel Preview는 전체 경로에 `X-Robots-Tag: noindex, nofollow`를 적용하고, Production에서는 showcase 경로만 같은 헤더로 제외한다.

#### FESTA 브랜드 자산 적용

- **파일**: `public/festa_symbol.png`, `public/festa-og-image.jpg`, `src/app/layout.tsx`
- **변경 내용**: 기존 favicon을 FESTA 심벌로 교체하고 1729×910 공통 공유 이미지를 공개 페이지 메타데이터에 연결했다.
- **이유**: 브라우저 탭과 링크 미리보기에서 서비스 브랜드를 일관되게 표시하기 위해서다.

favicon URL에는 현재 이미지 해시를 쿼리로 붙여 기존 브라우저 캐시와 구분했다.

#### 광고 이미지와 신청 링크 적용

- **파일**: `src/components/ui/AdSlot.tsx`, `public/ads/banner.png`, `public/ads/panel1.png`, `public/ads/panel2.png`
- **변경 내용**: 배너 슬롯에는 배너 이미지를 표시하고, 패널 슬롯은 두 소재 중 하나를 서버에서 무작위로 선택한다. 모든 광고는 같은 Google 신청 폼을 새 탭으로 연다.
- **이유**: 플레이스홀더를 실제 행사 안내로 교체하고 같은 광고 위치에서도 소재가 번갈아 노출되도록 하기 위해서다.

패널 이미지는 `object-cover`로 광고 컨테이너를 채운다. 원본이 세로형이므로 컨테이너 비율에 따라 위아래 일부가 잘릴 수 있다.

#### 회귀 검증 추가

- **파일**: `src/lib/seo.test.ts`, `src/app/sitemap.test.ts`, `src/components/ui/AdSlot.test.tsx`, `e2e/seo.spec.ts`
- **변경 내용**: 메타데이터·색인 정책·사이트맵 페이지 순회와 실패 처리·광고 랜덤 선택과 링크를 자동 검사한다. 공유 봇 User-Agent로 원본 HTML의 canonical, Open Graph, favicon, robots 응답을 확인하는 E2E 시나리오도 추가했다.
- **이유**: 검색 메타데이터는 화면 본문에서 보이지 않아 변경 중 누락되기 쉬우므로 HTML 응답과 생성 함수 양쪽에 검증 기준을 남기기 위해서다.

### 🧭 결정 기록 (ADR)

#### 검색 필터와 페이지네이션의 색인 정책 분리

검색어·장르·연도·비기본 정렬이 포함된 조합은 중복 페이지가 급격히 늘어나므로 `noindex` 처리했다. 페이지 번호만 다른 기본 목록은 서로 다른 콘텐츠 묶음이므로 각 페이지의 canonical을 유지했다.

⭐ 볼트 승격 권장 — 새로운 목록 화면과 필터가 추가될 때 동일한 색인 기준을 적용해야 한다.

#### 사이트맵의 부분 성공 금지

API 오류를 빈 목록으로 바꾸면 이미 공개된 URL이 사이트맵에서 조용히 사라진다. 생성 실패를 드러내 재시도할 수 있도록 중간 API 오류는 예외로 처리했다.

#### 광고 패널의 서버 선택과 채우기 방식

패널 소재 선택은 서버 컴포넌트에서 `randomInt`로 처리해 별도 클라이언트 상태를 만들지 않았다. 컨테이너 안의 여백을 없애기 위해 `object-cover`를 사용했고, 세로 원본 일부가 잘리는 점을 허용했다.
