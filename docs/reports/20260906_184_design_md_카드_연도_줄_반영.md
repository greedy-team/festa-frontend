### 📌 작업 개요

#182에서 축제 전체 목록 카드와 홈 최근 등록 카드가 네 줄(학교명 / 축제명 / 연도 / 기간)이 됐는데 DESIGN.md의 두 컴포넌트 스펙은 세 줄로 남아 있었다. 문서를 코드에 맞추고, 연도를 목록 카드에만 두는 판단의 근거를 문서에 남겼다.

코드 변경 0건. 문서 한 파일만 고쳤다.

### 🎯 구현 목표

- 두 카드 스펙과 홈 구조 절의 구성 나열을 네 줄로 맞춘다
- 연도가 목록 카드에만 있는 이유를 문서에 남겨, 다음 사람이 히어로에 연도를 넣거나 목록의 연도를 군더더기로 보고 지우지 않게 한다
- 피그마 실측값을 코드에서 잰 값으로 덮지 않는다

- **이유**: 기존 세 줄의 y좌표(y1456·y1476·y1504)와 카드 하단(y1519)은 연도 줄이 없던 시점의 시안 실측값이다. 값을 지우면 실측 기록이 사라지고, 새 값을 지어내면 문서 규칙을 어긴다. 값은 그대로 두고 어느 시점 것인지만 밝혔다

- **이유**: 이 두 줄이 컴포넌트를 만들 때 실제로 읽히는 자리다. 크기 표기를 그대로 두면 네 줄 구성에 세 줄 높이가 붙어 있는 것으로 읽히므로 출처를 밝혔다

- **이유**: 컴포넌트 스펙만 고치면 "왜 여기만 연도가 있나"의 답이 문서에 없다. 규칙 목록은 새 화면을 만들 때 훑는 자리라 판정 기준을 여기 둔다

- **이유**: 표기만 하고 두면 잊힌다. 이 문서는 nav/footer 미반영을 이미 같은 방식으로 관리하고 있어 그 관례를 따랐다

### 🧭 결정 기록 (ADR)

#### 카드 높이를 코드에서 재서 문서에 넣지 않는다

- **문제**: 줄이 하나 늘어 실제 렌더 높이가 커졌다. `{component.recent-card}`(236×379)와 `{component.festival-card}`(236×400)가 현재 화면과 맞지 않는다
- **선택**: 치수는 그대로 두고 "연도 줄 추가 전 시안 실측값"임을 표기한 뒤, 피그마 반영을 반영 대기 항목으로 등록
- **대안**:
  - 코드에서 잰 높이로 교체 — DESIGN.md Iteration Guide 8(치수는 반드시 Figma 실측값, 추정값 금지)을 어긴다. 더 나쁜 것은 문서 안에서 값의 출처가 섞인다는 점이다. 나머지 좌표는 전부 피그마 기준인데 이 둘만 브라우저 기준이 되면 다음 사람이 어느 쪽을 믿을지 알 수 없다
  - 치수를 지우고 "가변"으로 표기 — 실측 기록이 사라진다. 피그마와 대조할 근거가 없어진다
- **트레이드오프**: 문서가 당분간 코드와 다른 높이를 적어 둔다. 표기와 반영 대기 항목이 그 간극을 가리키지만, 읽는 사람이 그 문장을 지나치면 옛 높이를 그대로 쓴다

### 🔧 주요 변경사항 상세

#### 손대지 않은 자리

상단 `components:` YAML 블록의 `size:` 값은 무수정이다. Iteration Guide 1이 "산문의 수치와 상단 YAML이 어긋나면 YAML이 정본"이라고 정하므로, 산문의 크기 표기도 YAML과 같은 값을 유지한 채 주석만 붙였다.

홈 06-D 구조의 ASCII 좌표 지도(`1456 │ Host / Name / Date`)도 그대로 뒀다. 그것은 피그마 프레임을 옮긴 지도라, 좌표가 없는 항목을 끼워 넣으면 실측 지도에 없는 값을 그리게 된다. 바로 아래 절의 인용문과 반영 대기 항목이 이 지도가 옛 구성임을 가리킨다.

**특이사항**:
- 앵커 링크 3개를 새로 달면서 문서의 기존 관례(`[컴포넌트 시트](#컴포넌트-시트)`)에 맞춰 라벨과 대상 섹션 이름을 일치시켰다
