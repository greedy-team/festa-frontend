### 📌 작업 개요

축제 목록에서 필터 조합 결과가 0건일 때 정상적인 빈 상태 대신 에러 화면이 뜨는 버그(#119)를 수정했다. API가 `totalPages: 0`을 내려주는 정상 응답인데, 프론트가 이를 "존재하지 않는 페이지"로 오판해 잘못된 페이지를 재요청하다 에러로 빠지는 구조적 문제였다.

### 🎯 구현 목표

- 필터 결과 0건 시 빈 상태 UI가 뜨는지 확인하는 회귀 테스트 작성
- 원인이 되는 페이지네이션 경계 조건 수정

### ✅ 구현 내용

- **원인**: 목록 페이지가 `page >= totalPages`일 때 마지막 페이지로 리다이렉트하는 로직을 갖고 있었는데, `totalPages: 0`(결과 0건)인 경우도 이 조건에 걸려 `page: -1`로 재요청하는 경로를 탔다. `page=-1`은 API 스펙상 유효하지 않은 값이라 `INVALID_PAGE` 에러가 났고, 그게 그대로 에러 바운더리로 올라갔다
- **수정**: 리다이렉트 조건에 `totalPages > 0` 가드를 추가 — 결과 0건은 "존재하지 않는 페이지로 잘못 이동한 것"이 아니라 "정상적으로 빈 목록"이므로 리다이렉트 대상에서 제외
- 관련 페이지의 빈 상태 UI(필터 조건에 맞는 축제가 없다는 안내)는 이미 존재했고, 도달하지 못했을 뿐이라 별도 UI 작업은 없었다

### 🧪 테스트 및 검증

- 결과 0건이 되는 필터 조합(존재하지 않는 연도 등)으로 요청 시 에러 화면이 아니라 빈 상태 UI가 렌더되는지 확인하는 테스트 추가, `pnpm test` 통과
- `pnpm exec tsc --noEmit`, `pnpm lint` 통과

### 📌 참고사항

- 팀 내부에서 실사용 중 리포트된 버그를 이슈화(#119)해 처리한 케이스 — 재현 조건(연도 필터 등으로 결과 0건 유도)을 이슈 본문에 함께 남겼다
