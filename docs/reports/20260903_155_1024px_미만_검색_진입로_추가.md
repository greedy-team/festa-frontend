### 📌 작업 개요

lg(1024px) 미만에서 통합 검색 화면에 도달할 방법이 없던 문제를 고쳤다. 헤더 검색 폼이 `hidden lg:block`이라 좁은 폭에서 렌더되지 않는데, 그 자리를 대신할 진입 요소가 없어 주소창에 `/search`를 직접 입력해야만 갈 수 있었다.

### 🔍 문제 분석

헤더의 브레이크포인트가 두 개(`sm` 640 / `lg` 1024)라 폭 구간이 셋으로 갈리는데, 검색은 마지막 구간에만 있었다.

| 폭 | nav 링크 | 햄버거 | 검색 |
|---|---|---|---|
| < 640px | 없음 | 있음 | **없음** |
| 640 ~ 1023px | 있음 (`sm:flex`) | 없음 (`sm:hidden`) | **없음** |
| ≥ 1024px | 있음 | 없음 | 있음 |

중간 구간(640~1023px)에는 햄버거 자체가 없다. 그래서 "드롭다운에 검색을 넣는다"는 해법만으로는 이 구간이 덮이지 않는다 — 구간별로 다른 수단이 필요했다.

### ✅ 구현 내용

#### 640px 미만 — 햄버거 드롭다운에 검색 입력

- **파일**: `src/components/layout/Header.tsx`
- **변경 내용**: 드롭다운 상단, nav 링크 위에 `NavSearchForm`을 `fullWidth`로 배치했다.
- **이유**: 이미 열려 있는 패널이라 입력을 놓을 자리가 있다. 아이콘으로 `/search`에 보내는 것보다 바로 타이핑할 수 있어 한 단계 짧다. GET 폼이라 JS 없이도 제출되고, 제출하면 라우트가 바뀌어 `useRouteResetState`가 드롭다운을 닫는다.

#### 640~1023px — 헤더에 검색 아이콘

- **파일**: `src/components/layout/Header.tsx`
- **변경 내용**: `hidden sm:flex lg:hidden` 조건으로 `size-[44px]` 검색 아이콘 링크를 우측 클러스터에 추가했다. 히어로 위에서는 햄버거와 같은 `solid` 분기로 흰색이 된다.
- **이유**: 이 구간엔 열 메뉴가 없어 드롭다운 방식이 통하지 않는다. nav 링크는 이 폭에서 가로로 잘 들어가므로 그대로 두고, 검색만 아이콘으로 얹었다. 44px는 DESIGN.md 「Touch Targets」의 모바일 하한이다. 히어로 위 인디고 금지(DESIGN.md Don'ts)도 지켰다.

#### `NavSearchForm`에 `fullWidth` 옵션 추가

- **파일**: `src/components/layout/NavSearchForm.tsx`
- **변경 내용**: `fullWidth` prop을 두어 `w-full`과 `w-[280px] max-w-full`을 분기한다.
- **이유**: 드롭다운에서는 폭을 부모에 맞춰야 하는데, `className`으로 `w-full`을 넘기면 컴포넌트에 박힌 `w-[280px]`와 같은 width 유틸이라 어느 쪽이 이길지 클래스 문자열 순서가 정하지 않는다(생성된 CSS 순서가 정한다). 같은 파일의 기존 주석이 이미 경고하던 함정이라 분기를 명시적으로 뒀다.

#### 폭 구간별 진입로 회귀 테스트

- **파일**: `e2e/header-search-entry.spec.ts` (신규)
- **변경 내용**: 390 / 768 / 1280px 세 뷰포트에서 각자의 수단(드롭다운 검색창 / 아이콘 / 헤더 폼)으로 실제 `/search`까지 가는지 검증한다.
- **이유**: 구간마다 진입 수단이 달라 한 구간이 조용히 뚫려도 다른 구간 테스트는 초록으로 남는다. 데이터 값이 아니라 "어느 폭에서든 도달 가능하다"는 구조만 본다(DEC-0134).

### 🧭 결정 기록 (ADR)

#### 구간별로 다른 진입 수단을 쓴다

- **문제**: `lg` 미만이 한 덩어리가 아니라 640을 경계로 성격이 갈린다. 한 가지 수단으로 덮으려면 브레이크포인트를 재편해야 했다.
- **선택**: 640px 미만은 드롭다운 검색 입력, 640~1023px는 검색 아이콘. nav 링크의 `sm:flex`는 건드리지 않는다.
- **대안**:
  - 햄버거를 `lg:hidden`으로 넓혀 드롭다운 하나로 통일 — 브레이크포인트가 `lg` 하나로 단순해지지만, 768px에서 지금 가로로 보이는 nav 링크가 햄버거 안으로 들어간다. 자리가 충분한데 접는 건 후퇴다.
  - `lg` 미만 전 구간에 아이콘만 — 코드는 가장 작지만, 모바일에서 바로 타이핑하지 못하고 `/search`를 한 번 거친다.
- **트레이드오프**: 인접한 두 폭에서 진입 방식이 달라진다(640px 경계). 분기 코드가 한 줄 늘고, 회귀 테스트도 구간별로 따로 필요하다.

### 📌 참고사항

- 푸터에는 검색 링크를 넣지 않았다. 헤더에서 모든 폭이 덮이므로 중복이다.
- DESIGN.md 「Responsive Behavior > 미정의 영역」의 "nav 햄버거 전환"은 여전히 미정의다. 이번 변경은 검색 진입로만 메운 것이고, 모바일 nav 전반의 설계는 그대로 열려 있다.
