# .claude 커맨드 정리 및 프로젝트 규칙 정합화

### 📌 작업 개요

`npx projectops`가 넣은 `.claude/commands/` 커맨드 31개를 이 프로젝트에서 실제로 쓰는 7개로 줄이고, 남는 커맨드를 현재 이슈·브랜치·커밋·PR 규칙에 맞췄다. 작업 도중 커밋 메시지 형식이 두 번 바뀌었고, 봇 설정 파서에서 버그를 하나 발견해 함께 고쳤다.

**보고서 파일**: `.report/20260803_17_claude_커맨드_정리_및_프로젝트_규칙_정합화.md`

### 🎯 구현 목표

- 이 프로젝트(Next.js + Vercel)에서 쓰지 않거나 오작동하는 커맨드 제거
- 남는 커맨드를 브랜치·커밋·PR 규칙에 정합
- `/report`에 결정 기록(ADR) 섹션 추가

### ✅ 구현 내용

#### 커맨드 31개 → 7개

- **파일**: `.claude/commands/` (24개 삭제)
- **변경 내용**: `review-flutter` `suh-spring-test` `figma` `release-note`(타 스택 전제), `build` `test` `testcase` `document` `ppt` `init-worktree`(CI·미사용과 중복), `plan` `analyze` `design` 등 8개(Superpowers와 역할 중복), `review*` 5개(하네스 내장 리뷰와 중복), `index`(427줄 라우터) 제거
- **이유**: Flutter·Spring 전제 커맨드는 이 레포에서 잘못된 지시를 내린다. 나머지는 CI·하네스·Superpowers가 이미 담당한다

#### 이슈 번호·타입 추출 규칙 교체

- **파일**: `commit.md` `issue-branch.md` `pr-description.md` `rp.md` `cr.md`
- **변경 내용**: `/#(\d+)/` → `^(feat|fix|refactor|chore|docs)_[0-9]+_`
- **이유**: 브랜치 형식이 `YYYYMMDD_#번호_`에서 `타입_번호_슬러그`로 바뀌어 기존 정규식이 **전혀 매칭되지 않는 상태**였다. 새 정규식은 번호와 함께 타입까지 얻어, 커밋 메시지의 타입 자리를 이슈 재조회 없이 채운다

#### 커밋 메시지 형식

- **파일**: `version.yml`, `commit.md`, `issue-branch.md`, `cr.md`, `TEAM-CONVENTIONS.md`
- **변경 내용**: `${issueTitle} : ${commitType} : {설명} ${issueUrl}` → `${commitType} : {설명} #${issueNumber}`
- **이유**: 이슈 제목이 브랜치 슬러그와 사실상 같아 커밋 제목이 같은 내용을 두 번 말했다. 이슈 참조는 URL이 아니라 `#번호`여야 타임라인 연결이 생긴다(아래 ADR 참조)

#### `/issue` 를 실제 템플릿 5종에 정합

- **파일**: `issue.md`
- **변경 내용**: 삭제된 디자인·시험요청 템플릿 참조 제거, 리팩토링·설정·문서 추가. 제목은 프리필과 같은 형식, 한글 허용. `type:` 라벨 자동 지정
- **이유**: 존재하지 않는 템플릿을 안내하고 있었다. 담당자 블록 등 세부는 `.github/ISSUE_TEMPLATE/` 실제 파일을 기준으로 맞췄다

#### `/report` 결정 기록(ADR) 섹션

- **파일**: `report.md`
- **변경 내용**: `### 🧭 결정 기록 (ADR)` 섹션과 작성 규칙, 볼트 승격 판단 기준 3가지 추가
- **이유**: 코드만 봐서는 왜 그렇게 했는지 알 수 없는 선택을 남기기 위함

#### 봇 설정 파서 버그 수정

- **파일**: `.github/scripts/issue_helper.py` (백엔드 레포에도 동일 반영)
- **변경 내용**: `_strip_inline_comment()` 추가 — 따옴표 밖의 ` #...`만 주석으로 제거
- **이유**: 기존 `re.sub(r"\s+#.*$", "", ...)`가 따옴표를 무시해서, `"... #${issueNumber}"` 값이 통째로 잘렸다

### 🧭 결정 기록 (ADR)

#### 브랜치 슬러그에 한글 허용

- **문제**: 슬러그에서 한글을 버리면 `로그인 시 500 에러` → `fix_31_500` 처럼 의미 없는 브랜치명이 된다
- **선택**: 한글·영문소문자·숫자를 `_`로 이어 한글을 그대로 남긴다
- **대안**: 영문 강제 — 팀이 한글로 이슈를 쓰는데 제목마다 영문 요약을 덧붙여야 한다
- **근거를 뒤집은 과정**: "한글 브랜치명은 PR 생성 시 `422 Validation Failed`"라는 2차 정보로 한글을 배제했으나, 실측 결과 push·REST API PR 생성·Actions·`gh` CLI 모두 정상이었다. 그 422는 Windows PowerShell `ConvertTo-Json` 인코딩 버그로 보이며 우리 경로에는 해당 없다
- **트레이드오프**: 한글은 UTF-8 3바이트라 100자 제한만으로는 느슨한 ref 파일명 한계(255B)를 못 막는다 → `MAX_REF_BYTES=200` 바이트 상한을 추가했다
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### 커밋의 이슈 참조를 URL이 아닌 `#번호`로

- **문제**: 이슈 타임라인에 커밋이 하나도 안 잡혔다. Development 섹션도 비어 있었다
- **선택**: 커밋 메시지 끝을 `#<이슈번호>`로 통일
- **대안**: 전체 URL 유지 — 화면에는 `#17`로 렌더링되지만 `referenced` 이벤트가 생기지 않는다
- **검증**: 같은 projectops 템플릿을 쓰는 `eodaego-FE#20`은 커밋 원문이 `#20`이라 15개 커밋이 모두 잡혀 있었다. 형식 교체 후 이슈 #17에 `referenced` 13건 생성 확인
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### PR 본문에서 `Closes #N` 제거

- **문제**: `Closes #N`이 자동 종료를 만들지 않는데 "닫힐 것"이라는 착각을 준다
- **선택**: `관련 이슈: #N` 표기 + `작업완료` 라벨 후 수동 종료
- **대안**: `Closes` 유지 — Development 섹션 연결은 얻지만 자동 종료는 여전히 안 된다
- **근거**: 작업 PR은 `develop`으로 머지되는데 GitHub closing keyword는 기본 브랜치(`main`) 머지에서만 동작한다. 릴리스 PR 본문은 RELEASE-CHANGELOG가 CHANGELOG로 덮어써 키워드가 `main`에 도달하지 못한다. 실제 PR 머지로 확인
- **트레이드오프**: Development 섹션 자동 연결을 포기했다. 필요하면 사이드바에서 수동 연결
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### 브랜치 타입 소스를 `type:` 라벨로

- **문제**: GitHub 네이티브 이슈 타입은 org owner만 만들 수 있는데 이 계정은 org member다. `Refactor`/`Chore`/`Docs` 타입을 추가할 수 없다
- **선택**: `type: fix` 같은 라벨을 1차 소스로 삼는다. 추론 순서는 `이슈 타입 → type: 라벨 → 제목 [태그] → feat + 경고`
- **대안**: org owner에게 요청 후 대기 — 일정이 남의 손에 달린다
- **트레이드오프**: 나중에 owner가 이슈 타입을 만들면 그쪽이 자동으로 우선한다. 코드 수정은 필요 없다

#### 볼트 등록은 `/report`가 하지 않음

- **문제**: ADR을 어디에 남길지 — 보고서 안, 레포 로컬 `docs/adr/`, 또는 상위 레포의 지식 볼트
- **선택**: 보고서에 기록하고 승격 후보만 표시. 실제 등록은 `/capture`
- **대안**: `/report`가 볼트에 직접 쓰기 — 크로스 레포 쓰기·`DEC-NNNN` 번호 부여·충돌 감지를 떠안게 되고, 볼트 워크플로우와 이중화된다

### 🔧 주요 변경사항 상세

#### `issue_helper.py` — `_strip_inline_comment()`

값이 따옴표로 시작하면 짝이 되는 닫는 따옴표까지만 취하고, 아니면 기존처럼 ` #` 이후를 자른다. `version.yml`에 `#`를 포함한 값을 넣는 순간 터지던 자리다.

**특이사항**:
- 이 스크립트는 `npx projectops` 업데이트 시 덮어써진다. 커밋 템플릿을 스크립트 기본값이 아니라 `version.yml`에 둔 것도 같은 이유다
- 백엔드 레포(`festa-backend`)에도 같은 수정을 복사했다

#### 커밋 히스토리 재작성

형식이 두 번 바뀌어 브랜치 커밋을 두 차례 재작성했다. 매번 백업 브랜치를 만들고 **최종 트리 해시를 대조**해 내용 손실이 없음을 확인했다.

**특이사항**:
- 1차 재작성 때 `git cherry-pick -q`(존재하지 않는 플래그)를 써서 커밋이 리셋됐다. SHA를 미리 저장해둔 덕에 전량 복구했다
- 정규식 일괄 치환이 마크다운 테이블의 앞 컬럼까지 삼킨 적이 있어 원본과 대조해 복구했다

### 📌 참고사항

- PR 제목 형식과 커밋 형식의 표기 스타일 상이
