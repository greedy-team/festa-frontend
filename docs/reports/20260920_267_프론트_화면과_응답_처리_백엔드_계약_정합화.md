### 📌 작업 개요

관리자 아티스트·축제 화면과 공개 화면의 응답 처리를 현재 백엔드 계약과 확정 정책에 맞췄다. 아티스트 검수 필요 UI를 제거하고, 축제 폼에서 모든 주최를 선택할 수 있게 했으며, null 가능 필드가 화면에 잘못 노출되지 않도록 정리했다.

모바일에서는 홈 D-day와 축제·아티스트 목록 제목의 크기를 낮춰 작은 화면에서 시각적 비중과 가로 여백을 조정했다.

### 🔍 문제 분석

- 아티스트 관리 화면에 더 이상 사용하지 않는 `needsReview` 필터·표시·입력 필드가 남아 있었다.
- 축제 등록·수정 폼이 주최 목록 첫 50개만 조회해 이후 주최를 선택할 수 없었다.
- 장소명과 주최 약칭은 백엔드에서 null일 수 있지만 프론트 타입과 표시 로직이 이를 반영하지 않아 `null` 문자열이나 빈 구분자가 노출될 수 있었다.
- 발행 취소 응답은 `publishedAt: null`을 반환하지만 프론트 응답 타입은 문자열만 허용했다.
- 모바일에서 D-day와 목록 제목이 데스크톱과 같은 크기로 보여 화면을 과도하게 차지했다.

- **파일**: `src/features/admin/artist/types.ts`, `src/features/admin/artist/api.ts`
- **변경 내용**: 목록 파라미터, 응답 타입, 등록·수정 폼 값과 병합 결과에서 `needsReview`를 제거했다.
- **파일**: `src/features/admin/artist/components/ArtistAdminScreen.tsx`, `src/features/admin/artist/components/ArtistFormDialog.tsx`
- **변경 내용**: 검수 필요 필터, 테이블 표시, 모바일 표시와 폼 체크박스를 제거했다.
- **이유**: 검수 필요 표시를 없애기로 한 정책과 화면·요청 계약을 일치시키기 위해서다.

#### 축제 폼의 전체 주최 조회

- **파일**: `src/features/admin/host/api.ts`, `src/features/admin/host/queries.ts`
- **변경 내용**: 서버 페이지 크기 상한인 50개를 유지하면서 `hasNext`가 없을 때까지 모든 페이지를 순차 조회하는 `getAllHosts`와 전용 쿼리를 추가했다.
- **파일**: `src/features/admin/festival/components/FestivalFormDialog.tsx`
- **변경 내용**: 전체 주최 조회 결과를 선택지로 사용하고, 조회 중 안내와 실패 안내·재시도 버튼을 표시한다. 수정 중인 축제의 현재 주최는 목록 조회 전이나 누락된 경우에도 선택 상태를 유지한다.
- **이유**: 주최가 51개 이상이어도 모든 주최를 선택할 수 있고, 일부 페이지만 읽은 결과를 완전한 목록처럼 보여주지 않기 위해서다.

#### nullable 응답과 화면 표시 정합화

- **파일**: `src/features/home/types.ts`, `src/features/artists/types.ts`, `src/features/hosts/types.ts`
- **변경 내용**: `venueName`, `hostShortName`, `shortName`을 `string | null`로 정의했다.
- **파일**: `src/features/home/components/HeroPanel.tsx`
- **변경 내용**: 장소명이 없으면 장소 문단 자체를 렌더링하지 않는다.
- **파일**: `src/features/artists/components/ArtistRow.tsx`, `src/features/artists/components/UpcomingShowCard.tsx`, `src/features/hosts/components/HostHero.tsx`
- **변경 내용**: 존재하는 값만 조합해 `null` 문자열과 불필요한 구분자가 표시되지 않게 했다.
- **파일**: `src/features/admin/festival/types.ts`
- **변경 내용**: 발행·발행 취소 공통 응답의 `publishedAt`을 `string | null`로 수정했다.
- **이유**: 프론트 타입과 렌더링을 실제 백엔드 응답 범위에 맞추기 위해서다.

#### 모바일 타이포 크기 조정

- **파일**: `src/app/globals.css`, `src/features/home/components/HeroPanel.tsx`
- **변경 내용**: 모바일 D-day에 36px 제목 토큰을 사용하고 `sm` 이상에서는 기존 56px을 유지했다.
- **파일**: `src/app/festivals/page.tsx`, `src/app/artists/page.tsx`
- **변경 내용**: 모바일 목록 제목을 26px로 낮추고 `sm` 이상에서는 기존 48px을 유지했다.
- **이유**: 작은 화면에서 큰 제목이 콘텐츠를 과도하게 밀어내는 문제를 줄이면서 넓은 화면의 기존 위계를 보존하기 위해서다.

### 📌 참고사항

- 주최 전체 조회는 관리자가 축제 폼을 열 때만 실행되며, 서버가 제공하는 페이지 크기 상한 50개를 따른다.
- `needsReview`를 포함한 이전 아티스트 응답이 들어와도 프론트는 해당 값을 사용하거나 화면에 표시하지 않는다.
