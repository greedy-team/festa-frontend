### 📌 작업 개요

운영 홈 화면의 Lighthouse 결과를 데스크톱·모바일로 저장하고, 진단에서 실제로 달라진
항목을 비교했다. 사용자 행동 분석은 GA4와 Microsoft Clarity를 선택했지만, 분석 동의와
수집 범위 검증 전에는 운영 요청이 발생하지 않도록 연결 기반만 준비했다.

### 🎯 구현 목표

- Lighthouse 원본 JSON과 결과 화면을 저장해 개선 전·후 비교 근거 확보
- 성능 개선 대상과 선정 이유, 목표 지표의 근거 문서화
- 공개 정보 탐색 화면만 허용하는 GA4·Clarity 연결 기반 구현
- 동의 전, 관리자·정책·테스트 화면에서 분석 스크립트가 로드되지 않도록 차단

### ✅ Lighthouse 분석 결과

동일한 운영 홈을 대상으로 저장된 결과는 다음과 같다. Lighthouse 점수는 실행 환경에 따라
변동하므로 한 번의 총점만으로 개선을 주장하지 않고, 진단 항목과 핵심 지표를 함께 비교한다.

| 기기 | 측정 | 성능 | 접근성 | 권장사항 | SEO | FCP | LCP | TBT | CLS |

권장사항은 데스크톱과 모바일 모두 77에서 100으로 올랐다. 최초 보고서에 포함된
브라우저 확장 프로그램의 서드파티 쿠키와 DevTools 문제 진단이 확장 프로그램을 제외한
측정에서 사라진 결과다. 애플리케이션 코드 변경으로 성능이 개선된 결과로 해석하지 않는다.
성능 점수는 데스크톱 98에서 97, 모바일 77에서 77로 유의미하게 좋아지지 않았다.

모바일 LCP가 약 6.3초로 가장 큰 병목이므로 다음 성능 작업의 1순위로 선정한다. 사용자가
첫 화면의 대표 축제 정보를 늦게 보게 되는 지표이고, 양호 기준인 2.5초 이하를 목표로 삼는다.
데스크톱 LCP는 이미 1.3초 이하이며 TBT와 CLS도 양호해 우선순위를 낮춘다. 목표는
모바일 성능 90 이상, LCP 2.5초 이하를 같은 조건에서 여러 번 측정해 중앙값으로 확인하는 것이다.

### ✅ 사용자 행동 분석 연결 기반

- **파일**: `src/lib/analytics.ts`
- **변경 내용**: 홈, 축제·아티스트 목록과 상세, 학교 상세·이력, 검색 화면만 고정 분류한다.
  쿼리·해시를 제외한 경로와 고정 제목만 전송하며 referrer는 origin만 남긴다.
- **이유**: 축제 탐색 흐름에 필요한 화면만 분석하고 검색어, 토큰, 임의 문자열 ID가 분석
  서비스로 전달되는 범위를 줄이기 위해서다.

- **파일**: `src/components/analytics/Analytics.tsx`
- **변경 내용**: 기존 `next/script`로 GA4 수동 `page_view`와 Clarity 로더를 구성했다.
  Production, 유효한 공개 ID, 수집 허용 화면, 분석 동의가 모두 참일 때만 렌더한다.
- **이유**: 별도 SDK나 GTM을 추가하지 않고 현재 요구에 필요한 최소 연결만 제공한다.

- **파일**: `src/app/layout.tsx`
- **변경 내용**: 공통 레이아웃에서 분석 컴포넌트를 연결하되 `consentGranted={false}`로 둔다.
- **이유**: Vercel 환경변수가 등록돼도 동의 기능이 완성되기 전에는 실제 방문을 수집하지
  않는 배포 차단 장치다. 공개 화면의 동작 변화는 없다.

GA4는 유입·화면 이동 같은 정량 흐름을, Clarity는 클릭·스크롤·세션 재생 같은 정성 행동을
확인하는 용도로 나눈다. Hotjar/Contentsquare도 재생과 히트맵을 제공하지만, 현재 필요한
기능은 Clarity로 충족되고 별도 유료 기능이나 설문이 필요하지 않아 도구 수와 비용을 늘리지 않았다.
화면별 수집 이유와 활성화 전 검증 조건은 `docs/adr/20260916_220_analytics_scope.md`에 기록했다.

### 🧭 결정 기록

실제 수집 활성화는 #233으로 분리했다. 방문 또는 계속 이용을 분석 동의로 간주하지 않고,
명시적 동의·거부·철회와 개인정보 처리방침을 연결한 뒤 GA4 DebugView와 Clarity에서 전송
범위를 확인한다. `select_content`, `search_results_view`, `official_link_click` 이벤트와
수집 데이터 기반 UX 개선도 #233에서 이어서 수행한다.

네이버 `robots.txt`는 운영 주소에서 HTTP 200, 전체 크롤러 허용, sitemap 응답을 확인했고
현재 `src/app/robots.ts`가 같은 내용을 생성한다. 중복 정적 파일은 추가하지 않았다.
서치어드바이저의 과거 진단은 배포 후 재수집으로 확인한다.
