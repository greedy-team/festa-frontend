### 📌 작업 개요

GA4와 Microsoft Clarity를 방문자의 선택 이후에만 실행하도록 연결하고, 두 도구를 따로
허용하거나 거부·철회할 수 있는 화면을 추가했다. 분석이 비활성인 배포에서는 동의 화면과
설정 버튼 자체를 렌더하지 않아, 미완성 고지에 대한 선택이 나중 수집 동의로 재사용되지 않는다.

이번 작업은 코드 연결과 로컬 전송 검증까지 완료했다. 운영자명·문의처·보관기간·국외 이전
고지가 확정되지 않았으므로 운영 수집 스위치는 계속 꺼 둔다. 운영 데이터 기반 UX 개선은
데이터가 쌓이기 전에는 결과를 만들 수 없으므로 완료로 처리하지 않는다.

### 🎯 구현 목표와 선정 이유

| 대상 | 구현 | 선정 이유 |
| --- | --- | --- |
| 동의 상태 | GA4·Clarity 개별 선택, 거부, 철회, 브라우저 저장 | 두 도구의 목적이 다르며 선택 분석을 거부해도 축제 정보 열람은 유지해야 함 |
| 수집 화면 | 홈·축제·아티스트·학교의 공개 탐색 화면 | 공개 축제 탐색 개선이라는 분석 질문에 직접 필요한 범위 |
| 제외 화면 | 관리자·로그인·정책·showcase·검색의 Clarity 녹화 | 인증·고지 화면은 행동 분석 대상이 아니며 검색 URL에는 검색어가 포함될 수 있음 |
| 행동 이벤트 | `page_view`, `search_results_view`, `select_content`, `official_link_click` | 방문→검색 결과→상세 선택→공식 정보 이동의 최소 탐색 흐름을 수치로 확인하기 위함 |
| Clarity | 전체 body 마스킹과 허용 URL 검사 | DOM 마스킹만으로 URL 원문까지 보호되지는 않으므로 두 경계를 함께 검증해야 함 |
| 철회 | 쿠키 정리 후 문서 새로고침 | 내려받는 중인 외부 태그까지 중단하려면 현재 문서의 실행 수명을 끝내야 함 |

Clarity는 Hotjar/Contentsquare와 마찬가지로 히트맵과 세션 재생을 제공한다. 현재 과제는
설문보다 클릭·스크롤·탐색 장면 확인이 우선이고 Clarity가 이를 무료로 제공하므로 선택했다.
GA4는 정량 흐름, Clarity는 이용 장면을 담당한다. 정기 설문이 필요해지면 경쟁 도구를 다시
검토한다. 성능 우위는 선택 근거로 사용하지 않았다.

### ✅ 주요 동작

- 첫 방문에는 두 분석 항목이 모두 꺼져 있고, 선택 없이 거부해도 서비스를 계속 이용한다.
- 푸터의 `분석 설정`에서 선택을 바꾸며, 철회하면 GA4·Clarity 쿠키와 실행 중인 태그를 정리한다.
- 다른 탭에서 철회해도 기존 탭이 저장소 변경을 수신해 분석 문서를 종료한다.
- 공개 화면 간 이동은 SPA를 유지한다. 이미 태그가 실행된 뒤 제외 화면으로 이동할 때만 새
  문서로 탐색해 SDK가 남지 않게 한다.
- GA4의 페이지 URL은 쿼리·해시 없이 고정 경로와 화면 분류만 사용한다. 검색 이벤트는
  결과 개수와 분류만 보내며 검색어 원문은 보내지 않는다.
- Clarity는 검색, 쿼리·해시가 있는 URL, 민감한 이전 URL에서 로드하지 않는다.
- `ANALYTICS_ENABLED=true`, Vercel Production, 모킹 비활성 조건을 모두 충족해야 동의 UI와
  태그 연결이 나타난다.

### 🧪 실제 전송 검증

가짜 GA 측정 ID와 실제 SDK를 사용하는 로컬 프로덕션 빌드에서 수집 요청을 가로챘다.
검색→축제 82 상세→공식 홈페이지 클릭 시 다음 이벤트가 확인됐다.

| 이벤트 | 확인한 매개변수 |
| --- | --- |
| `page_view` | `/search`, `/festivals/82` |
| `search_results_view` | `result_count=4`, `search_type=ALL` |
| `select_content` | `content_type=festival_detail`, `item_id=82` |
| `official_link_click` | `link_type=homepage` |

GA 요청 URL과 본문에는 테스트 검색어와 쿼리 원문이 없었다. Clarity의 gzip JSON을 풀어
검사 대상 DOM 노드가 실제 페이로드에 포함된 것을 먼저 확인한 다음, 본문·링크 주소·title·
aria-label·검색 입력에 넣은 테스트 문자열이 전송되지 않은 것을 확인했다.

### 📊 분석 태그 부하 Lighthouse 비교

같은 소스와 로컬 프로덕션 서버를 대상으로 모바일 Lighthouse 12.8.2를 각 5회 실행했다.
비활성은 태그와 동의 UI가 없는 상태, 활성은 저장된 전체 동의로 GA·Clarity 태그와 Clarity
SDK가 실제로 내려온 상태다. GA는 테스트 측정 ID를 사용했다. 아래 값은 5회 중앙값이다.

| 조건 | Performance | FCP | LCP | TBT | CLS | Speed Index |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 분석 비활성 | 80 | 3.159초 | 4.138초 | 5ms | 0 | 3.159초 |
| 분석 활성 | 82 | 3.158초 | 3.835초 | 4.5ms | 0 | 3.158초 |
| 차이(활성-비활성) | +2 | -0.002초 | -0.303초 | -0.5ms | 0 | -0.002초 |

활성 조건의 네트워크 기록에서 `googletagmanager.com`, `clarity.ms/tag`, Clarity 0.8.69 SDK를
확인했다. 지표 악화는 관찰되지 않았다. 활성 LCP가 더 짧은 결과는 태그가 성능을 개선했다는
뜻이 아니며, 5회 합성 측정의 실행 변동으로 해석한다. 운영 화면의 기존 모바일 LCP 목표
2.5초 이하는 여전히 달성하지 못했다.

원본 JSON은 `docs/analyzes/analytics-tag-cost/`의 `festa-lh-off-1..5.json`과
`festa-lh-on-1..5.json`에 저장했다. 측정 중 Clarity 실제 프로젝트 ID를 사용해 localhost
세션이 프로젝트에 최대 5건 보일 수 있으며, 운영 이용자 데이터가 아니다.

### 📌 운영 활성화 전 남은 조건

- 개인정보 처리방침의 실제 운영자명·문의처·분석 항목·보관기간·국외 이전 내역 확정
- GA4 향상된 측정 해제와 데이터 보관 설정 확인
- Clarity Strict 마스킹, 만 18세 미만 대상 서비스 제한 해당 여부 확인
- `ANALYTICS_ENABLED=true` 배포 후 GA4 DebugView와 Clarity에서 운영 수신 확인
- 운영 기준선 수집 후 반복 불편 1~2개 선정, 실제 UX 개선과 전후 지표·Lighthouse 비교

운영 정보가 비어 있는 동안 수집을 시작하지 않는다. 이 보고서는 활성화 준비와 로컬 검증의
완료 근거이며, 운영 데이터 분석이나 UX 개선 완료 근거는 아니다.
