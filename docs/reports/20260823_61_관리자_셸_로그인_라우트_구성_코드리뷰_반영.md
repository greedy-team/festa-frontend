### 📌 작업 개요
PR #62(관리자 셸·로그인·축제 검수 화면)에 달린 코드 리뷰 4건을 검증 후 반영. 로그인 응답 파싱 계약 위반, 모바일 드로어 접근성, 축제 발행 해제 오조작 방지, 미사용 필터 배선 정리.

### 🔍 문제 분석

리뷰어가 라인 코멘트로 남긴 4건을 코드 대조로 검증했다.

1. `login()`의 성공 경로(`response.json()`)에 `try/catch`가 없어, 함수 docstring이 명시한 "실패 시 항상 `AdminApiError`를 던진다"는 계약을 200 응답이 깨진 본문(프록시 이슈 등)일 때 어긴다.
2. `AdminShell`의 모바일 드로어가 열린 동안 뒤에 깔린 `<main>`에 `aria-hidden`이 없어, 오버레이가 시각적으로만 가릴 뿐 Tab 포커스가 화면에 안 보이는 요소(체크박스·버튼)로 넘어간다.
3. `FestivalReviewTable`의 '해제' 버튼이 확인 절차 없이 클릭 한 번으로 `onUnpublish`를 실행해, 이미 발행된 축제를 오조작으로 내리면 되돌리기 어렵다.
4. `FestivalReviewScreen`의 `year` 필터가 URL 파싱 → `useAdminFestivals` → `makeHref`까지 전부 연결돼 있지만, 이 화면에는 `year`를 설정할 UI 컨트롤이 하나도 없어 URL을 직접 편집해야만 도달하는 죽은 경로였다.

### ✅ 구현 내용

#### 로그인 응답 파싱에 try/catch 추가
- **파일**: `src/features/admin/auth/api.ts`
- **변경 내용**: 성공 경로의 `response.json()`을 `try/catch`로 감싸, 파싱 실패 시 `AdminApiError(ADMIN_ERROR_CODE.UNKNOWN, response.status)`를 던지도록 수정
- **이유**: 에러 경로(44~51행)는 이미 `.catch(() => ({}))`로 방어하고 있었는데 성공 경로만 예외였다. 실패 시 항상 throw한다는 함수 계약을 전 경로에서 동일하게 지키도록 맞췄다

#### 드로어 열림 중 본문을 포커스 순서에서 제외
- **파일**: `src/components/layout/AdminShell.tsx`
- **변경 내용**: `<main>`에 `aria-hidden={isDrawerOpen}` 추가
- **이유**: 별도 포커스 트랩 없이도 스크린리더·Tab 순회에서 숨겨진 본문을 제외하는 최소 조치로 충분하다고 판단

#### 발행 해제 확인 절차 추가
- **파일**: `src/features/admin/festival/components/FestivalReviewTable.tsx`
- **변경 내용**: '해제' 버튼 클릭 시 `window.confirm(\`${festival.name}의 발행을 해제할까요?\`)`을 거친 뒤에만 `onUnpublish` 호출
- **이유**: 저장소에 확인 모달 컴포넌트가 없어 네이티브 `confirm`으로 처리. 되돌릴 UI가 없는 동작이라 최소 한 단계의 확인이 필요했다

#### year 필터 배선 제거
- **파일**: `src/features/admin/festival/components/FestivalReviewScreen.tsx`, `src/features/admin/festival/api.ts`, `src/features/admin/festival/types.ts`
- **변경 내용**: `parseYear` 함수, `year` state, `useAdminFestivals` 호출의 `year` 인자, `useEffect` 의존성 배열의 `year`, `makeHref`의 `year` 쿼리 파라미터 설정을 제거. `FestivalReviewParams.year` 타입 필드와 `api.ts`의 연도 필터링 로직도 함께 삭제
- **이유**: 실제로 값을 설정할 UI가 없는 상태에서 파싱·전달·URL 반영 로직만 남겨두면 코드 전 레이어(타입 → API → 화면)에 죽은 코드가 쌓인다. UI가 추가될 때 다시 배선한다

### 🔧 주요 변경사항 상세

#### src/features/admin/auth/api.ts
```ts
try {
  return (await response.json()) as LoginResponse;
} catch (error) {
  console.error(`POST ${LOGIN_PATH} 응답 파싱 실패`, error);
  throw new AdminApiError(ADMIN_ERROR_CODE.UNKNOWN, response.status);
}
```
에러 경로와 동일한 방식(`console.error` 후 `AdminApiError` throw)으로 통일했다.

**특이사항**:
- 현재 호출부(`admin/login/page.tsx`)는 `err instanceof AdminApiError`로만 분기해서 이번 수정 전에도 크래시는 나지 않았다. 다만 향후 `errorCode`로 세분 분기하는 호출부가 생기면 이 경로가 조용히 깨질 수 있었던 지점이라 선제 수정했다

#### src/features/admin/festival/components/FestivalReviewScreen.tsx
`year` 관련 코드를 5개 지점(파싱 함수, 변수 선언, 쿼리 훅 인자, effect 의존성, `makeHref`)에서 각각 제거. 화면 자체의 구조나 나머지 필터(published, discovery, q) 동작에는 변화가 없다.
