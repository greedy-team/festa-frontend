### 📌 작업 개요

프로젝트에 아키텍처 개요 문서가 없어 신규 합류자가 전체 구조를 파악하기 어렵다는 문제(#64)를 해결하기 위해 `docs/architecture.md`·`docs/mocking-strategy.md`를 신규 작성하고, 기존 `src/mocks/` 아래 3개 문서(`README.md`·`CODE_GUIDE.md`·`MOCKING_STRATEGY.md`)를 실제 코드와 어긋난 부분 위주로 최신화했다. 리뷰에서 9건의 사실관계 오류가 지적돼 전부 반영했다.

### 🎯 구현 목표

- 새 문서 2건: 폴더 구조·데이터 흐름을 다이어그램으로 보여주는 아키텍처 문서, 목데이터 전략을 설명하는 문서
- 기존 모킹 문서 3건이 서술하는 내용이 실제 구현(특히 `fetchJson`/`fetchMockJson`의 실제 동작)과 어긋난 부분 정정
- `host.type` 필드처럼 문서마다 산발적으로 설명이 중복된 항목을 단일 출처로 정리

### ✅ 구현 내용

- **`docs/architecture.md`(신규)**: 폴더 구조 다이어그램, 데이터 흐름도, `types/api.ts` vs `features/<domain>/types.ts` 분리 기준, 엔드포인트 표 작성
- **`docs/mocking-strategy.md`(신규)**: MSW 도입 배경, `NEXT_PUBLIC_API_MOCKING` 스위치 동작, FAQ 섹션 작성
- **기존 문서 최신화(`src/mocks/README.md`·`CODE_GUIDE.md`·`MOCKING_STRATEGY.md`)**: `host.type` 관련 설명을 `MOCKING_STRATEGY.md`의 "5. 갱신" 섹션 하나로 모으고 나머지 문서는 그 섹션을 가리키도록 정리, `CODE_GUIDE.md`의 모킹 메커니즘 설명을 실제 구현(`fetchJson`이 `RequestHandler.run()`을 직접 호출하는 방식)에 맞게 재작성

#### 리뷰 반영 (9건)
1. 데이터 흐름도의 엣지 라벨 "로컬 개발 시 가로챔" → "모킹 켜짐 시 직접 호출"로 정정 — 실제로는 `instrumentation.ts`의 `server.listen()` 네트워크 가로채기가 아니라 `api.ts`가 `RequestHandler.run()`을 직접 호출하는 경로가 실제 동작이기 때문
2. `lib/` 행 설명에 `api.ts`(`fetchJson`) 언급 추가
3. 컴포넌트·타입 배치 규칙 중복 서술 제거, `folder-structure.md`를 단일 출처로 지정하고 각주로 `types/api.ts` vs `features/<domain>/types.ts` 분리 기준만 보충
4. "실패 처리 계약" 섹션에 관리자 화면이 별도의 throw 기반 계약을 쓴다는 점 명시
5. 엔드포인트 표에 `GET /artists`의 `q` 파라미터 추가
6. 엔드포인트 표에 관리자 로그인(`POST /api/admin/auth/login`) 행 추가, 나머지 관리자 엔드포인트는 아직 실제로 존재하지 않는다는 주석 추가
7. `mocking-strategy.md` FAQ의 "관리자 화면은 아직 목데이터가 없습니다" 답변 정정 — 로그인은 `adminAuth.ts`로 모킹돼 있고, 이후 화면들만 MSW 대신 로컬 픽스처 상태를 쓰는 것
8. `CODE_GUIDE.md` §2.5/§3의 모킹 메커니즘 설명을 `instrumentation.ts` 중심 서술에서 실제 `fetchMockJson` 직접 호출 방식으로 재작성
9. `README.md` 구조 다이어그램에 5번째 핸들러(`adminAuth.ts`) 추가, `/auth/me` 부재 이유를 "로그인은 있지만 상태 재확인 엔드포인트가 없다"로 정정

### 🧪 테스트 및 검증

- 문서 전용 변경이라 런타임 테스트는 없음 — 각 서술이 실제 코드(`src/lib/api.ts`, `src/mocks/handlers/*`, `instrumentation.ts`)와 일치하는지 직접 읽고 대조
- `pnpm lint` 통과(마크다운은 대상 아님, 나머지 변경 없음 확인용)

### 📌 참고사항
