### 📌 작업 개요

축제 전체 목록과 홈 "최근 등록된 축제" 카드에서 기간이 `05.07 ~ 05.09`로만 보여 몇 년 축제인지 알 수 없던 문제 해결. 기간 바로 위에 연도를 별도 줄로 얹었다.

연도는 이미 응답에 들어 있었다. `GET /festivals` 항목의 `startDate`·`endDate`가 `YYYY-MM-DD` 전체 날짜이고, 화면에서 `dateRange`가 앞 5글자를 잘라내고 있었을 뿐이다. API 변경이나 추가 요청 없이 표기만 바꿨다.

### 🎯 구현 목표

- 카드에 연도를 표시하되, 기간과 별개의 줄로 둔다
- 여러 해가 섞여 나오는 화면(축제 목록·홈 최근 등록)에만 적용하고, 맥락이 이미 좁혀진 화면은 건드리지 않는다
- 해를 걸치는 축제에서 연도와 기간이 어긋나 보이지 않게 한다

### ✅ 구현 내용

#### 연도 표기 함수 추가

- **파일**: `src/lib/festivalDate.ts`
- **변경 내용**: `festivalYear(startDate, endDate)` 추가. 시작·종료 연도가 같으면 `2026`, 다르면 `2025 ~ 2026`
- **이유**: 기존 `dateRange`를 고치면 이 함수를 공유하는 9곳(홈 히어로, 축제 상세 히어로, 검색 결과 행, 주최 상세 카드 2종, 아티스트 출연 이력, 관리자 검수 표)이 전부 함께 바뀐다. 목록 카드에만 필요한 표기라 새 함수로 분리했다

#### 카드 두 곳에 연도 줄 추가

- **파일**: `src/features/festivals/components/FestivalCard.tsx`, `src/features/home/components/RecentCard.tsx`
- **변경 내용**: 축제명과 기간 사이에 연도 줄 삽입. `학교명 / 축제명 / 연도 / 기간` 네 줄 구성
- **이유**: 두 카드가 같은 시각 문법(포스터 + 3줄 텍스트)을 쓰고 홈과 목록에 나란히 노출된다. 한쪽만 고치면 같은 축제가 화면에 따라 다르게 보인다

#### 연도·기간 간격 조정

- **파일**: 위 두 파일
- **변경 내용**: 연도는 `mt-2`(8px), 기간은 `mt-1`(4px). 두 줄 모두 `text-label-regular text-muted-soft`로 같은 크기·색 유지
- **이유**: 같은 스타일에 간격만 좁혀 연도와 기간이 한 덩어리로 읽히게 했다. 새 색이나 새 토큰을 만들지 않았고, 두 간격 모두 DESIGN.md의 spacing 스케일(4·8·12…) 안의 값이다

### 🧭 결정 기록 (ADR)

#### `dateRange`를 수정하지 않고 `festivalYear`를 따로 만든다

- **문제**: 카드에 연도를 넣는 가장 짧은 방법은 `dateRange`가 `2025.05.07 ~ 05.09`를 반환하게 고치는 것이다. 그러나 이 함수는 9곳이 공유한다
- **선택**: `dateRange`는 그대로 두고 `festivalYear`를 신설, 목록 카드 두 곳에서만 조합
- **대안**:
  - `dateRange`에 연도 포함 옵션 인자 추가 — 호출부마다 불리언을 읽어야 무엇이 나오는지 알 수 있고, 기본값이 곧 숨은 결합이 된다
  - `dateRange` 자체를 연도 포함으로 변경 — 히어로·상세·검색·관리자 표까지 표기가 바뀐다. 이 화면들은 이미 하나의 축제를 보고 있거나 검색 조건이 걸려 있어 연도가 중복 정보다
- **트레이드오프**: 기간을 보여주는 함수가 둘이 된다. 새 화면을 만들 때 어느 쪽을 쓸지 판단이 한 번 더 필요하다

#### 해를 걸치는 축제는 두 연도를 함께 적는다

- **문제**: `2025-12-30 ~ 2026-01-02` 축제에 시작 연도만 적으면 `2025` 아래에 `12.30 ~ 01.02`가 놓여 종료일이 어느 해인지 알 수 없다
- **선택**: 시작·종료 연도가 다르면 `2025 ~ 2026`으로 함께 표기
- **대안**: 시작 연도만 표기 — 한 줄 덜 쓰지만 연도 줄을 넣은 목적 자체가 무너진다
- **트레이드오프**: 현재 데이터에는 해를 걸치는 축제가 없어 화면에서 확인할 수 없다. 유닛테스트로만 보장된다

### 🔧 주요 변경사항 상세

#### festivalYear

`startDate.slice(0, 4)`와 `endDate.slice(0, 4)`를 비교해 같으면 연도 하나, 다르면 물결로 잇는다. 두 값 모두 날짜 문자열이라 `Date` 객체를 만들지 않으며, 따라서 실행 환경 타임존의 영향을 받지 않는다. 같은 파일의 `todayInSeoul` 주석이 지적하는 서버(UTC)·브라우저(KST) 불일치 문제가 이 함수에는 애초에 생기지 않는다.

**특이사항**:
- 연도와 기간이 서로 다른 함수에서 나오지만 같은 두 날짜 문자열을 보므로 어긋날 수 없다
