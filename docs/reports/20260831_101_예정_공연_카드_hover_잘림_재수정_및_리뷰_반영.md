### 📌 작업 개요

아티스트 상세 화면의 예정 공연 카드가 hover 시 그림자(`--shadow-hover`)가 카드 컨테이너 경계에서 잘리는 문제(#101)를 수정했다. PR #102로 1차 수정을 머지한 뒤, 리뷰에서 지적된 주석 오류와 별도 레이아웃 회귀를 PR #121로 이어서 반영했다.

### 🎯 구현 목표

- hover 그림자가 카드 상하좌우로 잘리지 않게 여백을 확보
- 리뷰에서 지적된 주석의 사실관계 오류(근거 잘못 서술) 수정
- 여백 확보 과정에서 생긴 타이틀-카드 간격 레이아웃 버그 수정

### ✅ 구현 내용

#### PR #102 — hover 잘림 1차 수정
- **파일**: `src/features/artists/components/UpcomingShowsSection.tsx`
- 카드 컨테이너에 `p-6 -m-6`(패딩으로 시각적 여백을 만들고 동일한 값의 음수 마진으로 레이아웃상 차지 공간은 상쇄)을 적용해 hover 그림자가 퍼질 공간을 확보

#### PR #121 — 리뷰 반영
- **주석 오류 수정**: 원래 주석은 `p-6 -m-6`의 근거를 "5% 스케일 여유"라고 적어뒀는데, 실제 근거는 `globals.css`에 정의된 `--shadow-hover`(`0 12px 40px`)의 확산 범위였다. 컴파일된 CSS를 직접 확인해 근거를 정정하고 주석에 명시
- **레이아웃 버그 수정**: `p-6 -m-6`을 적용하면서 기존 `mt-4`(섹션 타이틀과 카드 사이 간격)가 의도한 24px이 아니라 다른 값으로 렌더되는 회귀가 생겼다. 원인은 Tailwind가 생성하는 CSS에서 `.m-*`(shor트핸드, `-m-6`) 규칙이 `.mt-*`(방향 지정, `mt-4`) 규칙보다 **먼저** 출력되는 순서 문제 — 소스 코드의 클래스 나열 순서와 무관하게 CSS 파일 내 등장 순서가 우선순위를 결정하는 CSS 특성상, 마지막에 정의된 쪽이 이겨야 할 `margin-top`이 실제로는 `-m-6`에 밀릴 수 있는 구조였다. `pnpm build` 후 컴파일된 CSS의 바이트 오프셋을 직접 대조해 `.-m-6`이 `.mt-0`/`.mt-4`보다 앞에 위치함을 확인
- `mt-4`를 `mt-0`으로 명시적으로 바꿔 margin-top을 0으로 고정한 뒤, 실제 24px 간격은 다른 방식(부모 요소의 `gap` 등 기존 레이아웃 구조)으로 유지되도록 확인 — 클래스 하나만 바꿔 `margin-top` 프로퍼티가 항상 의도한 값으로 pin되게 함

### 🧪 테스트 및 검증

- `pnpm build`로 실제 컴파일된 CSS를 확인해 `.-m-6`/`.mt-0`/`.mt-4`의 실제 출력 순서와 최종 적용값을 검증
- 브라우저에서 hover 시 그림자가 잘리지 않는지, 타이틀-카드 간격이 24px로 복원됐는지 육안 확인
- `pnpm lint`, `pnpm exec tsc --noEmit` 통과

### 📌 참고사항

- 이 케이스는 "Tailwind 유틸리티 클래스는 뒤에 적은 게 이긴다"는 통념이 shorthand·방향 클래스가 섞이면 깨질 수 있다는 걸 보여준 사례다. 비슷한 조합(`p-*`/`px-*`, `m-*`/`mt-*` 등)을 같은 요소에 함께 쓸 때는 컴파일된 CSS로 실제 우선순위를 확인하는 게 안전하다
