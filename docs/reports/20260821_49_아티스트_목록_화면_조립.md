### 📌 작업 개요
아티스트 목록(`/artists`) 화면을 새로 만들고, `SortDropdown`을 축제 목록과 공유하는 공용 컴포넌트로 일반화했다.

### 🎯 구현 목표
- 브레드크럼 → 장르 필터 칩 → 검색/정렬 → 카드 그리드 → 페이지네이션
- 장르 필터·정렬·페이지를 전부 URL 쿼리 상태로 관리

- **이유**: 같은 UI를 두 화면에서 각자 구현하면 나중에 어긋난다

### 🧭 결정 기록 (ADR)

#### `SortDropdown`을 네이티브 `<select>` + GET 폼으로 재구현
- **문제**: 커스텀 리스트박스(버튼+ul)가 `mousedown`으로만 닫히고, `aria-expanded`/`aria-haspopup`이 없고, Escape로 안 닫혔다. 리뷰에서 "공용 컴포넌트가 되는 시점이니 지금 정하자"는 지적을 받았다
- **선택**: `<form method="GET"> + 네이티브 <select>`로 전면 교체. 키보드·스크린리더·JS 미로드 처리를 전부 브라우저에 위임하고, `sort`/`page` 외 현재 쿼리(genre 등)는 hidden input으로 보존
- **대안**: ARIA 속성만 최소 패치 — 리스트박스 패턴을 제대로 하려면 방향키·포커스 관리까지 필요해 패치로는 부족하다고 판단
- **트레이드오프**: 드롭다운의 시각적 커스터마이징(화살표 아이콘 등)을 포기하는 대신 접근성을 브라우저 기본 구현에 위임
- ⭐ **볼트 승격 권장** — 다른 화면의 유사 컴포넌트에도 영향을 주는 패턴 결정

#### 장르 옵션을 `GENRE_LABELS` 하나에서 파생
- **문제**: `GENRE_OPTIONS`(화면용 배열)와 `VALID_GENRES`(검증용 배열)를 각각 손으로 나열해서, 장르가 하나 추가되면 두 곳을 같이 고쳐야 했다
- **선택**: `Object.entries(GENRE_LABELS)`/`Object.keys(GENRE_LABELS)`로 파생하도록 정리

### 🔧 주요 변경사항 상세

#### 실패/빈 상태 구분, page 파싱
홈·축제 목록과 같은 원칙 — `res.ok`로 실패를 구분하고, `?page=`에 `Math.floor` 가드를 두고 총 페이지 초과 시 `redirect()`로 마지막 페이지로 보낸다.

**특이사항**:
- `getArtists`의 기본값 4개(`page=0, size=10, sort="APPEARANCES"` 등)가 유일한 호출부가 전부 넘기고 있어 한 번도 실행되지 않는 죽은 코드였다 — 제거하고 `Params`를 필수 필드로 변경
