### 📌 작업 개요

통합 검색 결과 화면(/search)의 두 가지 어긋남을 정리했다.

- 다른 사용자 화면은 모두 진입 페이드인이 있는데 검색 화면만 없어 뚝 떴다.
- 아티스트 검색 결과가 이름 해시 색 + 이니셜 원형 아바타를 계속 썼다. 아티스트 히어로·목록은 이미 이 아바타를 걷어냈는데(사진 없는 자리를 색 배경으로 채우지 않는다는 판정) 검색 결과만 반영되지 않았고, 아티스트 결과만 테두리 카드 + 버튼 형태라 같은 화면의 학교·축제 행과 시각적으로 어긋났다.
- 축제 검색 결과가 학교명에서만 매칭됐을 때 "학교명 일치: {학교명}" 줄을 따로 붙였다. 바로 위 메타 줄이 이미 "· {학교명}"을 보여줘 중복이었다.
- 타입 필터 칩 4개가 한 줄 고정이라 좁은 폭에서 빠듯했고, 결과 행들의 좌우 패딩이 데스크톱 기준(24px)이라 모바일에서 텍스트 자리를 과하게 먹었다.

### 🎯 구현 목표

- 검색 결과 화면을 다른 화면과 같은 진입 페이드인으로 감싼다.
- 아티스트 결과에서 색 아바타를 제거한다.
- 아티스트 결과를 학교·축제와 같은 행 형태로 통일한다.
- 축제 결과의 "학교명 일치" 줄을 제거한다.
- 좁은 폭에서 칩이 접히게 하고 결과 행의 모바일 패딩을 줄인다.

### 🧭 결정 기록 (ADR)

#### 아티스트 검색 결과를 행으로 통일

- **문제**: 아티스트 검색 결과만 색 아바타가 달린 테두리 카드 + 버튼이라, 같은 화면의 학교·축제 행과 어긋났다. 색 아바타는 아티스트 히어로·목록에서 이미 제거된 상태였다.
- **선택**: 색 아바타를 제거하고 학교·축제 결과와 같은 행(`rounded-row border`, 행 전체 링크, `ChevronRight`)으로 재구성.
- **대안**:
  - 카드 형태 유지, 왼쪽 아바타 자리만 삭제 — 카드 + 버튼 골격이 남아 학교·축제 행과 계속 어긋난다.
  - 아바타 유지 — 사진 없는 자리를 색으로 채우지 않는다는 기존 판정과 어긋난다.
- **트레이드오프**: 검색 결과에서 아티스트의 시각적 무게가 줄어든다. 존재감을 이름 타이포와 여백으로만 낸다.

#### 진입 페이드인은 메인·빈 검색어 화면만 감싼다

- **문제**: `SearchPage`는 return 분기가 셋(검색어 없음 / API 실패 / 결과)이라 어디를 감쌀지 정해야 했다.
- **선택**: 결과 화면과 검색어 없는 화면만 `PageFadeIn`으로 감싸고 에러 화면은 그대로 둔다.
- **대안**: 세 분기 모두 감싸기 — 축제 목록 화면이 에러 분기를 감싸지 않는 기존 패턴과 어긋난다.
- **트레이드오프**: API 실패 화면은 페이드인 없이 뜬다. 드문 경로라 감수한다.

#### 폭 상한 값은 1200을 재사용한다

- **문제**: 캡을 걸기로 한 뒤 값을 정해야 했다. 실측상 행 텍스트가 요구하는 폭은 축제 250px · 학교/아티스트 183px뿐이라, 가독성만으로는 1100·1200·1280이 전부 충분해 값을 가릴 근거가 되지 못했다(2560px에서 세 후보를 렌더해 비교했으나 1200과 1280은 육안 구분이 안 된다).
- **선택**: 아티스트 목록·상세가 이미 쓰는 `1200`을 그대로 쓴다.
- **대안**:
  - `1280` — DESIGN.md의 데스크톱 컨테이너 값이자 `AdSlot` 배너의 명목 라벨(1280×96)과 맞는다. 다만 그 라벨은 이미 실제 폭과 분리돼 있고(아티스트 상세도 1200 캡 안에 같은 배너를 둔다), 읽기용 화면 폭이 1200/1280 둘로 갈린다.
  - `1100` — 더 좁혀도 텍스트엔 여유가 있지만, 세 번째 값을 만들 이유가 없다.
- **트레이드오프**: 가독성이 값을 가려주지 않으므로 이 선택의 근거는 전적으로 일관성이다. 나중에 읽기용 화면 폭을 조정하려면 아티스트 화면과 함께 옮겨야 한다.

#### 세 return 모두에 캡을 건다 (아티스트 화면과 다름)

- **문제**: 아티스트 목록·상세는 성공 return에만 캡을 걸었다. 같은 방식이면 `/search`는 결과 화면만 1200이 된다.
- **선택**: 검색어 없음·API 실패·결과 세 return 모두에 건다.
- **대안**: 아티스트와 동일하게 성공 return만 — 세 분기가 모두 같은 `SearchBar`를 그려서, 검색 전(전폭)과 검색 후(1200) 사이에 검색창 폭이 튄다.
- **트레이드오프**: 같은 결정(DEC-0131)의 적용 방식이 화면마다 미세하게 달라진다. 이유를 코드 주석에 남겼다.

#### "학교명 일치" 줄을 제거하며 DESIGN.md를 함께 고친다

- **문제**: 이 줄을 빼면 코드가 DESIGN.md `{component.search-result-row}` 스펙과 `{colors.accent}` "매칭 도트 전용" 정의와 어긋난다.

- **대안**: DESIGN.md는 별도 문서 이슈로 미룬다 — 코드와 스펙이 갈린 채로 남아 다음 사람이 되돌릴 근거가 된다.
- **트레이드오프**: `{colors.accent}`는 이제 실사용처가 없는 팔레트 전용 토큰이 된다.

#### 죽은 `ArtistAvatar`를 후속 이슈로 미루지 않고 이 PR에서 지운다

- **문제**: 리뷰에서 non-blocking으로 지적됐다 — 이 PR 뒤로 `ArtistAvatar`는 어디서도 import되지 않는다. 여기서 지우거나 후속 이슈로 올리거나 둘 중 하나다.

### 📌 참고사항

- `pnpm build`(Turbopack)는 워크트리 디렉터리 이름에 긴 비-ASCII 문자열이 있으면 자산 식별자를 자르다 패닉한다(`start byte index ... is not a char boundary`). 코드 문제가 아니라 Turbopack 버그이고 CI는 ASCII 경로에서 빌드해 영향이 없다 — 검증은 ASCII 경로의 워크트리에서 정상 수행했다.
- `ArtistResult` 타입의 `imageUrl` 필드는 이번 변경 이전부터 미사용이었고 이번 작업 범위 밖이라 그대로 뒀다.
- **320px에서 축제 결과 행은 여전히 좁다.** 가로 스크롤은 없지만 축제명이 두세 글자에서 잘리고 날짜가 여러 줄로 접힌다. 고정 폭 요소(포스터 80px · D-day pill · 화살표)가 텍스트 자리를 거의 남기지 않아서인데, 이를 풀려면 좁은 폭에서 포스터를 줄이거나 D-day를 메타 줄로 내리는 레이아웃 결정이 필요하다 — 패딩 조정 범위를 넘어서므로 이번에 다루지 않았다. 360px 이상에서는 읽힌다.
- **1024px 미만에서는 `/search`로 갈 수 있는 UI 자체가 없다** (헤더 검색 폼이 `hidden lg:block`, 햄버거 메뉴·푸터에도 진입 없음). 이 화면의 반응형을 손봐도 모바일 사용자가 도달할 경로가 없다는 뜻이라, 별도 이슈 #155로 분리했다.
