### 📌 작업 개요

개인정보 처리방침·이용약관·저작권 정책에 남아 있던 미확정 항목 43개를 실제 운영 정보로
채우고, 로그인이 없는 서비스 특성상 회원가입 절차가 없어 약관 적용을 알릴 자리가 없던
문제를 첫 방문 고지 모달로 보완했다. 두 작업 모두 #233(GA4·Clarity 분석 동의)이 운영
활성화 조건으로 요구한 선행 작업이다.

### 🎯 구현 목표

- 정책 페이지의 `(항목명 확정 전)` 표기를 실제 값으로 채워, 분석 수집을 켤 수 있는
  최소 조건(운영자·문의처·국외 이전 고지)을 만족한다.
- 회원가입이 없는 서비스에서 "계속 이용하면 약관에 동의한 것으로 본다"는 사실을 첫
  방문에 한 번 알린다. 이 고지는 개인정보 수집 동의가 아니므로 GA4·Clarity 같은 선택적
  수집 동의(AnalyticsConsent)와는 별개로 다룬다.

### ✅ 구현 내용

#### 정책 문서 확정값 반영
- **파일**: `src/lib/policy.ts`
- **변경 내용**: 운영자명·문의 창구 URL·개인정보 보호책임자·시행일을 공통 상수로 분리
- **이유**: 세 정책 페이지가 같은 값을 참조하므로 한 곳만 고치면 되게 했다

- **파일**: `src/app/privacy/page.tsx`
- **변경 내용**: 접속 기록 항목·보유기간·국외 이전 대상(Oracle·Vercel·Google·Microsoft)·
  선택적 분석 도구 고지·안전성 확보조치 등 43개 `PendingField` 자리를 채움
- **이유**: 접속 기록 항목과 보유기간은 추측하지 않고 백엔드 `AccessLogFilter`와
  `application.yml`의 `logging.logback.rollingpolicy` 설정을 직접 확인해 반영했다.
  국외 이전 대상은 실제 연동 중인 외부 서비스(포스터 저장소, 호스팅, 지도, 분석 도구)
  기준으로 적었다

- **파일**: `src/app/terms/page.tsx`, `src/app/copyright/page.tsx`
- **변경 내용**: 운영자·문의 창구·시행일 확정
- **이유**: privacy 페이지와 같은 공통 상수를 참조해 세 문서 간 값이 어긋나지 않게 했다

- **파일**: `src/components/ui/ContactLink.tsx` (신규), `src/components/ui/PendingField.tsx` (삭제)
- **변경 내용**: 문의 창구 링크를 공용 컴포넌트로 통일하고, 모든 미확정 자리가 채워져
  더는 쓰이지 않는 PendingField를 제거
- **이유**: 확정값 반영으로 PendingField의 마지막 사용처까지 없어졌다

#### 첫 방문 이용 고지 모달
- **파일**: `src/lib/siteNotice.ts`
- **변경 내용**: 고지 확인 여부를 브라우저 저장소(`festa.site-notice.v1`)에 기록하는
  구독 가능한 스토어를 추가
- **이유**: 분석 동의(`festa.analytics-consent.v1`)와 저장 키를 분리했다. 고지는 모든
  배포에서 뜨지만 분석 동의는 `ANALYTICS_ENABLED`가 켜진 배포에서만 뜨므로, 한 값으로
  합치면 분석을 나중에 켜는 순간 이미 고지를 본 방문자에게 모달이 다시 뜬다

- **파일**: `src/components/policy/SiteNotice.tsx`
- **변경 내용**: 첫 방문에 뜨는 고지 모달. 관리자 화면은 제외하고, 확인 또는 Escape로
  닫으면 다시 뜨지 않는다
- **이유**: 로그인이 없어 가입 절차에서 약관을 보여줄 자리가 없다. 계속 이용하는 것을
  약관 적용 확인으로 보고 그 사실을 먼저 알린다

- **파일**: `src/app/layout.tsx`, `src/components/analytics/AnalyticsConsent.tsx`
- **변경 내용**: SiteNotice를 루트 레이아웃에 연결하고, 고지를 확인하기 전에는 분석 동의
  모달이 겹쳐 뜨지 않도록 순서를 맞춤
- **이유**: 두 모달 모두 `<dialog>`라 동시에 열면 겹친다. 분석 활성 배포에서는 고지 확인
  → 분석 선택 순서로 이어지게 했다

### 🧭 결정 기록 (ADR)

#### 정책 문서를 읽으러 이동한 동안 고지를 다시 띄우지 않는다

- **문제**: SiteNotice는 루트 레이아웃에 있어 라우트 이동에도 언마운트되지 않는다.
  처음 구현에서는 고지 모달의 링크로 `/terms`에 갔다가 뒤로가기로 `/`에 돌아와도
  모달이 다시 뜨지 않았다 — 효과의 의존성이 `[isAdmin, acknowledged]`뿐이라 두 값이
  라우트 이동 동안 그대로라 효과가 다시 돌지 않았기 때문이다.
- **선택**: 경로에서 파생된 `isPolicyPage` 값을 의존성에 추가해, 정책 페이지에
  머무는 동안에는 닫아 두고 벗어나면(`true → false`) 효과가 다시 돌아 모달이 재노출되게
  했다
- **대안**:
  - 의존성을 그대로 두고 라우트 변경마다 수동으로 재평가 — 이미 있는 `pathname`
    구독 메커니즘을 우회하는 별도 장치가 필요해 더 복잡하다
  - 정책 링크를 새 탭으로 열기 — 모바일 탭 전환이 어색하고, 사이트 내부 문서를 새 탭으로
    여는 것은 이 저장소의 다른 내부 링크 관례와 다르다
- **트레이드오프**: 없음 — 부작용 없이 원래 의도한 동작(고지→정책 열람→복귀 시 재노출)을
  구현했다

### 🔧 주요 변경사항 상세

#### AnalyticsConsent의 hydration 스냅샷 버그
`useSyncExternalStore`의 서버 스냅샷을 `() => true`로 둔 채 그 값을 직접 판정에 썼더니,
고지를 확인하기 전에도 분석 동의 모달이 먼저 열리는 문제가 있었다. 구독값은 재실행을
거는 용도로만 쓰고, 실제 판정은 `readSiteNoticeAcknowledged()`로 저장소를 직접 읽도록
고쳤다.

**특이사항**:
- 이미 열린 `<dialog>`에 `showModal()`을 다시 호출하면 `InvalidStateError`가 나서
  `open` 여부를 먼저 확인하는 가드를 추가했다
- `showModal()`은 첫 포커스 가능 요소(이용약관 행)에 자동으로 포커스를 주는데, 전역
  `:focus-visible` 스타일 때문에 그 행에만 테두리가 둘리는 것처럼 보였다. 다이얼로그
  컨테이너에 `tabIndex={-1}`을 주고 열릴 때 포커스를 옮겨, 키보드 포커스 표시는
  유지하면서 첫 행만 달라 보이는 문제를 없앴다

### 📌 참고사항

- 개인정보 보호책임자를 "팀 페스타 운영자 (별도 부서를 두지 않아 운영자가 맡습니다)"로
  적었다 — 개인정보 보호법 제31조상 미지정 시 사업주·대표자가 자동으로 보호책임자가
  되므로 빈 값으로 둘 수 없었다
- 보유기간(문의 1년, 권리침해 신고·이용허락 3년, 백업 30일)과 분석 도구 보유기간(GA4
  14개월, Clarity 13개월)은 각 도구·업무 성격의 통상 기준을 적용한 것으로, 운영자의
  별도 방침이 있으면 다시 확인이 필요하다
- 분석 수집 활성화는 이 작업의 범위가 아니다. `ANALYTICS_ENABLED`는 계속 꺼진 상태이며,
  Vercel Production 환경변수 설정과 재배포는 별도로 진행한다
