### 📌 작업 개요
홈 히어로 4개 패널의 "자세히 보기 →" 링크가 클릭되지 않던 문제를 수정했다.

### 🔍 문제 분석
도트 페이지네이션을 감싸는 래퍼가 `inset-x-0`로 뷰포트 전체 폭을 차지하고 있었다. 도트 pill 자체는 가운데 좁은 영역만 시각적으로 보이지만, 래퍼는 좌우 빈 여백까지 포함해 전체 폭(예: 1710px)만큼 투명하게 깔려 있었다. 이 래퍼가 히어로 패널 grid보다 DOM에서 나중에 렌더링되어 쌓임 순서상 위에 오고, `pointer-events`가 기본값 `auto`라 투명한 빈 영역도 클릭을 그대로 가로챘다. 마침 래퍼의 높이(44px)가 "자세히 보기" 링크의 y좌표 대역과 겹쳐, 4개 패널 전부의 링크가 클릭되지 않았다.

브라우저에서 `document.elementFromPoint()`로 확인한 결과, 링크 위치를 클릭해도 실제로는 도트 래퍼 div가 최상단 요소로 잡혔다.

### ✅ 구현 내용

#### 도트 래퍼에 pointer-events-none 추가
- **파일**: `src/features/home/components/Hero.tsx`
- **변경 내용**: 도트를 감싸는 `<div className="absolute inset-x-0 bottom-9 flex justify-center">`에 `pointer-events-none` 추가
- **이유**: 투명한 빈 영역이 클릭을 가로채지 않도록 막기 위해

#### 도트 pill 자체에는 클릭을 다시 허용
- **파일**: `src/components/ui/HeroDots.tsx`
- **변경 내용**: 도트 pill 루트 div에 `pointer-events-auto` 추가
- **이유**: 부모에 `pointer-events-none`을 걸면 자식도 함께 비활성화되므로, 실제 눈에 보이는 도트 버튼 영역만 다시 클릭 가능하게 만들어야 페이지네이션 기능이 유지된다

### 🧭 결정 기록 (ADR)
해당 없음 — CSS `pointer-events` 속성으로 클릭 가능 영역을 시각적 요소 크기에 맞추는 표준적인 수정이다.
