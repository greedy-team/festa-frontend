### 📌 작업 개요
아티스트 상세(`/artists/{id}`) 화면을 새로 만들었다. 사진을 쓰지 않는 정책(DEC-0063) 때문에 이니셜+색상 아바타(`ArtistAvatar`)를 신규 공용 컴포넌트로 확정하고, 목록·검색 카드에도 함께 적용했다.

### 🎯 구현 목표
- 09-2 시안(히어로 + 예정 공연/출연 이력 좌우 2단) 재현
- 초상권 문제로 아티스트 실사진을 쓰지 않는 정책에 맞는 대체 아바타 확정

- **변경 내용**: `GET /artists/{id}` 연동. 히어로(아바타+장르+이름+인스타그램 배지), 예정 공연/출연 이력 좌우 2단(넓은 쪽이 예정 공연)
- **이유**: 이슈에 정의된 아티스트 상세 화면 구성

- **변경 내용**: 이름을 해시해 고른 색 위에 이니셜을 얹는 컴포넌트를 신규 작성하고, 이미 있던 두 화면의 `gridTint` 빈 원/사각형도 같이 교체
- **이유**: DEC-0063(초상권 문제로 실사진 미사용)에 대한 구체적인 답이 이 이슈에서 확정됨. 호출부가 이 PR만으로는 1개뿐이라 `size`/`shape` prop이 과한 유연성이 될 뻔했는데, 이미 있던 두 화면을 같이 옮겨서 호출부 3개로 근거를 만들었다

### 🧭 결정 기록 (ADR)

#### 예정 공연 행에 실제 공연일을 표시
- **문제**: D-day가 공연일(`performanceDate`) 기준으로 계산되는데, 옆에 보여주는 날짜는 축제 전체 기간이었다. 3일짜리 축제의 DAY 3 공연이면 D-day와 화면에 보이는 날짜가 서로 다른 걸 가리키는 것처럼 보였다
- **선택**: `DAY {day} · {fullDate(performanceDate)}`로 실제 공연일을 표시 — 두 필드(`performanceDate`, `day`)가 응답에는 있는데 화면에서 안 쓰이고 있던 것을 실제로 사용하게 됨

#### "더 보기"를 `/festivals?artistId={id}` 실제 링크로 승격
- **문제**: 예정 공연/출연 이력의 "더 보기" 요소가 항상 뜨는데(건수 조건 없음) 눌러도 아무 일도 안 일어났다
- **선택**: `total > items.length`일 때만 그리도록 가드를 추가하고, `getFestivals`에 `artistId` 파라미터를 새로 얹어(mock이 이미 지원) `/festivals?artistId={id}`로 가는 실제 링크로 변경. `/festivals` 목록 페이지도 이 쿼리를 실제로 읽어 넘기도록 배선
- **트레이드오프**: 축제 목록 화면이 "이 아티스트가 출연한 축제만" 필터링됐다는 것을 화면에 별도로 표시하지는 않음(범위 밖으로 판단)

### 🔧 주요 변경사항 상세

#### 출연 이력 연도 표시
`dateRange()`가 연도를 잘라내서(`09.04 ~ 09.06`) 2019년 출연과 2026년 출연이 같은 텍스트로 보였다 — 아카이브 성격의 화면에서 연도가 가장 중요한 정보인데 빠져 있던 것. 행마다 연도를 별도 줄로 추가했다.

**특이사항**:
- `flex` 컨테이너에 직접 준 `truncate`가 동작하지 않는 CSS 문제가 있었다(ellipsis가 붙을 line box가 없음) — 텍스트를 `<span className="truncate">`로 감싸서 해결
- 장르 조회(`GENRE_LABELS[genre]`)에 폴백이 없어 백엔드가 명세 밖 값을 내리면 빈 pill이 뜰 수 있었다 — "장르 없으면 자리를 그리지 않는다"는 기존 정책은 유지하면서 조회 자체를 가드
