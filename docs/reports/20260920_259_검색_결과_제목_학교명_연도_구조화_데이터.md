### 📌 작업 개요
구글에는 색인돼 있지만 사람들이 실제로 치는 검색어(`건국대 일감연 라인업`)에 걸리지 않는 문제를 검색 현황 실측으로 확인하고, 검색 결과 제목에 학교명·연도를 넣었다. 홈·목록에는 연도와 "대학 축제 모음"을 반영하고, 축제 상세에 `Festival`, 목록에 `ItemList` 구조화 데이터를 추가. 모든 공개 페이지에 끼어 있던 고지·동의 모달의 h2 두 개도 제목 태그에서 뺐다.

**보고서 파일**: `docs/reports/20260920_259_검색_결과_제목_학교명_연도_구조화_데이터.md`

### 🧭 결정 기록 (ADR)

### 출연자 타입은 `MusicGroup`

- **문제**: 출연자 데이터는 그룹인지 개인인지 구분하지 않는다
- **선택**: `performer`의 `@type`을 `MusicGroup`으로 통일
- **대안**:
  - `PerformingGroup` — 솔로 아티스트에 틀린 타입이 된다
  - `Person`/`MusicGroup` 분기 — 구분할 데이터가 없어 추측이 된다
- **트레이드오프**: 없음에 가깝다. schema.org 정의에 "솔로 뮤지션일 수도 있다"가 명시돼 있어, 구분을 모르는 데이터에 정확한 타입

### JSON-LD 직렬화에서 `<`를 `\u003c`로 이스케이프

- **문제**: 축제명·장소는 외부 입력이고 script 안에 들어간다. `</script>`로 태그를 닫고 나올 수 있다
- **선택**: `JSON.stringify` 결과의 `<`를 전부 `\u003c`로 치환. JSON으로는 같은 문자열이라 파싱 결과는 동일
- **대안**:
  - 이스케이프 없이 출력 — 관리자 등록값 하나로 전 방문자에게 스크립트가 실행될 수 있다
- **트레이드오프**: 원본 HTML에서 `<`가 든 값이 사람 눈에 덜 읽힌다. 공격 문자열(`</script><script>alert(1)</script>`) 테스트 포함
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

### 시크릿 게스트는 구조화 데이터에 넣지 않음

- **문제**: 라인업에는 공개 전 출연자(id `null`)가 섞여 있다
- **선택**: `id !== null`인 아티스트만, 일자 간 중복 없이 `performer`에 담는다
- **대안**: 따로 검토하지 않았다 — 기존 결정(DEC-0116)을 그대로 따랐다
- **트레이드오프**: 공개 전까지 구조화 데이터의 출연자 수가 화면의 슬롯 수보다 적다. 공개 전 출연자를 검색엔진에 먼저 넘기지 않는다는 기존 결정(볼트 DEC-0116)을 그대로 따른 것

### 상세 H1은 화면 글자를 바꾸지 않고 sr-only 보조 텍스트로

- **문제**: H1에 학교명·연도가 없지만, 화면 글자를 `건국대학교 일감연 2026`으로 바꾸면 히어로 디자인이 달라진다
- **선택**: 화면에는 축제명만, 학교명·연도는 `sr-only` span으로 앞뒤에 덧붙임. 축제명에 이미 학교명·연도가 들어 있으면 붙이지 않는다
- **대안**:
  - 화면 글자 변경 — 바로 아래 메타에 학교명·날짜가 이미 보여 같은 말이 두 번 나온다
  - H1 그대로 — 대표 제목만 읽는 보조 기술·검색엔진이 어느 학교의 몇 년 축제인지 알 수 없다
- **트레이드오프**: 보이는 글자와 H1 텍스트가 다르다. 덧붙인 값이 같은 화면에 이미 보이는 값이라 숨긴 키워드가 아니다

### 기존 E2E 3곳의 H1 단언을 완전 일치 → 포함으로

- **문제**: H1 텍스트에 학교명·연도가 붙으면서 `toHaveText(축제명)`이 실패한다
- **선택**: `toContainText(festivalName)`으로 변경
- **대안**: 따로 검토하지 않았다
- **트레이드오프**: 단언이 느슨해진다. 다만 테스트의 의도(에러·404 페이지가 아니라 클릭한 축제의 상세인가)는 유지된다 — `error.tsx`·`not-found.tsx`의 H1에는 클릭한 축제 이름이 들어 있지 않다

### 새 회귀 E2E는 원본 HTML이 아니라 렌더된 DOM에서 읽는다

- **문제**: 목 모드에서는 `MockProvider`가 워커 준비 전까지 본문을 그리지 않아 `request`로 받은 원본 HTML에 본문이 없다
- **선택**: `page.goto` 후 DOM에서 `script[type="application/ld+json"]`과 H1을 읽는다
- **대안**:
  - `request`로 원본 HTML 검사 — 목 모드에서 항상 실패한다
- **트레이드오프**: E2E는 "JS 없이도 원본 HTML에 들어간다"를 증명하지 못한다. 그 부분은 운영 조건 빌드의 원본 HTML 실측(아래 검증 절)으로 확인했다

### 홈·목록 제목의 연도는 한국 시간으로 계산

- **문제**: 연도를 고정값으로 적으면 해가 바뀔 때 조용히 낡는다
- **선택**: `Intl.DateTimeFormat`에 `timeZone: "Asia/Seoul"`로 연도를 계산. 서버가 UTC로 돌아도 한국 달력으로 센다
- **대안**:
  - 고정값 `2026` — 2027년 1월에 아무 오류 없이 틀린 제목이 된다
  - 서버 로컬 시간 — UTC 서버에서는 1월 1일 0~9시(KST)에 작년으로 나온다
- **트레이드오프**: 홈 제목이 상수가 아니게 돼 `seo.ts`의 `title === SITE_TITLE` 비교를 접두어 비교로 바꿔야 했다. `2026-12-31T15:30:00Z` → `2027` 테스트 포함

### 주소는 그대로 두고 학교 페이지가 해를 잇는다

- **문제**: `/festivals/:id`는 해마다 새 ID라 검색 신뢰가 다음 해로 이어지지 않는다
- **선택**: 주소 체계는 건드리지 않고, 해마다 주소가 같은 학교 페이지(`/hosts/:id`)의 제목에 다가오는 축제 연도를 담아 그 역할을 맡긴다
- **대안**: 주소 체계 개편은 검토하지 않았다 — 이번 범위는 제목·구조화 데이터다
- **트레이드오프**: 축제 상세 자체는 해마다 새로 색인을 쌓는다
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

### 🔧 주요 변경사항 상세

#### festivalHeadingParts — 중복을 붙이지 않는 규칙
`{ before, name, after }`를 돌려준다. 축제명에 학교명이 들어 있으면 `before`가 `null`, 연도가 들어 있으면 `after`가 `null`. 제목(`festivalSeoTitle`)·H1(`FestivalHero`)·구조화 데이터의 `name`이 전부 이 결과를 쓴다.

**특이사항**:
- `2026 한양대학교 가을 대동제`에 다시 붙이면 `한양대학교 2026 한양대학교 …`가 되므로 포함 여부를 먼저 본다
- 해를 걸치는 축제는 `2025 ~ 2026`으로 두 연도를 모두 적는다. 축제명에 앞 연도만 들어 있어도 이미 연도를 말한 것으로 본다

#### festivalEventJsonLd — 없는 값은 뺀다
`Festival`(Event 하위 타입)에 이름·시작/종료일·URL·오프라인 참석 모드·주최(`CollegeOrUniversity`)를 담는다. 포스터·장소·좌표·무료 여부·출연자는 값이 있을 때만 넣고, 빈 값으로 채우지 않는다. 주최 URL은 학교 홈페이지가 있으면 그 주소, 없으면 `/hosts/:id`.

#### 새 E2E의 교차 확인
상세 테스트는 값을 하드코딩하지 않고 구조화 데이터와 나머지를 서로 맞춰 본다 — 제목이 `organizer.name`과 `startDate`의 연도를 포함하는지, H1 텍스트가 `event.name`과 같은지. 목록 테스트는 `#site-notice-title`이 실제로 1개 그려진 상태에서 그 요소가 제목 태그가 아닌지 확인한다(요소가 없어서 통과하는 것을 막음).
