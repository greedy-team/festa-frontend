### 📌 작업 개요
학교별 축제 이력(`/hosts/{id}/history`) 화면을 새로 만들었다. 연도 필터·정렬·페이지네이션을 지원한다.

### 🎯 구현 목표
- 특정 학교의 축제 이력을 연도별로 필터링해서 보여주는 화면
- 축제 목록 API(`GET /festivals`)에 `hostId`/`year` 파라미터를 얹어 재사용

### ✅ 구현 내용

#### 축제 이력 화면 신규
- **파일**: `src/app/hosts/[id]/history/page.tsx`, `src/features/hosts/api.ts`, `src/features/hosts/types.ts`, `src/features/hosts/components/FestivalHistoryCard.tsx`
- **변경 내용**: `GET /hosts/{id}`로 학교 정보(이름·연도 목록) 조회 후, `GET /festivals?hostId&year`로 이력 조회. 연도 칩·정렬·페이지네이션
- **이유**: 20 시안에 정의된 학교별 축제 이력 화면

#### `getFestivals`에 `hostId`/`year` 파라미터 추가
- **파일**: `src/features/festivals/api.ts`
- **변경 내용**: 기존 목록 API에 필터 파라미터 확장
- **이유**: 전용 엔드포인트 대신 목록 API에 필터를 얹는 쪽이 API 응답 스키마(`PaginatedFestivals`)를 그대로 재사용할 수 있다

### 🧭 결정 기록 (ADR)

#### 동적 라우트 세그먼트를 `[hostId]`에서 `[id]`로 통일
- **문제**: 이 화면(`/hosts/[hostId]/history`)과 주최 상세 화면(이슈 #46, `/hosts/[id]`)이 같은 base에서 병렬로 만들어지면서 서로 다른 세그먼트 이름을 썼다. Next.js는 같은 URL 위치의 동적 세그먼트 이름이 앱 전체에서 하나여야 하는데, 이 충돌은 `next build`로는 안 잡히고 `next start`(운영 모드)에서만 500으로 드러난다
- **선택**: 먼저 만들어진 #46 쪽(`[id]`)에 맞춤 — `src/app/hosts/[hostId]/history` → `src/app/hosts/[id]/history`
- **트레이드오프**: 라우트 폴더만 옮기고, 내부 변수명은 의미가 더 분명한 `hostId`로 유지했다
- ⭐ **볼트 승격 권장** — 병렬 브랜치가 같은 경로 아래 동적 라우트를 만들 때 재발할 수 있는 함정
