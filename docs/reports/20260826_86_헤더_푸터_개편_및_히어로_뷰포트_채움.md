### 📌 작업 개요

헤더·푸터에서 실제 기능이 없는 플레이스홀더(프로필·알림·북마크·소셜 아이콘·화면 없는 링크)와 MVP 이후 범위인 분실물 링크를 걷어내고, 헤더를 모든 페이지 상단에 고정(sticky)했다. 홈에서는 히어로가 뷰포트 높이를 통째로 채우며 헤더 아래까지 올라오고, 그 위에서 헤더가 투명(흰 글자)으로 떠 있다가 히어로를 벗어나면 흰 배경으로 전환된다. 640px 미만에서는 햄버거 드롭다운 메뉴를 쓰고, 푸터는 한 줄 가운데 정렬 구성으로 바꿨다.

리뷰 과정에서 헤더 전환 상태가 잘못 고정되는 버그 3건을 찾아 고치고, 지적받은 중복 코드 2건을 정리했다.

**보고서 파일**: `docs/reports/20260826_86_헤더_푸터_개편_및_히어로_뷰포트_채움.md`

### 🎯 구현 목표

- 로그인·SNS·해당 화면이 없는 상태에서 빈 껍데기로 남아 있던 헤더·푸터 요소 제거
- 헤더를 모든 페이지에서 상단 고정하고, 홈 히어로 위에서는 투명 ↔ 히어로 밖에서는 솔리드로 자연스럽게 전환

- 푸터를 로고·copyright·링크 한 줄 구성으로 단순화하고 텍스트를 키움

### 🐛 발견·수정한 버그

전환 상태가 한 번 잘못 잡히면 되돌릴 경로가 없어 화면에 그대로 남는 유형이 세 건 나왔다. 모두 헤더가 흰 배경 위에 흰 글자로 남거나, 어두운 히어로 위에 흰 배경으로 남는 형태다.

#### 홈을 벗어나도 헤더가 계속 투명한 채 고정
- **파일**: `src/components/layout/HeroSurface.tsx`
- **증상**: 홈에서 축제 목록 등으로 이동하면 흰 본문 위에 흰 글자 헤더가 남았다. 3초를 기다려도 복구되지 않았다 — 깜빡임이 아니라 영구 고정이었다
- **원인**: 언마운트 직전 `IntersectionObserver` 콜백이 한 번 더 늦게 걸려 `overHero`를 true로 되돌렸다. 그 뒤에는 아무도 다시 고치지 않는다 — 경로 변경 감지는 이미 지나간 뒤였다
- **수정**: cleanup에서 `disconnect()` 뒤에 `setOverHero(false)`로 확정

#### 드롭다운을 연 채 창을 넓히면 헤더가 솔리드로 고정
- **파일**: `src/components/layout/Header.tsx`
- **증상**: 좁은 화면에서 햄버거 메뉴를 연 뒤 창을 sm(640px) 이상으로 넓히면, 햄버거 버튼과 드롭다운은 `sm:hidden`으로 사라지는데 `isMenuOpen`은 true로 남았다. 홈 최상단인데도 헤더가 흰 배경으로 고정되고, 닫을 UI가 없어 다른 페이지로 이동하기 전까지 풀리지 않았다
- **원인**: `isMenuOpen`을 경로 변경 시에만 되돌리고 있었다. CSS는 미디어 쿼리로 숨기지만 상태는 그대로다
- **수정**: `matchMedia("(min-width: 40rem)")`의 `change`에서 sm 이상이면 닫는다. 하이드레이션 시점에 이미 넓은 경우도 최초 1회 확인

#### 스크롤 복원된 새로고침에서 첫 페인트가 잘못 그려짐
- **파일**: `src/components/layout/HeroSurface.tsx`
- **증상**: 홈을 스크롤한 상태로 새로고침하면(브라우저가 스크롤 위치를 복원하는 경우) 첫 페인트에 투명+흰 글자 헤더가 스크롤된 흰 본문 위에 잠깐 그려진다
- **원인**: 컨텍스트 초기값은 경로만 보고 투명으로 잡는데, 보정하는 옵저버는 `useEffect`라 첫 페인트 뒤에 돈다
- **수정**: `useLayoutEffect`(SSR에서는 `useEffect`로 폴백)로 페인트 전에 `getBoundingClientRect().bottom > HEADER_HEIGHT`를 재서 실제 위치로 맞춘다

### 🧭 결정 기록 (ADR)

#### 히어로 전환 관찰 주체를 헤더가 아니라 히어로 쪽에 둔다

- **문제**: 헤더가 히어로 위에 있는지 알아야 투명↔솔리드를 전환할 수 있다. 처음엔 Header가 `document.querySelector("[data-hero]")`로 히어로를 찾아 관찰했는데, `MockProvider`가 MSW 워커 준비 전까지 자식을 그리지 않아 Header effect 시점에 히어로가 DOM에 없었고, effect가 pathname에만 의존해 다시 찾지 않아 옵저버가 영영 붙지 않았다
- **선택**: 관찰 주체를 뒤집었다. `HeroSurface`가 자기 ref를 `IntersectionObserver`로 관찰해 컨텍스트에 `setOverHero`로 쓰고, `SiteChrome`이 상태를 보유하고, Header는 읽기만 한다
- **대안**:
  - Header가 `MutationObserver`로 히어로 등장을 기다림 — 마운트 순서 문제를 감시 코드로 덮는 것이라 복잡도만 는다
  - `scroll` 이벤트로 `scrollY > 히어로 높이` 계산 — 히어로 높이가 dvh라 리사이즈·주소창 접힘마다 재계산 필요
- **트레이드오프**: 히어로가 되려면 반드시 `HeroSurface`를 써야 한다 — 다른 페이지가 자기 마크업으로 투명 헤더를 요구할 수는 없다
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### 히어로 높이는 100dvh, 상한(max-h)을 두지 않는다

- **문제**: 이전 `h-[calc(100vh-72px)]` + `max-h-[952px]/xl:1100/2xl:1300`(#80)은 뷰포트가 상한보다 큰 화면에서 첫 화면을 다 채우지 못하고 아래 섹션이 삐져나왔다 — 해상도마다 모양이 달랐다
- **선택**: `h-dvh min-h-[420px]`만 둔다. dvh 자체가 상한이다. 다른 프로젝트(church-frontend)의 100dvh + 투명 헤더 방식을 참고했다
- **대안**:
  - 상한을 더 높은 값으로 재조정 — 어느 값을 골라도 그보다 큰 화면이 있어 같은 문제가 반복된다
- **트레이드오프**: 100dvh는 모바일 브라우저 주소창이 접히고 펴짐에 따라 히어로 높이가 변할 수 있다(참고 프로젝트와 동일한 선택). #80에서 완화한 와이드 화면 패널 비율은 이제 뷰포트 비율을 그대로 따른다
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### 헤더는 fixed가 아니라 sticky + 히어로 음수 마진

- **문제**: 히어로가 헤더 아래까지 올라오려면 헤더가 흐름 밖에 있거나(fixed), 히어로가 헤더 자리로 올라가야 한다(음수 마진)
- **선택**: 헤더는 `sticky top-0 z-30`으로 흐름에 남기고, 홈 히어로(`HeroSurface`)만 `-mt-[72px]`로 당긴다
- **대안**:
  - 헤더 `fixed` — 홈 외 모든 페이지 본문에 상단 패딩 72px을 넣어야 하고, 빠뜨린 페이지는 헤더에 가려진다
- **트레이드오프**: 헤더가 모든 페이지에서 sticky가 된다(이전엔 스크롤하면 사라졌다). `<dialog>` 기반 LineupSheet는 top layer라 z-30 헤더와 겹침 문제 없음
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### 전환 상태는 사라지는 쪽에서 확정한다

- **문제**: 옵저버로 켠 상태를 옵저버가 사라질 때 누가 끄는가. 언마운트 직전 늦은 콜백이 상태를 되돌려 놓으면 그 뒤로는 고칠 주체가 없다
- **선택**: `HeroSurface`의 cleanup에서 `setOverHero(false)`로 확정한다. 켜는 주체가 끄는 책임까지 진다
- **대안**:
  - Header가 경로를 보고 매번 재판정 — 홈 안에서의 스크롤 전환과 충돌한다(경로는 그대로인데 상태는 바뀌어야 한다)
  - `overHero`를 파생 상태로 계산 — 스크롤 위치를 상태로 들고 있어야 해서 리렌더가 잦아진다
- **트레이드오프**: 없음. 히어로가 사라졌는데 "히어로 위"인 상태는 정의상 존재할 수 없다
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### CSS가 숨기는 UI의 상태는 같은 조건으로 닫는다

- **문제**: 드롭다운은 `sm:hidden`으로 사라지는데 `isMenuOpen`은 남아, 보이지 않는 상태가 헤더 배경을 계속 지배했다
- **선택**: `matchMedia`로 같은 브레이크포인트를 구독해 CSS가 숨기는 시점에 상태도 닫는다
- **대안**:
  - `resize` 이벤트 — 드래그하는 내내 매 프레임 발화한다. `matchMedia`는 경계를 넘을 때만 한 번 발화한다
  - 드롭다운을 `sm:hidden` 대신 조건부 렌더로 — 서버에서 화면 폭을 모르므로 SSR과 어긋난다(LSN-0020)
- **트레이드오프**: 브레이크포인트 값(`40rem`)이 Tailwind 설정과 코드 두 곳에 있다. 주석으로 표시했다

#### 옵저버 공용 훅은 만들지 않는다

- **문제**: `HeroSurface`와 `FadeInSection`이 각각 `IntersectionObserver`를 쓴다 — 코드 리뷰에서 중복으로 지적받았다
- **선택**: 묶지 않는다. 세 번째 사용처가 생기면 그때 다시 본다
- **대안**:
  - 공용 `useIntersectionObserver` 훅 — 공유되는 건 API 호출 세 줄뿐이고 의미는 반대다. FadeInSection은 첫 교차에 끊는 one-shot(threshold), HeroSurface는 양방향 지속(rootMargin)이며 언마운트 확정·layout 단계 초기 측정이 더 붙는다. one-shot 여부·옵션·콜백을 전부 파라미터로 받아야 하고 HeroSurface 고유 로직은 어차피 훅 밖에 남는다
- **트레이드오프**: `new IntersectionObserver`·`observe`·`disconnect` 세 줄이 두 파일에 각각 남는다

### 🔧 주요 변경사항 상세

#### Header.tsx
`overHero`와 드롭다운 열림 상태를 합쳐 `solid = !overHero || isMenuOpen`으로 배경을 결정 — 드롭다운이 열리면 투명 상태에서도 솔리드로 바꿔 흰 패널 위에 흰 글씨가 뜨지 않게 한다. 데스크톱 nav와 모바일 드롭다운은 `NavLinks`를 공유하고 링크 클래스만 각자 넘긴다.

**특이사항**:
- 드롭다운 닫기는 `useRouteResetState`가 맡는다 — `useEffect` 안 `setState`가 아니라 렌더 중 이전 경로와 비교하는 패턴(`react-hooks/set-state-in-effect` 규칙)
- 훅이 돌려주는 setter는 `useState`의 setter라 안정적이지만 lint가 훅 너머를 보지 못해 stable로 인식하지 않는다 — 해당 deps에 명시했다(런타임 동작 동일, 구독은 여전히 마운트 시 1회)
- 검색 폼의 display 클래스는 래퍼 `<span>`에 건다 — `NavSearchForm`의 `inline-flex`와 충돌해 className으로 넘긴 `hidden`이 밀린다

#### SiteChrome.tsx
`overHero` 상태의 소유자. 초기값 `pathname === "/"`, 경로가 바뀌면 되돌려 `/festivals`→홈 클라이언트 라우팅 직후에도 즉시 투명. 컨텍스트 value를 `useMemo`로 감싼다 — 매 렌더 새 객체면 `overHero`가 그대로여도 구독자가 전부 다시 그려진다. 기존 `isAdmin` 분기는 그대로 두고 비관리자 셸만 Provider로 감싼다.

#### HeroSurface.tsx / HeroVisibilityContext.tsx
`HEADER_HEIGHT = 72`는 Header `h-[72px]`, HeroSurface `-mt-[72px]`, 옵저버 `rootMargin`이 공유하는 단일 값. 컨텍스트 기본값은 `overHero: false`, `setOverHero: noop` — Provider 밖(관리자 셸)에서 HeroSurface가 쓰여도 깨지지 않는다.

**특이사항**:
- 옵저버 콜백은 `entry.isIntersecting` 하나로 양방향 전환을 처리한다 — `rootMargin`으로 루트를 헤더 아래 영역으로 줄여 두면 히어로 하단이 헤더 하단(scrollY = 뷰포트 높이 − 72)을 지나는 순간 값이 뒤집힌다
- `useLayoutEffect`는 SSR에 없어 경고를 내므로 `typeof window === "undefined"`로 갈라 `useEffect`로 폴백한다

#### Hero.tsx / page.tsx
캐러셀 히어로는 `<HeroSurface>`만 감싸고, 빈 상태·에러 상태는 `pt-[72px]`로 헤더 겹침분만큼 내용을 내린다. `ScrollHint`는 `HeroSurface`의 `<section>`을 `closest("section")`으로 찾아 다음 섹션으로 스크롤한다.
