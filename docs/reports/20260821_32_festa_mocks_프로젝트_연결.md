### 📌 작업 개요
준비만 되어 있고 실제로는 연결되지 않았던 MSW 기반 모킹 계층(`festa-mocks/`)을 `src/` 구조로 옮기고 프로젝트에 실제로 연결했다.

### 🎯 구현 목표
- 실제 백엔드 없이 프론트를 개발·테스트할 수 있도록 SSR/CSR 양쪽 fetch를 가로채는 모킹 계층 활성화
- pnpm 전용 프로젝트에 잘못 섞여 있던 npm 흔적(`package-lock.json`) 제거

### ✅ 구현 내용

#### 모킹 계층 이동 및 연결
- **파일**: `src/instrumentation.ts`, `src/mocks/`(fixtures, handlers, `browser.ts`/`server.ts`, `MockProvider.tsx`, README 문서), `src/app/layout.tsx`
- **변경 내용**: `festa-mocks/` 폴더 전체를 `src/` 하위로 이동하고 상대 import 경로(`./src/mocks/server` → `./mocks/server`)를 수정. `layout.tsx`가 `NEXT_PUBLIC_API_MOCKING=enabled`일 때만 `MockProvider`로 감싸도록 연결
- **이유**: SSR용 `instrumentation.ts`와 CSR용 `MockProvider`가 준비돼 있었지만 실제 앱 진입점에 연결되지 않아 동작하지 않는 상태였다

#### 의존성 정리
- **파일**: `package.json`, `pnpm-lock.yaml`, `public/mockServiceWorker.js`, `package-lock.json`(삭제)
- **변경 내용**: `msw`를 pnpm으로 재설치하고 서비스 워커 스크립트 생성. npm으로 잘못 설치되며 남아있던 `package-lock.json` 제거
- **이유**: pnpm 전용 프로젝트에 `package-lock.json`이 남아 있으면 CI가 깨질 수 있다

### 🧭 결정 기록 (ADR)

#### 모킹 플래그를 Vercel이 아니라 로컬 `.env.local` 전용으로 문서화
- **문제**: `NEXT_PUBLIC_API_MOCKING`을 Vercel 환경변수로 등록하면 Preview/Production 배포까지 모킹이 걸릴 위험이 있다
- **선택**: 로컬 전용으로 한정 — Preview/Production은 모킹 없이 실제 API로 그대로 동작
