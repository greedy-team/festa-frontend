### 📌 작업 개요
주최(학교) 상세(`/hosts/{id}`) 화면을 새로 만들었다. 히어로 → 다가오는 축제 캐러셀 → 축제 이력 → 자주 온 아티스트 순서로 구성된다.

### 🎯 구현 목표
- 10 School Detail 시안 재현
- 이미 있던 축제 이력 화면(이슈 #51)과 연결되는 학교 상세 진입점 완성

### ✅ 구현 내용

#### 주최 상세 화면 신규
- **파일**: `src/app/hosts/[id]/page.tsx`, `HostHero.tsx`, `UpcomingFestivalsSection.tsx`, `UpcomingFestivalCard.tsx`, `FestivalHistorySection.tsx`, `FrequentArtistsSection.tsx`, `src/features/hosts/types.ts`
- **변경 내용**: `GET /hosts/{id}` 연동. 다가오는 축제는 한 장씩 넘기는 카드 캐러셀(응답 0건이 흔한 케이스라 섹션 자체는 숨기지 않음), 축제 이력은 미리보기 2건 + "전체 보기" 링크, 자주 온 아티스트는 배열이 비면 섹션 자체를 그리지 않음
- **이유**: 이슈에 정의된 주최 상세 화면 구성

#### 공용 컴포넌트 승격
- **파일**: `src/features/home/components/HeroArrow.tsx`/`HeroDots.tsx` → `src/components/ui/`
- **변경 내용**: 홈 히어로 캐러셀 전용이던 화살표·점 컴포넌트를 공용 위치로 옮겨 주최 상세의 캐러셀에서도 재사용
- **이유**: 캐러셀을 새로 만들면서 40px 화살표를 따로 만들었다가, 홈의 48px 화살표(터치 타깃 44px 기준 충족)와 동작(끝에서 멈춤 vs 순환)이 달라지는 문제가 있어 원본을 공용화하는 쪽으로 정리

### 🧭 결정 기록 (ADR)

#### 축제 이력 카드를 `FestivalHistoryCard` 재사용으로 정리
- **문제**: 주최 상세 안에 같은 236px 포스터 카드를 다시 인라인 구현하고 있었다(이슈 #51에 이미 있는 컴포넌트와 클래스 문자열이 사실상 동일)
- **선택**: `FestivalHistoryCard`의 Props를 카드가 실제 쓰는 필드(`festivalId, name, startDate, endDate, posterUrl`)만 받도록 좁혀서, 목록용 `Festival` 타입과 이 화면의 `HostFestivalHistoryItem` 타입 양쪽에서 재사용 가능하게 함

#### 캐러셀 `index`를 항상 클램프
- **문제**: `/hosts/5` → `/hosts/7`처럼 같은 라우트 패턴 사이를 이동하면 컴포넌트가 재마운트되지 않아, 이전 학교의 `index`가 새 학교의 `festivals.length`보다 클 때 배열 접근이 `undefined`가 되어 크래시할 수 있었다
- **선택**: `Math.min(index, festivals.length - 1)`로 렌더링 직전에 항상 클램프(홈 히어로 캐러셀의 `current` 패턴과 동일)

### 🔧 주요 변경사항 상세

#### 잘못된 주석 수정
"축제 이력 화면(`/hosts/{id}/history`)이 아직 없다"는 주석을 근거로 "전체 보기"를 링크가 아닌 텍스트로 남겨뒀는데, 실제로는 이슈 #51이 이 브랜치의 base 커밋부터 이미 있었다. `git ls-tree`로 확인 후 실제 링크(`hostId` prop 추가)로 승격했다. `SchoolResultRow`(검색 결과)도 `/hosts/{id}/history` 대신 `/hosts/{id}`로 다시 연결했다.

**특이사항**:
- "다가오는 축제"에서 진행 중인 축제가 `D+1`(하루 지난 것처럼)로 표시되는 버그가 있었다 — 응답에 포함되는 축제는 전부 `endDate >= today`라 `dday <= 0`이면 지난 게 아니라 진행 중이므로 "진행중" 문구로 분기
- 스크림이 2단(`scrim-35 → scrim-25`)으로 구현돼 있던 것을 DESIGN.md 스펙대로 3단(`scrim-35 → scrim-30 → scrim-25`)으로 보정
