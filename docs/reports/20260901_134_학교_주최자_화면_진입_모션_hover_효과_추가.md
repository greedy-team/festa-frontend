### 📌 작업 개요

축제·아티스트 화면에는 있던 진입 페이드업과 카드 hover 효과가 학교(주최자) 상세·축제
이력 화면에만 빠져 있었다(ISS-0081 범위 밖). 화면 사이를 오갈 때 학교 화면만 정적으로
뚝 뜨던 것을 나머지 화면과 맞춘다. 새 컴포넌트 없이 기존 공용 컴포넌트(`PageFadeIn`,
`FadeInSection`)와 hover 클래스를 재사용한다.

### 🎯 구현 목표

- 학교 상세·축제 이력 화면에 진입 페이드업 적용 (다른 상세 화면과 동일한 `PageFadeIn`)
- 학교 상세는 히어로 아래 섹션마다 스크롤 진입 페이드업 (`FadeInSection`, 축제 상세와 동일)
- 학교 화면의 포스터 카드에 hover 확대·그림자 효과 추가 (기존 카드와 동일 규격)
- `prefers-reduced-motion` 대응은 공용 컴포넌트·`motion-reduce:` 클래스 재사용으로 유지

### ✅ 구현 내용

#### 학교 상세 화면 진입·섹션 모션

- **파일**: `src/app/hosts/[id]/page.tsx`
- **변경 내용**: 화면 전체를 `PageFadeIn`으로 감싸고, 히어로 아래 섹션(다가오는 축제 /
  축제 이력 / 자주 온 아티스트 / 광고)을 각각 `FadeInSection`으로 감쌈
- **이유**: 카드·검색 결과 클릭으로 진입하는 화면이라 다른 상세 화면과 전환 인상을 맞춘다.
  섹션별 `FadeInSection`은 축제 상세와 동일한 패턴

#### 자주 온 아티스트 섹션 조건부 래핑

- **파일**: `src/app/hosts/[id]/page.tsx`
- **변경 내용**: `FrequentArtistsSection`을 `host.frequentArtists.length` 삼항으로 감싸,
  빈 결과일 때 `FadeInSection` 래퍼째 렌더하지 않음
- **이유**: `FrequentArtistsSection`은 빈 결과일 때 `null`을 반환한다. 무조건 감싸면
  빈 `FadeInSection`의 wrapper div가 `flex flex-col gap-16`의 간격을 그대로 남긴다
  (LSN-0054). 나머지 3개 섹션은 빈 상태 문구를 그리므로 무조건 감싸도 안전

#### 축제 이력 화면 진입 모션

- **파일**: `src/app/hosts/[id]/history/page.tsx`
- **변경 내용**: 성공 반환 경로를 `PageFadeIn`으로 감쌈. 에러 반환 경로는 제외
- **이유**: 학교 상세에서 넘어오는 화면이라 진입 인상을 맞춘다. 에러 화면까지
  페이드업할 이유는 없다. diff가 큰 것은 래퍼 추가에 따른 들여쓰기 이동이 대부분이다
  (`git diff -w`로 보면 import 1줄 + 래퍼만 실질 변경)

#### 축제 이력 카드 hover

- **파일**: `src/features/hosts/components/FestivalHistoryCard.tsx`
- **변경 내용**: `FestivalCard`와 동일한 포스터 카드 hover 추가 —
  `group-hover:scale-105 group-hover:shadow-hover` + `motion-reduce:` 대응
- **이유**: 기존 카드 3종(`FestivalCard`·`RecentCard`·`UpcomingShowCard`)과 문자 단위로
  동일해 `motion-reduce:` 대응이 그대로 승계된다

#### 다가오는 축제 카드 hover

- **파일**: `src/features/hosts/components/UpcomingFestivalCard.tsx`
- **변경 내용**: 포스터 전면형 카드 hover 추가. `Link` 자체가 포스터 컨테이너라
  스케일을 `Link`에 직접 건다. 확대율은 5%가 아닌 3%(`hover:scale-[1.03]`)
- **이유**: 356px로 큰 카드라 5% 확대는 캐러셀 폭을 넘긴다

#### 자주 온 아티스트 카드 — hover + 링크 목적지

- **파일**: `src/features/hosts/components/FrequentArtistsSection.tsx`
- **변경 내용**: 카드에 `hover:shadow-hover` + `motion-reduce:transition-none` 추가.
  링크 목적지를 `href="/"`에서 `href={`/artists/${artist.artistId}`}`로 교체하고
  19행의 임시 연결 주석 삭제
- **이유**: hover로 「클릭 가능」 어포던스를 켜는 김에 목적지도 맞춘다. 어포던스만 켜고
  목적지를 홈에 두면 학교 상세에서 아티스트 카드를 누른 사용자가 전부 홈으로 튕긴다
  (LSN-0043 — 임시 연결 주석은 대상이 생겨도 갱신되지 않는다). 아티스트 상세 화면
  (`src/app/artists/[id]/page.tsx`)이 이미 있고 `artist.artistId`는 `number`다.
  이 부분은 코드리뷰 반영으로 추가됐다

### 🧭 결정 기록 (ADR)

#### 다가오는 축제 카드 확대율을 3%로 낮춤

- **문제**: 다른 포스터 카드는 hover 시 5% 확대(`scale-105`)인데, 이 카드는 356px로
  커서 5% 확대하면 가로 캐러셀 폭을 넘긴다
- **선택**: 이 카드만 3%(`hover:scale-[1.03]`)로 낮춤
- **대안**: 5% 유지 후 캐러셀에 `overflow` 여백 보정 — 이 캐러셀은 index 방식이라
  `overflow-x-auto` 스크롤 행이 아니고, 여백 보정(LSN-0038의 `p-6 -m-6`)이 애초에
  필요 없는 구조다. 확대율만 낮추는 쪽이 변경이 작다
- **트레이드오프**: hover 확대 정도가 카드마다 미세하게 다르다. 크기가 다르므로 의도된 차이

#### 자주 온 아티스트 링크를 이 PR에서 아티스트 상세로 연결

- **문제**: 원래 이 PR은 hover 어포던스만 추가하고 `href="/"`는 범위 밖으로 두려 했다
- **선택**: 코드리뷰에서 어포던스만 켜고 목적지 방치는 순손해라는 지적을 받아, 목적지
  교체·`motion-reduce` 누락 보완·임시 주석 삭제를 이 PR에서 함께 처리
- **대안**: 별도 이슈로 분리 — 어포던스가 켜진 채로 오클릭이 생기는 기간이 생긴다
- **트레이드오프**: PR 범위가 한 줄 늘었다. 대신 「어포던스는 있는데 홈으로 가는」 상태를
  안 만든다

### 🔧 주요 변경사항 상세

#### PageFadeIn / FadeInSection 재사용

두 컴포넌트 모두 이미 축제·아티스트 화면에서 쓰이던 공용 컴포넌트다. `FadeInSection`은
`"idle"`(보이는 쪽)로 시작해 SSR·JS 미실행·IntersectionObserver 미발화 어느 경우에도
콘텐츠가 사라지지 않는다.

**특이사항**:
- `HostHero`에는 hover를 넣지 않았다 — 다른 화면 히어로와 일관되게 hover 없음
- `PageFadeIn`은 `useState(false)`로 시작해 SSR HTML이 `opacity-0`로 나간다.
  `/hosts/[id]/history`는 연도 칩·페이지네이션이 전부 `<Link>`, 정렬도 네이티브 GET
  폼이라 원래 무JS로 완결되는 화면인데 클라이언트 번들이 실패하면 빈 화면이 된다.
  이미 머지된 4개 화면과 같은 패턴이라 이 작업의 범위로 두지 않았다 — 별도 이슈 후보다
