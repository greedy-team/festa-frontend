### 📌 작업 개요

다가오는 축제가 0건일 때(방학 시즌 등) 뜨는 홈 히어로에 배경 이미지를 얹을 수 있는 자리를 만들었다. 이미지 파일 자체는 추가하지 않고 형식만 구성한다 — 이미지가 지정되지 않으면 지금과 동일하게 파란 단색 화면이 뜨고, 지정되면 사진 배경 + 스크림으로 전환된다.

**보고서 파일**: `docs/reports/20260902_150_다가오는_축제_0건_히어로_배경_이미지_자리.md`

### 🎯 구현 목표

- 빈 상태 히어로가 선택적으로 배경 이미지를 받을 수 있게 한다
- 이미지 미지정 시 기존 동작(`bg-hero-1` 단색 + 글로우)을 그대로 유지한다
- 이미지 지정 시 흰 타이포 가독성을 위한 스크림을 얹는다
- 이미지 파일은 이번 작업 범위 밖 — 나중에 넣을 때 컴포넌트를 다시 손대지 않아도 되게 한다

### ✅ 구현 내용

#### 빈 상태 히어로 배경 이미지 상수 추가

- **파일**: `src/features/home/components/Hero.tsx`
- **변경 내용**: 모듈 상수 `EMPTY_HERO_BACKGROUND_SRC: string | null = null` 추가. 사진을 쓸 때는 파일을 `public/hero/offseason.jpg`로 저장하고 이 값을 `"/hero/offseason.jpg"`로 바꾸면 된다는 안내를 주석에 명시
- **이유**: 정적 이미지 방식이라 백엔드 응답과 무관하다. 상수 한 줄만 바꾸면 활성화되고, 지금은 `null`이라 화면 변화가 없다

#### 빈 상태 분기에 이미지·스크림 레이어 추가

- **파일**: `src/features/home/components/Hero.tsx`
- **변경 내용**: `festivals.length === 0` 분기에서 `EMPTY_HERO_BACKGROUND_SRC` 값에 따라 삼항으로 갈린다.
  - 값이 있으면 `PosterImage`(`object-cover`)로 사진을 깔고 그 위에 `bg-scrim-hero`(순검정 55%) 전면 스크림
  - 값이 없으면 기존 글로우 `div`를 그대로 렌더 (마크업 동일, 삼항 else로만 이동)
- **이유**: 이미지 유무를 코드 설정으로 갈라 두면 화면 코드 변경 없이 전환할 수 있다. `PosterImage`는 기존 컴포넌트 재사용 — 로드 실패 시 스스로 사라져 `bg-hero-1`로 폴백된다

#### 오버레이 pointer-events 방어 (리뷰 반영)

- **파일**: `src/features/home/components/Hero.tsx`
- **변경 내용**: `PosterImage`와 스크림 `div`에 `pointer-events-none` 추가. 로드 실패 시 동작을 설명하는 주석도 실동작대로 정정
- **이유**: 전면 오버레이가 하위 요소의 클릭을 가로채지 않도록. 지금은 콘텐츠가 전부 `z-10`이라 버그는 아니지만, 글로우 `div`가 #68 이력으로 같은 속성을 달고 있어 일관성·방어 차원

### 🧭 결정 기록 (ADR)

#### 빈 상태 배경을 정적 이미지 방식으로

- **문제**: 빈 상태 히어로에 사진을 넣을 방법이 없어, 나중에 넣으려면 매번 컴포넌트를 고쳐야 한다
- **선택**: 모듈 상수(`EMPTY_HERO_BACKGROUND_SRC`)에 `public/` 이미지 경로를 넣는 정적 방식
- **대안**:
  - `recent` 축제 포스터 재활용 — 프론트 데이터만으로 가능하지만, 빈 상태 히어로가 "특정 축제가 아니라 서비스 자체"를 나타낸다는 기존 설계 의도와 어긋난다
  - `<Hero>`에 prop으로 주입 — `page.tsx`까지 배선이 필요한데, 요청·상황과 무관한 정적 자산이라 상수가 최소 형태다
- **트레이드오프**: 이미지가 바뀌면 코드(상수 값)를 고쳐야 한다. 브랜드 이미지 한 장이라 빈도가 낮아 감수한다
- 되돌리기 쉬운 프론트 내부 결정이라 볼트 승격 대상은 아님

### 🔧 주요 변경사항 상세

#### src/features/home/components/Hero.tsx

빈 상태 분기의 첫 자식이 `{EMPTY_HERO_BACKGROUND_SRC ? (...) : (...)}` 삼항이 됐다. 이미지 경로가 있으면 `PosterImage` + 전면 스크림, 없으면 기존 글로우. 하위 콘텐츠(`relative z-10`)·`ScrollHint`·`QUICK_LINKS` 그리드는 그대로다.

**특이사항**:
- 이미지 경로가 지정됐는데 404가 나면 `PosterImage`만 사라지고 스크림은 남는다 — 화면은 `bg-hero-1 + 순검정 55%`(글로우 없음)가 된다. 흰 타이포 가독성에는 오히려 유리해 동작은 그대로 뒀고, 주석에 사실대로 적었다
- 스크림은 DESIGN.md의 히어로 규칙(순검정 55% 단일 단계)을 따르며, 히어로 내 인디고 금지도 유지된다
- `PosterImage` import 추가. `EMPTY_HERO_BACKGROUND_SRC`가 `null`이라 현재 번들에는 이미지 관련 렌더 경로가 실행되지 않는다
