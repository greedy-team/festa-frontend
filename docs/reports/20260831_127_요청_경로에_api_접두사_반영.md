### 📌 작업 개요

2026-08-23 백엔드 결정(DEC-0099)으로 모든 API 경로(공개·관리자)가 `/api` 아래로 옮겨갔는데, 프론트 코드는 이를 반영하지 않은 채 접두사 없는 경로로 요청을 보내고 있었다(#127). 실제 배포된 첫 5개 공개 엔드포인트가 `/api` 접두사로 열린 걸 확인하고 전체 코드베이스를 맞췄다.

### 🎯 구현 목표

- 실제 요청을 만드는 `lib/api.ts`의 `API_BASE`에 `/api` 접두사 반영
- 이 상수와 나란히 존재하는 MSW 목 핸들러 5개도 같은 접두사로 맞춰 로컬 모킹이 실제 API와 계속 일치하게 유지
- 관련 주석(과거 DEC-0084 근거로 "접두사 없음"이라 적어둔 것들)도 함께 정정

### ✅ 구현 내용

- **`src/lib/api.ts`**: `API_BASE`를 `${NEXT_PUBLIC_API_BASE_URL ?? "https://api.festa.kr"}/api`로 변경. 이 한 곳을 고치면 `fetchJson`을 쓰는 공개 화면과, 같은 상수를 그대로 가져다 쓰는 `features/admin/auth/api.ts`에도 함께 반영되도록 주석에 명시
- **목 핸들러 5개** (`src/mocks/handlers/hosts.ts`·`festivals.ts`·`search.ts`·`artists.ts`·`adminAuth.ts`): 각 파일의 `const API` 상수에 동일하게 `/api` 접두사 추가. 목 핸들러가 가로채는 경로가 실제 요청 경로와 어긋나면 로컬에서 모킹이 조용히 실패(요청이 그냥 통과)하기 때문에 `lib/api.ts`와 반드시 짝을 맞춰야 함
- **`adminAuth.ts`**: `// DEC-0084: 경로에 /api 접두사를 붙이지 않는다` 라는 이제는 틀린 주석을 `// DEC-0099가 DEC-0084(접두사 없음)를 대체했다`로 정정, 하드코딩된 에러 응답의 `instance` 필드(`/admin/auth/login` → `/api/admin/auth/login`)도 함께 수정
- **`src/features/admin/auth/api.ts`**: 같은 취지로 stale 주석 정정
- **`src/features/admin/festival/api.ts`**: 아직 실제로 연결되지 않은 향후 관리자 엔드포인트를 문서화한 주석 4곳에도 `/api` 접두사 반영

### 🧪 테스트 및 검증

- `pnpm test` — MSW 핸들러 경로 변경 후에도 기존 테스트 전부 통과 확인(핸들러와 호출부가 같은 상수를 공유해 한쪽만 바뀌는 사고가 나지 않음)
- `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm build` 통과
- `env -u NEXT_PUBLIC_API_BASE_URL pnpm build`로 환경변수 미설정 시에도 빌드가 깨지지 않는지 별도 확인 — CI의 "빌드 검증" 단계가 의도적으로 환경변수 없이 `pnpm build`를 돌리기 때문에, 폴백 값(`https://api.festa.kr`)이 있어야 그 단계가 계속 통과한다는 걸 미리 확인
- 이 검증 과정에서 "폴백 값을 없애고 환경변수 누락 시 throw하도록 바꾸자"는 대안도 검토했으나, 그러면 CI의 빌드 검증이 항상 실패하게 되고 그 워크플로우 파일은 `npx projectops` 재실행 시 덮어써져 신뢰성 있게 고칠 수도 없어 폴백을 그대로 유지하기로 함
