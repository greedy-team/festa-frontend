### 📌 작업 개요

프로젝트에 유닛테스트 러너가 전혀 없어서, 데모데이 요구사항인 "목표했던 타겟 환경에서의 서비스 핵심 기능 동작 확인(Unit Test)"을 충족하지 못하고 있었다. Vitest로 최소 구성의 테스트 환경을 만들고, 화면 곳곳에서 쓰이는 핵심 순수 함수부터 우선 테스트를 붙였다.

### 🎯 구현 목표

- 유닛테스트 환경 구축(경량 구성)
- 핵심 로직(날짜 계산, 라벨 매핑, 해시 함수, 페이지 파싱)부터 우선 커버
- CI에서 PR마다 테스트가 자동으로 돌게 함

### ✅ 구현 내용

#### Vitest 도입
- **파일**: `vitest.config.mts`, `package.json`
- **변경 내용**: `vitest`만 devDependency로 추가하고 `test` 스크립트(`vitest run`)를 등록. 별도 alias 플러그인 없이 Vite의 `resolve.tsconfigPaths: true` 네이티브 옵션으로 `tsconfig.json`의 `@/*` 경로를 그대로 재사용
- **이유**: React 컴포넌트 렌더링 테스트는 이번 범위 밖(순수 함수 우선)이라 `jsdom`·Testing Library는 넣지 않았다. 필요해지면 그때 추가한다

#### 핵심 순수 함수 테스트 34건
- **파일**: `src/lib/festivalDate.test.ts`, `src/lib/admission.test.ts`, `src/lib/posterTint.test.ts`, `src/lib/searchParams.test.ts`
- **변경 내용**:
  - `festivalDate.ts` — `formatDday`/`dDay`/`fullDate`/`dateRange`/`festivalSeason`/`festivalStatus`/`dateWithWeekday`. `dDay`·`festivalStatus`는 시스템 시간에 따라 결과가 흔들리지 않도록 `today`를 항상 명시적으로 넘겨 테스트했다
  - `admission.ts` — 라벨 매핑 3종(`externalVisitorLabel`/`verificationLabel`/`ticketTypeLabel`) + 명세 밖 값이 와도 빈 칸 대신 "안내 없음"으로 떨어지는지
  - `posterTint.ts` — 같은 id·이름이 항상 같은 색을 내는지(결정성), 팔레트 개수(4/5종) 안에서 순환하는지, 음수 id도 절댓값 기준으로 동작하는지
  - `searchParams.ts` — `parsePage`의 `undefined`/`null`/비숫자/0 이하 처리

#### CI 테스트 워크플로우 추가
- **파일**: `.github/workflows/FESTA-TEST.yaml`(신규)
- **변경 내용**: PR(`main`/`develop` 대상)마다 `pnpm test` 실행
- **이유**: 기존 빌드 검증 워크플로우(`PROJECT-REACT-CI.yaml`)는 파일명에 `PROJECT-` 접두어가 있어 `npx projectops` 업데이트 시 덮어써진다 — 테스트 단계를 거기 끼워 넣으면 다음 업데이트 때 조용히 사라진다. 같은 이유로 이미 접두어를 뺐던 `FESTA-DISCORD-MERGE-NOTIFY.yaml` 전례를 따라 별도 파일로 분리했다

### 🧭 결정 기록 (ADR)

#### 컴포넌트 테스트(Testing Library)는 이번 범위에서 뺌
- **문제**: 이슈 본문 예시엔 "Vitest + React Testing Library"가 언급돼 있었지만, 컴포넌트 렌더링 테스트를 붙이려면 `jsdom` 환경·Next.js 라우터 모킹 등 설정이 늘어난다
- **선택**: 이번엔 화면 곳곳에서 재사용되는 순수 함수(날짜·라벨·해시·페이지 파싱)만 커버하고, 컴포넌트 테스트는 범위에서 뺐다
- **대안**: 처음부터 Testing Library까지 갖추는 안 — 데모데이 전에 최소 커버리지를 빨리 확보하는 게 우선이라 보류
- **트레이드오프**: 컴포넌트·통합 레벨 회귀는 여전히 수동 확인에 의존한다. 필요해지면 후속 이슈로 진행

#### CI 테스트 단계를 기존 빌드 워크플로우에 합치지 않고 분리
- **문제**: `PROJECT-REACT-CI.yaml`에 테스트 단계를 추가하면 구조는 더 단순해지지만, `npx projectops` 재실행 시 그 파일이 통째로 덮어써져 테스트 단계가 사라질 위험이 있다
- **선택**: `FESTA-TEST.yaml`로 완전히 분리
- **트레이드오프**: 체크아웃·pnpm·Node 설정 스텝이 두 워크플로우에 중복된다. 덮어쓰기에 안전한 것의 대가로 감수했다
- ⭐ **볼트 승격 권장** — 이 레포에 워크플로우를 새로 추가할 때마다 반복될 판단이라 `knowledge/decisions/`에 남겨둘 만하다

### 📦 의존성 변경

- 추가: `vitest` (devDependency)
- 설치했다가 제거: `vite-tsconfig-paths` — Vitest 4.x가 `resolve.tsconfigPaths`를 네이티브로 지원해서 플러그인 없이 같은 결과를 냈다

- `pnpm exec tsc --noEmit`, `pnpm lint` 통과

### 📌 참고사항

- `searchParams.parsePage`의 함수 주석("1 미만·소수·비숫자를 전부 1로 접는다")과 실제 동작(`Math.floor`가 먼저 적용돼 1 이상인 소수는 내림된 정수로 살아남음 — 예: `"2.5"` → `1`이 아니라 `2`)이 다르다는 걸 테스트 작성 중 발견했다. 동작 자체는 합리적이라 코드는 그대로 두고, 테스트는 실제 동작 기준으로 작성했다. 주석을 고칠지는 별도 판단이 필요해 이번 PR에서 건드리지 않았다
- 컴포넌트·통합 테스트, 커버리지 목표 설정은 후속 작업으로 남는다
