### 📌 작업 개요

PR #103(유닛테스트 환경 구축, #100) 리뷰에서 나온 후속 테스트 후보 5건(#104~#109 중 실제로 진행한 #105~#109)을 이슈별로 브랜치·PR을 나눠 처리했다. 전부 기존 함수에 테스트 파일만 추가하는 작업이라 런타임 코드 변경은 없다.

### 🎯 구현 목표

- `safeHttpUrl`(XSS 방어), `isActiveRoute`(nav 오탐 방지), `genreLabel`·`adminErrorMessage`·`discoveryLabel`/`publishBlockerLabel`(라벨 매핑 폴백) — 리뷰에서 우선순위 높다고 지적된 함수부터 순서대로 커버
- 이슈 하나 = 브랜치 하나 원칙을 지키며 5개를 연달아 처리

### ✅ 구현 내용

#### #105 — `safeHttpUrl` 스킴 필터링
- **파일**: `src/lib/safeUrl.test.ts`(신규)
- **내용**: `http(s)` 통과, 스킴 대소문자 무관, `javascript:`/`data:`/프로토콜 상대 URL(`//evil.com`) 차단 확인
- **리뷰 반영**: 정규식 `^` 앵커가 빠져도 기존 케이스는 전부 통과한다는 지적 — "차단해야 할" 값 중 어디에도 `http://`가 안 섞여 있었기 때문. `javascript:alert('https://ok.example')`처럼 문자열 중간에 스킴이 섞인 케이스를 추가하고, 실제로 앵커를 지워봐서 이 테스트가 잡는 것까지 검증했다

#### #106 — `isActiveRoute` 오탐 경계
- **파일**: `src/lib/activeRoute.test.ts`(신규)
- **내용**: 정확히 일치, 하위 경로, 접두어만 같고 슬래시 경계가 다른 경로(`/festivals-archive` vs `/festivals`) 오탐 방지 확인
- **리뷰 반영**: 실제 Header 메뉴에서 가장 위험한 입력(`href="/"`, 홈 메뉴)이 빠져 있었다는 지적. `isActiveRoute("/", "/")`은 true, `isActiveRoute("/festivals", "/")`은 false — `${href}/`가 `//`가 되어 오탐을 막는 게 우연이 아니라 이 함수의 핵심 동작임을 테스트로 못박았다

#### #107 — `genreLabel` 라벨 매핑
- **파일**: `src/lib/artistGenre.test.ts`(신규)
- **내용**: 4개 장르 매핑, `null`·명세 밖 값의 "장르 미상" 폴백 확인
- **리뷰**: 지적 없음 — "처음부터 지적할 게 없었다"는 승인

#### #108 — `adminErrorMessage` 라벨 매핑
- **파일**: `src/lib/adminError.test.ts`(신규)
- **내용**: 에러 코드별 문구 매핑, 미정의 코드의 괄호 폴백 확인
- **리뷰 반영**: `ADMIN_ERROR_CODE` 6개 중 3개만 덮여 있었고, 빠진 것 중 `UNKNOWN`이 제일 헷갈리는 자리라는 지적 — `UNKNOWN`은 `MESSAGES`에 **정의된** 코드라 "모르는 코드" 폴백(괄호에 코드 붙임)과 이름은 비슷해 보이지만 결과가 다르다. `STORAGE_UNAVAILABLE`·`NETWORK`도 추가하고, `UNKNOWN`과 미정의 코드 폴백을 별도 케이스로 나란히 검증해 헷갈리지 않게 했다

#### #109 — `discoveryLabel`/`publishBlockerLabel`
- **파일**: `src/lib/adminEnums.test.ts`(신규)
- **내용**: 두 함수의 매핑 + 사전에 없는 값 폴백(원본 그대로 노출) 확인. `discoveryLabel`의 `PASTED` 케이스는 ERD엔 있는데 API 명세엔 없는 미해결 불일치(DOC-0007 #24)를 실행되는 코드로 고정해둔 것
- **리뷰**: 지적 없음 — `PASTED` 케이스가 좋다는 승인

### 📌 참고사항

- 5개 PR 모두 `이슈 하나 = 브랜치 하나` 컨벤션을 지켜 별도로 처리했다 — 묶어서 한 브랜치로 처리하지 않았다
